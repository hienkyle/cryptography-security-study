Using Symmetric Ciphers

A block cipher on its own encrypts exactly one b-bit block. Chapter 7 shows how to use one on real data: repeating it (triple DES), chaining blocks together (the five NIST modes), encrypting disk sectors (XTS-AES), and keeping a field’s format (FPE). Chapter 8 covers the random and pseudorandom bits that keys, IVs, nonces and stream ciphers depend on.

3DES: C = E(K3, D(K2, E(K1, P))) CBC: Cj = E(K, Pj ⊕ Cj−1) CTR: Cj = Pj ⊕ E(K, Tj) BBS: Xi = Xi−1² mod n Stream: ci = pi ⊕ ki

7.1Multiple Encryption and Triple DES

DES’s 56-bit key is too short for brute force resistance. One fix is a new cipher (AES); the other keeps existing DES hardware and software and runs DES several times with several keys.

Redrawn from Figure 7.1.

Double DES

C = E(K2, E(K1, P)) P = D(K1, D(K2, C))

The key appears to be 2 × 56 = 112 bits. Two questions decide whether that is real strength:

  • Reduction to a single stage. If for every K1, K2 there were a K3 with E(K2, E(K1, P)) = E(K3, P) (Eq. 7.1), any number of DES stages would equal one DES. This is believed not to happen: with a fixed key, DES is a permutation of the 2⁶⁴ possible blocks (each input maps to a unique output, otherwise decryption would fail). There are (2⁶⁴)! > 101020 such permutations but DES keys select at most 2⁵⁶ < 10¹⁷ of them, so composing two DES mappings almost certainly gives a mapping that no single key produces.
  • Meet-in-the-middle. The attack below breaks double encryption with far less than 2¹¹² work, for any block cipher.

Meet-in-the-middle attack

Meet-in-the-middle attack — a known-plaintext attack on double encryption. It uses the fact that the middle value can be reached from both ends: X = E(K1, P) = D(K2, C).
  1. Given a known pair (P, C), encrypt P under all 2⁵⁶ values of K1; store the results X in a table sorted by X.
  2. Decrypt C under all 2⁵⁶ values of K2. Look each result up in the table.
  3. Every match gives a candidate (K1, K2). Test candidates on a second known pair; keep the ones that also work.

Why a second pair is needed: there are 2¹¹² keys but only 2⁶⁴ possible ciphertexts, so about 2¹¹²/2⁶⁴ = 2⁴⁸ wrong key pairs also map P to C (“false alarms”). A second 64-bit pair cuts this to 2⁴⁸⁻⁶⁴ = 2⁻¹⁶, so the correct keys are found with probability 1 − 2⁻¹⁶. Total work is on the order of 2⁵⁶ — barely more than the 2⁵⁵ average for single DES.

Triple DES with two keys

C = E(K1, D(K2, E(K1, P))) P = D(K1, E(K2, D(K1, C)))

The sequence is encrypt–decrypt–encrypt (EDE). Using D in the middle adds no cryptographic strength; it only lets 3DES talk to single DES, since setting K2 = K1 collapses it to E(K1, P). 3DES is also called the Triple Data Encryption Algorithm (TDEA), standardized in NIST SP 800-67.

Brute force on two-key 3DES costs about 2¹¹² ≈ 5 × 10³³. The attacks the book describes are all impractical:

  • Chosen-plaintext attack — find plaintexts that make the first intermediate value A = 0, then meet in the middle. Effort about 2⁵⁶, but it needs 2⁵⁶ chosen plaintext–ciphertext pairs.
  • Known-plaintext attack — if A and C were known, the problem would reduce to attacking double DES. The attacker guesses a value a for A, uses n known (P, C) pairs to build candidate K1 values (Pi = D(i, a) must match a known P, Figure 7.2), then searches K2. Expected effort ≈ 2⁵⁶ · 2⁶⁴/n = 2120 − log2 n.

Triple DES with three keys

C = E(K3, D(K2, E(K1, P)))

Compatible with DES by setting K3 = K2 or K1 = K2. Although the key is 3 × 56 = 168 bits, a meet-in-the-middle attack reduces its strength to about that of a 112-bit key. NIST SP 800-57 recommends retiring two-key 3DES in favour of three-key 3DES.

Current status (outside the book)NIST withdrew SP 800-67 on January 1, 2024: TDEA is no longer approved for encryption, key wrapping or MAC generation, and remains allowed only for decrypting or verifying data already protected with it. See Sources.

7.2Electronic Codebook

A block cipher maps a b-bit block and a key to a b-bit block (b = 64 for DES/3DES, 128 for AES). Longer data is split into b-bit blocks, and how those blocks are combined is the mode.

Mode of operation — a technique that adapts a block cipher to an application, such as encrypting a sequence of blocks or a data stream. NIST SP 800-38A defines five (ECB, CBC, CFB, OFB, CTR) for use with any symmetric block cipher, including 3DES and AES.
Padding — extra bits appended so the last block is a full b bits. ECB and CBC (and CFB with s-bit segments) need it; OFB and CTR do not.
Electronic codebook (ECB) — each plaintext block is encrypted independently with the same key. For a given key, every b-bit plaintext has one fixed ciphertext, like an entry in a giant codebook.
Cj = E(K, Pj) Pj = D(K, Cj) j = 1, …, N

Weakness: identical plaintext blocks always give identical ciphertext blocks. In long, structured messages this leaks patterns, gives known plaintext–ciphertext pairs (e.g. fixed headers), and lets an attacker substitute or rearrange blocks. ECB should be used only for data no longer than one block, such as a single encryption key.

Criteria for evaluating modes

Properties for judging modes that improve on ECB (from [KNUD00], as listed in the book):

  • Overhead — extra work for encryption and decryption compared with ECB.
  • Error recovery — a bit error in the iᵗʰ ciphertext block affects only a few plaintext blocks, after which the mode resynchronizes.
  • Error propagation — a bit error in the iᵗʰ ciphertext block (a transmission error, not a computation error) affects the iᵗʰ and all later plaintext blocks.
  • Diffusion — how plaintext statistics show in the ciphertext. Low-entropy (predictable) plaintext blocks should not be reflected in the ciphertext.
  • Security — whether ciphertext blocks leak information about plaintext blocks.

7.3Cipher Block Chaining Mode

Goal: a repeated plaintext block should produce different ciphertext blocks. CBC gets this by mixing each plaintext block with the previous ciphertext block before encrypting.

Initialization vector (IV) — a b-bit block (same size as the cipher block) used in place of the “previous ciphertext block” for the first block. Sender and receiver must both know it, but a third party must not be able to predict it.
Cipher block chaining (CBC) — the input to the encryption function is the XOR of the current plaintext block and the preceding ciphertext block; the same key is used for every block.
C1 = E(K, P1 ⊕ IV) Cj = E(K, Pj ⊕ Cj−1) j = 2, …, N P1 = D(K, C1) ⊕ IV Pj = D(K, Cj) ⊕ Cj−1 j = 2, …, N

Why decryption works: D(K, Cj) = D(K, E(K, Cj−1 ⊕ Pj)) = Cj−1 ⊕ Pj, and XORing with Cj−1 leaves Pj.

Protecting the IV

The IV should be protected against unauthorized change (e.g. sent with ECB encryption). Because P1 = IV ⊕ D(K, C1), bit by bit P1[i] = IV[i] ⊕ D(K, C1)[i]: an opponent who flips IV[i] flips P1[i] at the receiver, without knowing the key.

Nonce — a time-varying value with at most a negligible chance of repeating: e.g. a fresh random value, a timestamp, a sequence number, or a combination (NIST SP 800-90 definition).

Any unpredictable IV works. SP 800-38A suggests two ways: (1) encrypt a nonce under the same key used for the message; or (2) generate a random block with a random number generator.

Uses: general-purpose block-oriented transmission of messages longer than b bits, and authentication (CBC-MAC, Chapter 12). Like ECB, CBC pads the last block.

7.4Cipher Feedback Mode

CFB, OFB and CTR turn a block cipher into a stream cipher: no padding, ciphertext the same length as the plaintext, and each character (e.g. s = 8 bits) can be sent as soon as it is typed.

Stream cipher — encrypts a data stream one bit or one byte (generally s bits) at a time, usually by XORing it with a key-dependent pseudorandom stream (Section 8.4).
Shift register — here, a b-bit register whose contents are shifted left by s bits each step, with s new bits entering on the right.
MSBs(X), LSBs(X) — the s most / least significant (leftmost / rightmost) bits of X. ‖ is concatenation.
Cipher feedback (CFB) — the plaintext is processed s bits at a time. A b-bit shift register (starting at the IV) is encrypted; the leftmost s output bits are XORed with the plaintext segment to give the ciphertext segment, which is then shifted into the register.
I1 = IV Ij = LSBb−s(Ij−1) ‖ Cj−1 Oj = E(K, Ij) Cj = Pj ⊕ MSBs(Oj) Pj = Cj ⊕ MSBs(Oj)
  • Decryption uses E, not D. C1 = P1 ⊕ MSBs[E(K, IV)] rearranges to P1 = C1 ⊕ MSBs[E(K, IV)]; the receiver regenerates the same Oj.
  • Not a typical stream cipher: the bits XORed with the plaintext depend on earlier ciphertext, hence on earlier plaintext — not only on the key and IV.
  • Parallelism: encryption cannot be parallelized (each register needs the previous ciphertext). Decryption can, once the input blocks are built in series from the IV and ciphertext.
  • Uses: general-purpose stream-oriented transmission; authentication.

7.5Output Feedback Mode

OFB looks like CFB, but the feedback is the encryption output itself, not the ciphertext — so the pseudorandom stream never depends on the message.

Output feedback (OFB) — the output of each encryption is fed back as the input to the next encryption; the outputs are XORed with full plaintext blocks.
I1 = Nonce Ij = Oj−1 Oj = E(K, Ij) Cj = Pj ⊕ Oj (j = 1 … N−1) C*N = P*N ⊕ MSBu(ON) Pj = Cj ⊕ Oj (j = 1 … N−1) P*N = C*N ⊕ MSBu(ON)

* marks a final partial block of u < b bits; only the leftmost u bits of ON are used and the rest discarded.

  • The IV must be a nonce. O1, O2, … depend only on K and the IV. Reusing them on two messages means a known plaintext block in one reveals that part of the Oi stream, and therefore the matching block of the other.
  • Advantage: bit errors do not propagate. An error in C1 affects only P1. (In CFB, C1 also enters the shift register and corrupts later segments.)
  • Disadvantage: more vulnerable to message stream modification than CFB. Flipping a ciphertext bit flips exactly that plaintext bit, so an opponent can make controlled changes to both data and checksum that an error-correcting code will not detect.
  • OFB has the structure of a typical stream cipher (key + initial value → bit stream ⊕ plaintext), but works a full block at a time. Use: stream-oriented transmission over noisy channels (e.g. satellite).

7.6Counter Mode

CTR encrypts a sequence of counter values and XORs the results with the plaintext. There is no chaining at all, which makes it fast and random-access.

Counter (CTR) — a b-bit counter T is encrypted and XORed with the plaintext block. SP 800-38A only requires a different counter value for every plaintext block; typically it starts at some value and is incremented by 1 per block (mod 2ᵇ).
Cj = Pj ⊕ E(K, Tj) (j = 1 … N−1) C*N = P*N ⊕ MSBu[E(K, TN)] Pj = Cj ⊕ E(K, Tj) (j = 1 … N−1) P*N = C*N ⊕ MSBu[E(K, TN)]

Counter uniqueness: like OFB, T1 must be a nonce, and every Ti across all messages under the same key must be unique. If a counter value repeats and one plaintext block for it is known, E(K, T) = P ⊕ C is exposed and every other block encrypted with that counter can be read. One way to ensure uniqueness: start each message’s counter one above the last counter of the previous message.

Advantages of CTR [LIPM00]

  • Hardware efficiency — blocks can be encrypted or decrypted in parallel; throughput is limited only by the parallelism available, not by one cipher execution per block.
  • Software efficiency — parallel processor features (pipelining, multiple dispatch, many registers, SIMD) can be exploited.
  • Preprocessing — E(K, Tj) does not depend on the data, so it can be computed in advance; when data arrives only XORs remain.
  • Random access — block i can be processed without the i − 1 blocks before it.
  • Provable security — at least as secure as the other modes in the chapter.
  • Simplicity — only the encryption algorithm (and its key schedule) is needed, which matters for AES, where decryption differs substantially.

Comparing the five modes

7.7XTS-AES Mode for Block-Oriented Storage Devices

XTS-AES (IEEE Std 1619-2007, approved by NIST in SP 800-38E) encrypts data stored in sector-based devices, where the adversary may get at the stored data.

Tweakable block ciphers

Tweak — an extra, non-secret input to a block cipher. The key provides security; the tweak provides variability: the same plaintext under the same key with different tweaks gives different ciphertexts. It plays a role like a salt for passwords.
Tweakable block cipher — a cipher with three inputs, plaintext P, key K and tweak T: C = E(K, T, P). A common structure uses a hash H of the tweak:
C = H(T) ⊕ E(K, H(T) ⊕ P) P = H(T) ⊕ D(K, H(T) ⊕ C)

A mode built from it is essentially ECB with a different tweak for every block, which removes ECB’s main weakness (equal blocks → equal ciphertext).

Storage encryption requirements (P1619)

  • The ciphertext is freely available to an attacker (shared database with encrypted records, unauthorized access, stolen disk or laptop).
  • Data layout does not change: ciphertext is the same size as plaintext.
  • Data is accessed in fixed-size blocks, independently, in any order; encryption is in 16-byte blocks, independently (except the last two blocks of a sector that is not a multiple of 16 bytes).
  • No metadata except the location of the data blocks.
  • The same plaintext encrypts to different ciphertexts at different locations, but always to the same ciphertext when rewritten to the same location.
  • Any conforming device can decrypt data encrypted by another.

Why not CTR or CBC? With CTR, an attacker with write access flips any plaintext bit by flipping the ciphertext bit. With CBC and a sector-number IV, a ciphertext sector copied to another position still decrypts to the same plaintext (except perhaps the first 128 bits), and flipping a ciphertext bit flips the matching plaintext bit of the next block (randomizing the current one).

Operation on a single block

Parameters — Key: 256 or 512 bits, split as Key = Key1 ‖ Key2. Pj, Cj: 128-bit plaintext / ciphertext block j of a data unit (typically a sector). j: sequential number of the block inside the data unit. i: 128-bit tweak, a nonnegative integer assigned to each data unit, consecutively. α: a primitive element of GF(2¹²⁸), the polynomial x. ⊗: multiplication in GF(2¹²⁸), i.e. of binary polynomials modulo x¹²⁸ + x⁷ + x² + x + 1. αʲ: α multiplied by itself j times.

Operation on a sector: ciphertext stealing

A sector’s plaintext is split into 128-bit blocks P0 … Pm; the last block may be empty or 1–127 bits. Full blocks are encrypted independently. If the last block Pm has s < 128 bits, the last two blocks use ciphertext stealing instead of padding, so the ciphertext stays exactly as long as the plaintext:

XX = XTS-AES-blockEnc(K, Pm−1, i, m−1) CP = LSB128−s(XX) ← the “stolen” tail of XX YY = Pm ‖ CP ← pad Pm with it Cm−1 = XTS-AES-blockEnc(K, YY, i, m) Cm = MSBs(XX)

Like CTR, XTS-AES has no chaining, so blocks can be processed in parallel; unlike CTR it uses both a nonce (i) and a counter (j).

7.8Format-Preserving Encryption

Encrypt a field so the ciphertext has the same format as the plaintext — a 16-digit card number stays 16 digits — and can be stored wherever the plaintext was.

Motivation

FPE retrofits encryption into legacy applications without changing database schemas, and with minimal changes to applications (only those that must see plaintext). Examples: COBOL record structures referenced by hundreds of modules; database fields that accept only character strings (Base64 of binary ciphertext would lengthen them); and FPE ciphertext, unlike AES binary output, compresses well for transmission.

Design requirements and difficulties

  1. Ciphertext has the same length and format as the plaintext.
  2. Adaptable to many character sets: decimal digits, lowercase letters, a full keyboard character set.
  3. Works with variable plaintext lengths.
  4. Security comparable to AES.
  5. Strong even for very short plaintexts.

Reversibility. Encrypting 4-bit-coded digits with AES and taking each 4-bit output mod 10 gives 16 decimal digits — but it cannot be decrypted, because mod 10 is many-to-one (12 mod 10 = 2 mod 10 = 2).

Short inputs. In a card number, the first six digits identify the issuer and the last is a check digit; if the last four must stay in the clear, only six digits are encrypted. An adversary collecting plaintext/ciphertext pairs could build a dictionary of six-digit values; in a database of 100 million cards about 100 share any given middle six digits, so learning k numbers exposes about 100k. The fix is a tweak (Section 7.7): e.g. add the first two and last four digits, digit by digit mod 10, to the middle six before encrypting.

8.1Principles of Pseudorandom Number Generation

Keys, IVs, nonces and stream-cipher keystreams all need bits an opponent cannot guess. This section says what “random enough” means and which kind of generator supplies it.

Uses of random numbers

  • Nonces in key distribution and mutual authentication handshakes (Chapters 14–15), so an opponent cannot replay an old transaction.
  • Session keys — symmetric keys generated for one transaction or session and valid briefly.
  • Key generation for RSA (Chapter 9).
  • Bit streams for symmetric stream encryption (this chapter).

Two requirements

Randomness — statistical randomness, validated by two criteria: uniform distribution (ones and zeros occur about equally often) and independence (no subsequence can be inferred from the others). Independence cannot be proven by a test; tests can only show its absence, so many tests are applied until confidence is high enough.
Unpredictability — successive members of the sequence cannot be predicted from earlier ones. Needed for authentication, session keys and stream ciphers, where statistical randomness alone is not enough.

TRNGs, PRNGs and PRFs

Entropy source — a source of effectively random input drawn from the physical environment, e.g. keystroke timing, disk electrical activity, mouse movements, instantaneous clock values.
Seed — the fixed input value from which a deterministic generator computes its output.
Pseudorandom numbers — numbers produced by a deterministic algorithm that are not statistically random but, if the algorithm is good, pass many tests of randomness.
Redrawn from Figure 8.1.
  • True random number generator (TRNG) — converts an entropy source to binary, possibly with extra processing to remove bias (Section 8.6).
  • Pseudorandom number generator (PRNG) — a deterministic algorithm that produces an open-ended bit sequence from a seed, often with some output fed back. Anyone who knows the algorithm and seed can reproduce the whole stream. Typical use: keystream for a stream cipher.
  • Pseudorandom function (PRF) — produces a pseudorandom string of fixed length (e.g. a symmetric key or nonce) from a seed plus context-specific values such as a user or application ID.

Apart from output length, PRNG and PRF are the same: same algorithms, both need a seed, both must be random and unpredictable.

PRNG requirements

An adversary who does not know the seed must not be able to determine the output. (If a PRF that should yield a 128-bit key does not produce effectively random output, the adversary may narrow the possibilities enough for brute force.) This splits into three requirements:

1. Randomness. No single test proves it; NIST SP 800-22 tests should establish:

  • Uniformity — at any point, a 0 or 1 is equally likely (probability 1/2); expect n/2 zeros in n bits.
  • Scalability — any test applicable to a sequence also applies to randomly extracted subsequences, which should also pass.
  • Consistency — behaviour is consistent across seeds; testing one seed (or one physical output for a TRNG) is not enough.

SP 800-22 has 15 tests; three examples:

  • Frequency test — are the numbers of ones and zeros about what a truly random sequence would have? The most basic test; always included.
  • Runs test — a run is an uninterrupted sequence of identical bits bounded by the opposite bit. Are there as many runs of each length as expected?
  • Maurer’s universal statistical test — measures bits between matching patterns (related to compressed length). A significantly compressible sequence is non-random.

2. Unpredictability.

  • Forward unpredictability — without the seed, the next output bit cannot be predicted from any previous bits.
  • Backward unpredictability — the seed cannot be determined from generated values; each output bit looks like an independent event with probability 1/2.

The randomness tests also test unpredictability: a sequence that looks random has no usable correlation with earlier bits or with the seed.

3. Seed requirements. The PRNG is deterministic, so the seed must be secure and unpredictable — itself random or pseudorandom. Typically a TRNG generates it (Figure 8.2, as SP 800-90A recommends):

entropy source → TRNG → seed → PRNG → pseudorandom bit stream

Why not use the TRNG directly? (1) A stream cipher with a TRNG keystream would need a key as long as the message (a one-time pad); a PRNG only needs a short key delivered securely. (2) A TRNG’s output may be biased; passing it through a PRF conditions it. (3) A TRNG may be too slow for the application.

Algorithm design

  • Purpose-built algorithms — designed only for generating pseudorandom bits: general PRNGs (Section 8.2) and stream-cipher generators such as RC4 (Section 8.5).
  • Algorithms based on existing cryptographic algorithms — ciphers must randomize their input, so they can be the core of a PRNG: symmetric block ciphers (Section 8.3), asymmetric ciphers (Chapter 10), hash functions and MACs (Chapter 12). Reusing code an application already has is convenient.

8.2Pseudorandom Number Generators

Linear congruential generators

Linear congruential generator (LCG) — iterates Xn+1 = (aXn + c) mod m with modulus m > 0, multiplier 0 < a < m, increment 0 ≤ c < m and seed 0 ≤ X0 < m. Every output lies in 0 ≤ Xn < m.
Period — the number of outputs before the sequence repeats. A full-period generator produces every value 0 … m − 1 before repeating.

The choice of a, c, m is critical. With a = 7, c = 0, m = 32, X0 = 1 the sequence is 7, 17, 23, 1, 7, … (period 4); a = 5 gives period 8. m should be near the largest representable integer, e.g. near 2³¹. Three tests for a good LCG [PARK88]:

  • T1 full period; T2 the sequence appears random; T3 efficient with 32-bit arithmetic.

With m prime and c = 0, some a give period m − 1 (only 0 missing). A widely used, heavily tested choice: Xn+1 = (16807 · Xn) mod (2³¹ − 1), with a = 7⁵.

Lab · LCG period

Cryptographic weakness: nothing is random except X0. If the opponent knows the parameters (e.g. a = 7⁵, c = 0, m = 2³¹ − 1), one output reveals all later ones. Even without them, four outputs X0 … X3 give three equations X1 = (aX0 + c) mod m, … that can be solved for a, c and m. Countermeasure: make the sequence non-reproducible, e.g. restart every N numbers with the current clock value (mod m) as the new seed, or add the clock value to each output (mod m).

Blum Blum Shub generator

Perhaps the strongest public proof of cryptographic strength of any purpose-built PRNG.

choose primes p ≡ q ≡ 3 (mod 4); n = p × q choose seed s relatively prime to n (neither p nor q divides s) X0 = s² mod n for i = 1, 2, …: Xi = (Xi−1)² mod n, Bi = Xi mod 2 (least significant bit)
Next-bit test — a pseudorandom bit generator passes it if no polynomial-time algorithm, given the first k bits, can predict bit k + 1 with probability significantly greater than 1/2. (A polynomial-time algorithm of order k runs in time bounded by a polynomial of order k.)
Cryptographically secure pseudorandom bit generator (CSPRBG) — one that passes the next-bit test. BBS is a CSPRBG; its security rests on the difficulty of factoring n into p and q.

8.3Pseudorandom Number Generation Using a Block Cipher

A good block cipher’s output shows no patterns that reveal its input, so it makes a good PRNG core — with known security properties if the cipher is standardized (DES, AES), and code many applications already contain.

PRNG using block cipher modes of operation

ANSI X9.17 PRNG

One of the strongest PRNGs cryptographically; used in financial security applications and PGP. It uses two-key triple DES (EDE) three times, all with the same secret pair K1, K2 reserved for PRNG use.

  • Outputs: a 64-bit pseudorandom number Ri and the next seed Vi+1.

Strength: a 112-bit key and nine DES encryptions; two independent inputs (date/time and a seed distinct from the output). Even if Ri is compromised, Vi+1 cannot be deduced from it, because one more EDE separates them.

8.4Stream Ciphers

Keystream — the output of the pseudorandom generator in a stream cipher; it is XORed with the plaintext (typically a byte at a time).
Redrawn from Figure 8.7.
11001100 plaintext ⊕ 01101100 keystream 10100000 ciphertext
10100000 ciphertext ⊕ 01101100 keystream 11001100 plaintext

A stream cipher resembles the one-time pad (Unit 3), but the pad is pseudorandom instead of truly random, so only the short key has to be shared.

Design considerations [KUMA97]

  1. Large period. The generator eventually repeats; the longer the period, the harder the cryptanalysis (as with a longer Vigenère keyword).
  2. Keystream close to a true random stream — e.g. about equal ones and zeros, and all 256 byte values about equally often.
  3. Long key. The keystream is conditioned on the key, so brute force must be infeasible: at least 128 bits.

With a properly designed PRNG, a stream cipher can be as secure as a block cipher of comparable key length.

Stream cipher or block cipher?

  • Stream advantage: ciphers not built from block ciphers are typically faster and use far less code (RC4 is a few lines). This has shrunk with AES, which is efficient in software and has hardware support (Intel’s AES instructions give about an order-of-magnitude speedup over pure software).
  • Block advantage: keys can be reused. Two plaintexts encrypted with the same stream-cipher keystream give C1 ⊕ C2 = P1 ⊕ P2, which is often easy to break when the plaintexts have known structure.
  • Applications: stream ciphers suit streams such as a data communications channel or a browser/Web link; block ciphers suit blocks of data such as file transfer, email and databases. Either can be used in virtually any application.

8.5RC4

RC4 — a variable-key-size, byte-oriented stream cipher based on a random permutation. A key of 1 to 256 bytes initializes a 256-byte state vector S that always holds a permutation of 0 … 255. Each output byte k is selected from S, and S is permuted again. Its period is overwhelmingly likely to exceed 10¹⁰⁰; it needs 8–16 machine operations per output byte.

1 · Initialization of S

for i = 0 to 255 do S[i] = i; T[i] = K[i mod keylen];

T is a temporary vector: the key, repeated to fill 256 bytes.

2 · Initial permutation of S

j = 0; for i = 0 to 255 do j = (j + S[i] + T[i]) mod 256; Swap(S[i], S[j]);

Only swaps, so S remains a permutation of 0 … 255.

3 · Stream generation

i, j = 0; while (true) i = (i + 1) mod 256; j = (j + S[i]) mod 256; Swap(S[i], S[j]); t = (S[i] + S[j]) mod 256; k = S[t]; // encrypt: XOR k with next plaintext byte; decrypt: with next ciphertext byte

After initialization the key is no longer used.

Strength of RC4

  • Early published attacks were not practical against reasonable key lengths such as 128 bits.
  • WEP (802.11 wireless LAN confidentiality) was broken — not through RC4 itself but through how WEP generated RC4 keys; fixable by changing key generation. It shows how hard it is to combine cryptographic functions with protocols securely.
  • Later: a weakness in the key scheduling algorithm reduces the effort to find the key [PAUL07], and keystream biases allow recovery of repeatedly encrypted plaintexts [ALFA13].
  • Consequently RFC 7465 prohibits RC4 in TLS, and NIST SP 800-52 prohibits it for U.S. government use.

8.6True Random Number Generators

Entropy sources

A TRNG uses a nondeterministic source, usually by measuring unpredictable natural processes: pulse detectors of ionizing radiation, gas discharge tubes, leaky capacitors; Intel’s chip samples thermal noise from a coupled pair of inverters; LavaRnd uses a saturated CCD in a light-tight can. RFC 4086 lists computer sources usable with care:

  • Sound/video input — a sound digitizer with nothing plugged in, or a camera with the lens cap on, yields essentially thermal noise.
  • Disk drives — small random fluctuations in rotational speed due to chaotic air turbulence; the measurements are highly correlated and need significant processing.

Conditioning

Bias — a random process is biased (with respect to a set of possible outcomes) if some outcomes are more probable than others, e.g. more ones than zeros. Physical noise may contain periodic structures that look random but fail statistical tests. Skew is used in the same sense.
Min-entropy — a measure of the number of random bits in a block (book Appendix F). Entropy rate — assessed entropy of a bit string from the source divided by its length: k/n for an n-bit string with min-entropy k. It ranges from 0 (no entropy) to 1 (full entropy: unbiased, every bit and group of bits independent).
Conditioning (deskewing) algorithms — methods that further “randomize” hardware bits, assuming bias and an entropy rate below 1. Usually a cryptographic algorithm scrambles them: a hash function or a symmetric block cipher.
  • Hash function: pass blocks of m ≥ n input bits through an n-bit hash; the outputs are the random bits. Linux pools bits from four sources (mouse and keyboard activity, disk I/O, specific interrupts) and passes them through SHA-1 when bits are requested.
  • Hash_df (SP 800-90A): concatenate Hash(counter ‖ no_of_bits_to_return ‖ input_string) for counter = 1, 2, … and keep the leftmost bits — up to 255 × the hash length. Only the counter differs between blocks, but a strong hash’s diffusion makes the outputs completely different.
  • Block cipher: e.g. encrypt 128-bit blocks of TRNG bits with AES under some key; Intel uses an AES-based conditioner.

Health testing checks that the noise source works as expected and that the conditioner’s output has the desired characteristics; SP 800-90B recommends both.

On the noise source (point A). Digitized noise is expected to be biased, so SP 800-22 randomness tests would always fail; tests are tailored to the expected behaviour of a correctly working source, checking that it produces entropy at the expected rate. SP 800-90B mandates two continuous tests:

  • Repetition Count Test — quickly detects a catastrophic failure where the source gets “stuck” on one value. For min-entropy H bits per sample, Pr[C identical samples in a row] ≤ (2⁻ᴴ)^(C−1). Choose a tiny false-positive probability W and the smallest cutoff C with W ≥ (2⁻ᴴ)^(C−1):
    C = ⌈1 + (−log2 W) / H⌉ e.g. W = 2⁻³⁰, H = 7.3 → C = ⌈1 + 30/7.3⌉ = 6
    Count repetitions of the current sample value; reset to 1 when the value changes; report an error at C.
  • Adaptive Proportion Test — detects a large loss of entropy (physical failure, environmental change): record a sample value, observe the next N samples, and report an error if the value occurs at least C times. SP 800-90B recommends W = 2⁻³⁰ and gives guidance on N and C.

Intel Digital Random Number Generator

A hardware TRNG whose bit rate is comparable to PRNGs (an NRBG, despite the “DRNG” name). It is implemented entirely in hardware (more secure and faster than designs with a software component) and on the same multicore chip as the processors (no I/O delays).

Combined and simplified from Figures 8.10 and 8.11.
  • Entropy source — two inverters (NOT gates), each output feeding the other’s input, have two stable states. Clocked transistors force both into the same indeterminate state (all logical 1); thermal noise then settles them randomly into one stable state, giving one random bit per clock. Extra circuitry compensates for bias or correlation.
  • Conditioner — 512 bits at a time go through two hardware AES CBC implementations (two 128-bit blocks each; the second output kept), initially with an all-zero key; later the PRNG stage’s output becomes the key. Output: 256 bits, intended to have no skew or bias.
  • DRBG — the 256 bits enter the CTR_DRBG update function (initialized with Key = 0, V = 0, iterated twice and XORed in) to give a 128-bit key and 128-bit V; the generate function then outputs 128-bit blocks, faster than the entropy source. Cores read them with RDRAND.
  • ENRNG (enhanced nondeterministic random number generator) — provides seeds for other cryptographic algorithms, compliant with SP 800-90B and 90C; cores read them with RDSEED.

Chapter 7

7.1 What is triple encryption?

Encrypting with a block cipher three times in sequence using two or three keys. For DES the standard form is EDE: C = E(K3, D(K2, E(K1, P))), with K3 = K1 in the two-key version.

7.2 What is a meet-in-the-middle attack?

A known-plaintext attack on double encryption C = E(K2, E(K1, P)). Encrypt P under every K1 and store the results; decrypt C under every K2 and look for a match X = E(K1, P) = D(K2, C); confirm candidate key pairs on a second (P, C) pair. Against double DES it costs about 2⁵⁶ instead of 2¹¹².

7.3 How many keys are used in triple encryption?

Two (K1, K2, K1) or three (K1, K2, K3). Three-key 3DES has a 168-bit key but, because of meet-in-the-middle, about 112 bits of strength.

7.4 List and briefly define the block cipher modes of operation.

ECB: each block encrypted independently with the same key. CBC: each plaintext block XORed with the previous ciphertext block (the IV for the first) before encryption. CFB: s bits at a time; encrypt a shift register of previous ciphertext and XOR its leftmost s bits with the plaintext. OFB: like CFB but the encryption output is fed back and full blocks are XORed. CTR: XOR each block with the encryption of a counter that changes for every block. (Also XTS-AES for storage and FPE methods.)

7.5 Why do some block cipher modes of operation only use encryption while others use both encryption and decryption?

In CFB, OFB and CTR the cipher only produces a pseudorandom stream that is XORed with the data; XORing the same stream again recovers it, so both sides run the forward (encryption) function. In ECB and CBC the data itself passes through the cipher, so the receiver needs the inverse (decryption) function.

Chapter 8

8.1 List two criteria to validate the randomness of a sequence of numbers.

Uniform distribution (ones and zeros about equally frequent) and independence (no subsequence can be inferred from the others).

8.2 What is ANSI X9.17 PRNG?

A PRNG built from two-key triple DES (three EDE units with keys K1, K2). Inputs: a 64-bit date/time DTi and a 64-bit seed Vi. Outputs: Ri = EDE(Vi ⊕ EDE(DTi)) and the next seed Vi+1 = EDE(Ri ⊕ EDE(DTi)). Used in financial applications and PGP.

8.3 What is the difference between a one-time pad and a stream cipher?

A one-time pad XORs the data with a truly random key stream as long as the message, used once. A stream cipher XORs it with a pseudorandom keystream generated from a short key, so only the key must be shared.

8.4 List a few applications of stream ciphers and block ciphers.

Stream ciphers: streams of data such as a data communications channel or a browser/Web link (e.g. character-by-character, real-time traffic). Block ciphers: blocks of data such as file transfer, email and databases. Either can serve virtually any application.
