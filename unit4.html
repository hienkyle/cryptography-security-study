Finite Fields & AES

Chapter 5 builds up the algebra AES needs: groups, rings and fields, then the finite fields GF(p) and GF(2ⁿ), where every byte has a sum, a product and (if nonzero) an inverse. Chapter 6 uses arithmetic in GF(2⁸) to build the Advanced Encryption Standard: four round transformations, a key expansion, and fast implementations.

5.1Groups

Groups, rings and fields are the basic structures of abstract algebra: sets whose elements can be combined to give another element of the same set, under fixed rules. Each structure in this chapter adds rules to the one before (Figure 5.1).

Redrawn from Figure 5.1, labelled with the axioms each level adds (Figure 5.2).

Group

Binary operation. A rule, written ·, that takes an ordered pair (a, b) of elements and gives one element a · b. The symbol is generic: it may be addition, multiplication or some other operation.
Group {G, ·}. A set G with a binary operation such that, for all a, b, c in G:
  • (A1) Closure: a · b is in G.
  • (A2) Associative: a · (b · c) = (a · b) · c.
  • (A3) Identity element: there is an e with a · e = e · a = a.
  • (A4) Inverse element: each a has an a′ with a · a′ = a′ · a = e.
Example · the permutation group Sₙ

A permutation of n symbols {1, …, n} is a one-to-one mapping of the set onto itself. Sₙ, the set of all of them under composition, is a group: composing two permutations gives a permutation (A1), composition is associative (A2), the “do nothing” permutation {1, 2, …, n} is the identity (A3), and every permutation can be undone (A4). Example: {3, 2, 1} · {1, 3, 2} = {2, 3, 1}.

  • Finite group: finitely many elements. Its order is the number of elements. Otherwise it is an infinite group.
  • Abelian group: also satisfies (A5) Commutative: a · b = b · a. Examples: the integers under +; nonzero reals under ×. Sₙ is not abelian for n > 2.
  • When the operation is addition, the identity is written 0, the inverse of a is −a, and subtraction means a − b = a + (−b).

Cyclic group

Exponentiation in a group. Repeated application of the operation: a³ = a · a · a, a⁰ = e, and a⁻ⁿ = (a′)ⁿ.
Cyclic group. Every element is a power aᵏ (k an integer) of one fixed element a. That a generates G and is called a generator. A cyclic group is always abelian and may be finite or infinite. Example: the integers under + are generated by 1 (powers are read additively: n is the nth “power” of 1).

5.2Rings

A ring adds a second operation, multiplication. In a ring you can add, subtract and multiply without leaving the set — but not necessarily divide.

Ring {R, +, ×}. A set with two binary operations, addition and multiplication (usually written by juxtaposition, ab), such that for all a, b, c in R:
  • (A1–A5) R is an abelian group under addition (identity 0, inverse −a).
  • (M1) Closure under multiplication: ab is in R.
  • (M2) Associativity of multiplication: a(bc) = (ab)c.
  • (M3) Distributive laws: a(b + c) = ab + ac and (a + b)c = ac + bc.
Commutative ring. A ring that also satisfies (M4) ab = ba.
Examples: even integers; Zₙ = {0, …, n − 1} with arithmetic mod n. Not commutative: n × n real matrices (still a ring).
Integral domain. A commutative ring that also has (M5) a multiplicative identity 1 (a1 = 1a = a) and (M6) no zero divisors: if ab = 0 then a = 0 or b = 0.
Example: the integers.

5.3Fields

A field is a set in which you can add, subtract, multiply and divide without leaving the set. Division is defined as a / b = a(b⁻¹).

Field {F, +, ×}. An integral domain (A1–A5, M1–M6) that also satisfies (M7) Multiplicative inverse: every a except 0 has an a⁻¹ in F with aa⁻¹ = a⁻¹a = 1.

Equivalent view: F is a field if (1) it is an abelian group under addition, (2) its nonzero elements are an abelian group under multiplication, and (3) the distributive law holds.

Fields: rational, real and complex numbers. Not a field: the integers — only 1 and −1 have multiplicative inverses.

5.4Finite Fields of the Form GF(p)

Infinite fields are of little use in cryptography. The order of a finite field (its number of elements) must be a prime power pⁿ, n a positive integer. The field of order pⁿ is written GF(pⁿ) (GF = Galois field).

Redrawn from Figure 5.3. GF(p) (n = 1) has a different structure from n > 1. Of the GF(pⁿ) fields, GF(2ⁿ) is the one cryptography cares about (5.6).
GF(p), p prime. The set Zₚ = {0, 1, …, p − 1} with addition and multiplication mod p — ordinary modular arithmetic (Unit 2).

Why it is a field. Zₙ is always a commutative ring. An integer has a multiplicative inverse in Zₙ only if it is relatively prime to n (its only common positive factor with n is 1). When n = p is prime, every nonzero element is relatively prime to p, so M7 holds. Multiplying all of Zₚ by a nonzero w permutes the residues, so exactly one product is 1 — that partner is w⁻¹. Consequently the cancellation law needs no extra condition:

if (a × b) ≡ (a × c) (mod p) then b ≡ c (mod p) (5.1)

The simplest finite field: GF(2)

Multiplication = logical AND. Inverses: −0 = 0, −1 = 1, 1⁻¹ = 1.

Finding the multiplicative inverse in GF(p)

Small p: read it off the multiplication table (find the 1 in row w). Large p: use the extended Euclidean algorithm (Unit 2), which solves

ax + by = d = gcd(a, b) (2.7)

If gcd(a, b) = 1, then reducing mod a gives by ≡ 1 (mod a), so y = b⁻¹ mod a. The same works in any Zₙ: if the algorithm returns d = 1, then y = b⁻¹.

Summary. GF(p) has p elements; + and × are defined on the set; addition, subtraction, multiplication and division never leave the set; every nonzero element has an inverse, and division is multiplication by it.

5.5Polynomial Arithmetic

Fields with 2ⁿ elements are built from polynomials, so we first need polynomial arithmetic. There are three classes (Figure 5.4).

Redrawn from Figure 5.4. This section covers classes 1 and 2; class 3 is 5.6.

Ordinary polynomial arithmetic

Polynomial of degree n (n ≥ 0): f(x) = aₙxⁿ + aₙ₋₁xⁿ⁻¹ + … + a₁x + a₀ = Σ aᵢxⁱ with aₙ ≠ 0. The aᵢ come from a set S, the coefficient set; f is “defined over S”.
  • Constant polynomial: degree 0 — just an element of S. Monic polynomial: leading coefficient aₙ = 1.
  • Indeterminate: in abstract algebra we never plug a value in for x; x just marks positions.
  • Add / subtract: combine corresponding coefficients. Multiply: cₖ = a₀bₖ + a₁bₖ₋₁ + … + aₖb₀; degree of product = sum of degrees.
Example (Figure 5.5), S = integers
f(x) = x³ + x² + 2, g(x) = x² − x + 1 f + g = x³ + 2x² − x + 3 f − g = x³ + x + 1 f × g = x⁵ + 3x² − 2x + 2

Polynomial arithmetic with coefficients in Zₚ

Polynomial over a field F. Coefficients are elements of a field. The set of such polynomials is a ring, the polynomial ring.

Division needs the coefficients to be a field (e.g., (5x²)/(3x) has no solution over the integers, but equals 4x over Z₇). Even then it is not always exact; like integers, it leaves a remainder:

f(x) = q(x)·g(x) + r(x) deg q = n − m, deg r ≤ m − 1 (5.2)
  • Write r(x) = f(x) mod g(x). If r(x) = 0, then g(x) divides f(x), written g(x) | f(x); g(x) is a factor (divisor) of f(x).
  • Over GF(2), the case that matters most: + is XOR, × is AND, and addition = subtraction (1 + 1 = 1 − 1 = 0).
Irreducible (prime) polynomial. f(x) over F cannot be written as a product of two polynomials over F, both of lower degree than f(x).
x⁴ + 1 over GF(2) is reducible: x⁴ + 1 = (x + 1)(x³ + x² + x + 1). x³ + x + 1 is irreducible: neither x nor x + 1 divides it, and any factorization of a cubic would need a degree-1 factor.

Greatest common divisor

gcd[a(x), b(x)] is the polynomial c(x) that (1) divides both a(x) and b(x), and (2) is divisible by every common divisor — equivalently, the common divisor of maximum degree.

The Euclidean algorithm carries over unchanged (it assumes deg a ≥ deg b): repeat gcd[a(x), b(x)] = gcd[b(x), a(x) mod b(x)] (5.3) until the remainder is 0. The last nonzero remainder is the gcd.

Summary. Ordinary polynomials: +, −, × by the rules of algebra; no division unless the coefficients form a field. Coefficients in GF(p): all four operations, but division generally leaves a remainder. The Euclidean algorithm finds polynomial gcds over a field.

5.6Finite Fields of the Form GF(2ⁿ)

For n > 1, arithmetic mod pⁿ does not give a field. This section builds a field with 2ⁿ elements — exactly the n-bit words — from polynomials.

Motivation

An algorithm that divides must work in a field. For efficiency we want every n-bit pattern 0 … 2ⁿ − 1 to be usable. But Z₂ₙ (mod 2ⁿ) is not a field — e.g., 2 has no inverse mod 2ⁿ. Using the nearest prime instead (Z₂₅₁ for bytes) wastes the patterns 251–255.

Even without division, Z₂ₙ is a poor choice: its multiplication table is uneven, which a cryptanalyst might exploit. GF(2³) is uniform:

Modular polynomial arithmetic

Let S be the set of all polynomials of degree ≤ n − 1 with binary coefficients — there are exactly 2ⁿ of them, one per n-bit string (aₙ₋₁ … a₁a₀). With these rules, S is a finite field:

  1. Use ordinary polynomial arithmetic, with two refinements:
  2. coefficient arithmetic is mod 2 (XOR);
  3. if a product has degree > n − 1, reduce it mod an irreducible polynomial m(x) of degree n — divide by m(x), keep the remainder.
  • The set of residues modulo an nth-degree m(x) has pⁿ elements, one per polynomial of degree < n. The residue class [x + 1] is every a(x) with a(x) mod m(x) = x + 1.
  • All finite fields of the same order are isomorphic: same structure, possibly different labels for the elements.
  • GF(2³) has two possible m(x): x³ + x² + 1 and x³ + x + 1.
Book example in GF(2⁸), m(x) = x⁸ + x⁴ + x³ + x + 1
f(x) = x⁶ + x⁴ + x² + x + 1, g(x) = x⁷ + x + 1 f + g = x⁷ + x⁶ + x⁴ + x² f × g = x¹³ + x¹¹ + x⁹ + x⁸ + x⁶ + x⁵ + x⁴ + x³ + 1 mod m(x) = x⁷ + x⁶ + 1

Finding the multiplicative inverse

The extended Euclidean algorithm adapts to polynomials. If deg b(x) < deg a(x) and gcd[a(x), b(x)] = 1, it solves

a(x)v(x) + b(x)w(x) = d(x) = gcd[a(x), b(x)]

and when d(x) = 1, w(x) = b(x)⁻¹ mod a(x). If a(x) is irreducible, its only factors are itself and 1, so the gcd is always 1. Each step: rᵢ = rᵢ₋₂ mod rᵢ₋₁, vᵢ = vᵢ₋₂ − qᵢvᵢ₋₁, wᵢ = wᵢ₋₂ − qᵢwᵢ₋₁ (over GF(2), − is ⊕).

Computational considerations

Each element of GF(2ⁿ) is an n-bit number. For GF(2⁸) that is one byte, written in hex as {..} (two 4-bit groups).

Addition = bitwise XOR. (x⁶+x⁴+x²+x+1) + (x⁷+x+1) = x⁷+x⁶+x⁴+x², i.e. 01010111 ⊕ 10000011 = 11010100, i.e. {57} ⊕ {83} = {D4}.

Multiplication has no single XOR, but it is cheap. Key observation for m(x) = x⁸ + x⁴ + x³ + x + 1:

x⁸ mod m(x) = m(x) − x⁸ = x⁴ + x³ + x + 1 = {1B} (5.4)

Multiplying f(x) = b₇x⁷ + … + b₀ by x shifts every coefficient up one place. If b₇ = 0 nothing overflows; if b₇ = 1 the x⁸ term is replaced by {1B}:

x · f(x) = (b₆b₅b₄b₃b₂b₁b₀0) if b₇ = 0 x · f(x) = (b₆b₅b₄b₃b₂b₁b₀0) ⊕ (00011011) if b₇ = 1 (5.6)

So ×{02} = 1-bit left shift + conditional XOR with {1B}. Repeating it gives ×x², ×x³, …; XOR the ones you need to multiply by any constant.

Using a generator

Generator. An element g of a finite field F of order q whose first q − 1 powers produce every nonzero element: F = {0, g⁰, g¹, …, g^(q−2)}.
Root. For a field defined by polynomial f(x), an element b of F with f(b) = 0. A root g of an irreducible polynomial is a generator of the field defined on that polynomial.

For GF(2³) with x³ + x + 1: g³ + g + 1 = 0, so g³ = g + 1 (− = + mod 2). Then g⁴ = g² + g, g⁵ = g² + g + 1, g⁶ = g² + 1, g⁷ = 1 = g⁰ (Table 5.5; switch the lab above to “power of g”). Multiplication becomes adding exponents: gᵏ = g^(k mod 7); in general gᵏ = g^(k mod (2ⁿ−1)).

Book example
g⁴ · g⁶ = g¹⁰ = g³ = g + 1 (power form) (g² + g)(g² + 1) = g⁴ + g³ + g² + g, mod (g³ + g + 1) = g + 1 (polynomial form, same answer)
Summary. GF(2ⁿ) has 2ⁿ elements: all polynomials of degree ≤ n − 1 with binary coefficients, each a unique n-bit value. +, −, ×, ÷ never leave the set; every nonzero element has an inverse. Addition is XOR; multiplication is polynomial multiplication mod an irreducible m(x).

6.1Finite Field Arithmetic in AES

The Advanced Encryption Standard (AES) is a symmetric block cipher, published by NIST, intended to replace DES. Every AES operation works on 8-bit bytes in GF(2⁸).

Addition of two bytes

Bitwise XOR: cᵢ = aᵢ ⊕ bᵢ.

Multiplication of two bytes

Multiplication in GF(2⁸) with the irreducible polynomial m(x) = x⁸ + x⁴ + x³ + x + 1. It is the first of the 30 irreducible degree-8 polynomials in the list the designers used.

Multiplication by {02}

{02}·A = (a₆…a₀0) if a₇ = 0, else (a₆…a₀0) ⊕ {1B}. Larger constants: repeat and XOR.

Notation (from FIPS PUB 197): hex bytes in curly brackets, · = multiplication in GF(2⁸), ⊕ = XOR = addition in GF(2⁸). The book’s Appendix I describes a hand-computable Simplified AES (S-AES) worth working through alongside this chapter.

6.2AES Structure

Block size is always 128 bits (16 bytes). The key is 16, 24 or 32 bytes, giving AES-128, AES-192 or AES-256.

General structure

  • The 128-bit input block is copied into the State, a 4 × 4 matrix of bytes that every stage modifies; after the final stage State is copied to the output.
  • Bytes fill the matrix by column: the first 4 input bytes form the first column, and so on. The key is arranged the same way, then expanded into words (columns); 44 words for a 128-bit key.
  • N rounds. Rounds 1 … N − 1 use four transformations — SubBytes, ShiftRows, MixColumns, AddRoundKey. The final round has three (no MixColumns). One AddRoundKey comes before round 1 (“round 0”).
  • Key expansion produces N + 1 round keys, each a 4 × 4 matrix, one per AddRoundKey.

6.3AES Transformation Functions

For each stage: the forward (encryption) step, its inverse (decryption) step, and the design rationale.

Redrawn from Figure 6.4. Colours mark the column each byte starts in: after ShiftRows the four bytes of every column feed four different columns of MixColumns.

Substitute bytes (SubBytes)

S-box. A 16 × 16 table of bytes containing a permutation of all 256 byte values (Table 6.2a). SubBytes replaces each State byte independently: its left 4 bits select the row, its right 4 bits the column. Example: {95} → row 9, column 5 → {2A}.

Construction (Figure 6.6a):

  1. Initialize the table in ascending order: row y, column x holds {yx}.
  2. Replace each byte by its multiplicative inverse in GF(2⁸); {00} maps to itself.
  3. Apply an affine transformation to each bit, with c = {63} = 01100011:
bᵢ′ = bᵢ ⊕ b₍ᵢ₊₄₎ mod 8 ⊕ b₍ᵢ₊₅₎ mod 8 ⊕ b₍ᵢ₊₆₎ mod 8 ⊕ b₍ᵢ₊₇₎ mod 8 ⊕ cᵢ (6.1)

In matrix form (Eq. 6.2) this is an 8 × 8 bit matrix times the bit vector, plus {63}, where “multiply” is AND and “add” is XOR. InvSubBytes uses the inverse S-box (Table 6.2b), built by applying the inverse affine map bᵢ′ = b₍ᵢ₊₂₎ ⊕ b₍ᵢ₊₅₎ ⊕ b₍ᵢ₊₇₎ ⊕ dᵢ (indices mod 8, d = {05}) and then the GF(2⁸) inverse.

Rationale. Designed to resist known cryptanalytic attacks: low correlation between input and output bits, and an output that is not a linear function of the input — the nonlinearity comes from the multiplicative inverse. The constant {63} was chosen so there are no fixed points (S(a) = a) and no opposite fixed points (S(a) = ā, the bitwise complement). The S-box is invertible but not self-inverse: S({95}) = {2A} while IS({95}) = {AD}.

ShiftRows

ShiftRows: row 0 unchanged; row 1 circular left shift by 1 byte; row 2 by 2; row 3 by 3. InvShiftRows shifts rows 1–3 right by the same amounts.

Watch it · ShiftRows (Figure 6.7a)

Book example: rows 87 F2 4D 97 / EC 6E 4C 90 / 4A C3 46 E7 / 8C D8 95 A6. Colours = original column. After the shift, every column holds one byte from each original column.

Rationale. More substantial than it looks: State, the input/output and the round key are all handled column by column, so moving a byte along its row moves it to another column (a linear distance of a multiple of 4 bytes). The 4 bytes of one column end up in 4 different columns.

MixColumns

MixColumns works on each column separately: every output byte depends on all four bytes of the column. Matrix form, with + = XOR and · = GF(2⁸) multiplication:

┌02 03 01 01┐ ┌s₀,ⱼ┐ s₀,ⱼ′ = (2·s₀,ⱼ) ⊕ (3·s₁,ⱼ) ⊕ s₂,ⱼ ⊕ s₃,ⱼ │01 02 03 01│ │s₁,ⱼ│ s₁,ⱼ′ = s₀,ⱼ ⊕ (2·s₁,ⱼ) ⊕ (3·s₂,ⱼ) ⊕ s₃,ⱼ │01 01 02 03│ │s₂,ⱼ│ s₂,ⱼ′ = s₀,ⱼ ⊕ s₁,ⱼ ⊕ (2·s₂,ⱼ) ⊕ (3·s₃,ⱼ) └03 01 01 02┘ └s₃,ⱼ┘ s₃,ⱼ′ = (3·s₀,ⱼ) ⊕ s₁,ⱼ ⊕ s₂,ⱼ ⊕ (2·s₃,ⱼ) (6.3, 6.4)

×{03} is computed as {03}·a = ({02}·a) ⊕ a. InvMixColumns multiplies by the matrix with rows 0E 0B 0D 09 / 09 0E 0B 0D / 0D 09 0E 0B / 0B 0D 09 0E (Eq. 6.5); the product of the two matrices is the identity (Eq. 6.6).

Try it · MixColumns on one column

Polynomial view (used by FIPS 197): each column is a four-term polynomial with coefficients in GF(2⁸), multiplied modulo x⁴ + 1 by the fixed polynomial

a(x) = {03}x³ + {01}x² + {01}x + {02} (6.7) b(x) = {0B}x³ + {0D}x² + {09}x + {0E} = a⁻¹(x) mod (x⁴ + 1) (6.8)
Rationale. The coefficients come from a linear code with maximal distance between code words, giving good mixing within each column. MixColumns plus ShiftRows make every output bit depend on every input bit after a few rounds. Coefficients {01}, {02}, {03} cost at most a shift and an XOR. InvMixColumns is costlier, but encryption was considered more important: CFB and OFB modes (Unit 5) and block-cipher MACs (Unit 7) use only encryption.

AddRoundKey

AddRoundKey. XOR the 128 bits of State with the 128 bits of the round key — column by column (one State column with one key word), or equivalently byte by byte. It is its own inverse, since XOR is.
Book example (first column)
{47} ⊕ {AC} = {EB} {37} ⊕ {77} = {40} {94} ⊕ {66} = {F2} {ED} ⊕ {F3} = {1E}
Rationale. As simple as possible, and it affects every bit of State. Security comes from the complexity of the key expansion together with the other stages.

Inputs to a single round (Figure 6.8): the constant inputs are the S-box and the MixColumns matrix; the variable inputs are State and the round key.

6.4AES Key Expansion

AES-128 takes a 4-word (16-byte) key and produces a linear array of 44 words (176 bytes): one 4-word round key for the initial AddRoundKey and for each of the 10 rounds.

KeyExpansion (byte key[16], word w[44]) { word temp for (i = 0; i < 4; i++) w[i] = (key[4*i], key[4*i+1], key[4*i+2], key[4*i+3]); for (i = 4; i < 44; i++) { temp = w[i − 1]; if (i mod 4 = 0) temp = SubWord(RotWord(temp)) ⊕ Rcon[i/4]; // = g(w[i−1]) w[i] = w[i − 4] ⊕ temp } }

The key fills w[0..3]. Each later word depends on the word just before, w[i − 1], and the word four back, w[i − 4]: a plain XOR in three cases out of four, and the function g when i is a multiple of 4.

  1. RotWord: one-byte circular left shift, [B₀, B₁, B₂, B₃] → [B₁, B₂, B₃, B₀].
  2. SubWord: S-box substitution on each of the 4 bytes.
  3. XOR with the round constant Rcon[j] = (RC[j], 0, 0, 0), so only the leftmost byte changes. RC[1] = 1, RC[j] = {02}·RC[j − 1] in GF(2⁸).

Rationale

The round-dependent constant removes symmetry between how round keys of different rounds are made. Design criteria:

  • Knowing part of the cipher key or a round key does not reveal many other round-key bits (with fewer than Nk consecutive words known, the rest is hard to reconstruct).
  • An invertible transformation: any Nk consecutive words of the expanded key regenerate all of it (Nk = key size in words).
  • Speed on a wide range of processors; simplicity of description.
  • Round constants to eliminate symmetries.
  • Diffusion of cipher-key differences into the round keys: each key bit affects many round-key bits.
  • Enough nonlinearity that round-key differences cannot be fully determined from cipher-key differences alone.

Avalanche effect

Avalanche effect. A small change in plaintext or key produces a large change in ciphertext. If it were small, it could be used to reduce the plaintext or key space to be searched. The ideal is about half the bits changing — almost all bits changing would be as informative as almost none.

6.6AES Implementation

Equivalent inverse cipher

Standard decryption orders its steps differently from encryption, so software needing both requires two modules. The equivalent inverse cipher has the same step order as encryption (with each step replaced by its inverse) at the cost of a changed key schedule. Two swaps are needed:

Encryption round

SubBytes → ShiftRows → MixColumns → AddRoundKey

Standard decryption round

InvShiftRows → InvSubBytes → AddRoundKey → InvMixColumns

Equivalent inverse round

InvSubBytes → InvShiftRows → InvMixColumns → AddRoundKey(InvMixColumns(key))

  1. InvShiftRows ↔ InvSubBytes. InvShiftRows changes byte order but not byte contents; InvSubBytes changes contents but not order, and neither depends on what the other changes. So they commute: InvShiftRows[InvSubBytes(Sᵢ)] = InvSubBytes[InvShiftRows(Sᵢ)].
  2. AddRoundKey ↔ InvMixColumns. Both act on State one column at a time, and InvMixColumns is linear over XOR: InvMixColumns(Sᵢ ⊕ wⱼ) = InvMixColumns(Sᵢ) ⊕ InvMixColumns(wⱼ). So they can be swapped if InvMixColumns is first applied to the round key — except for the first and last AddRoundKey, which are not swapped (Figure 6.10).

The AES lab above also runs the equivalent inverse cipher in your browser; both decryptions return the same plaintext.

8-bit processors (e.g., smart cards)

AddRoundKey is a byte XOR, ShiftRows a byte shift, SubBytes a 256-byte table. MixColumns needs only ×{02} and ×{03}; using {03}·x = ({02}·x) ⊕ x, Eq. 6.4 becomes

Tmp = s₀,ⱼ ⊕ s₁,ⱼ ⊕ s₂,ⱼ ⊕ s₃,ⱼ s₀,ⱼ′ = s₀,ⱼ ⊕ Tmp ⊕ [2·(s₀,ⱼ ⊕ s₁,ⱼ)] s₁,ⱼ′ = s₁,ⱼ ⊕ Tmp ⊕ [2·(s₁,ⱼ ⊕ s₂,ⱼ)] s₂,ⱼ′ = s₂,ⱼ ⊕ Tmp ⊕ [2·(s₂,ⱼ ⊕ s₃,ⱼ)] s₃,ⱼ′ = s₃,ⱼ ⊕ Tmp ⊕ [2·(s₃,ⱼ ⊕ s₀,ⱼ)] (6.9)
Timing attacks. The shift-and-conditional-XOR for ×{02} may take data-dependent time, exposing it to a timing attack (Unit 3, Section 4.4). Replacing it with a 256-byte lookup table X2[i] = {02}·i both counters this and is faster, at some storage cost.

32-bit processors (e.g., PCs)

Combine all four stages of a round on column j into one equation (ShiftRows column indices mod 4):

sⱼ′ = T₀[s₀,ⱼ] ⊕ T₁[s₁,ⱼ₋₁] ⊕ T₂[s₂,ⱼ₋₂] ⊕ T₃[s₃,ⱼ₋₃] ⊕ kⱼ T₀[x] = (02, 01, 01, 03)·S[x] T₁[x] = (03, 02, 01, 01)·S[x] T₂[x] = (01, 03, 02, 01)·S[x] T₃[x] = (01, 01, 03, 02)·S[x]

Each T-table maps a byte to a 32-bit column word and can be precomputed: 4 tables × 256 words = 4 KB. A round costs only 4 table lookups and 4 XORs per column. Rijndael’s developers believe this compact, efficient implementation was probably one of the most important reasons it was selected as AES.

App. 6APolynomials with Coefficients in GF(2⁸)

A second polynomial layer: words are polynomials of degree ≤ 3 whose four coefficients are bytes (elements of GF(2⁸)). This is how FIPS 197 defines MixColumns.

  • Do not mix the layers up: a byte is a degree ≤ 7 polynomial with bit coefficients, multiplied mod a degree-8 polynomial; a word is a degree ≤ 3 polynomial with byte coefficients, multiplied mod the degree-4 polynomial x⁴ + 1.
  • Addition: add corresponding coefficients in GF(2⁸), i.e., XOR byte by byte.
  • Multiplication: ordinary polynomial multiplication with coefficients multiplied in GF(2⁸), then reduce mod x⁴ + 1. The result is a polynomial ring, not a field (x⁴ + 1 is reducible).
xⁱ mod (x⁴ + 1) = x^(i mod 4) (6.13)

So reducing just folds the high coefficients back: d(x) = c₃x³ + (c₂ ⊕ c₆)x² + (c₁ ⊕ c₅)x + (c₀ ⊕ c₄), which is the circulant matrix product

┌d₀┐ ┌a₀ a₃ a₂ a₁┐ ┌b₀┐ │d₁│ = │a₁ a₀ a₃ a₂│ │b₁│ │d₂│ │a₂ a₁ a₀ a₃│ │b₂│ └d₃┘ └a₃ a₂ a₁ a₀┘ └b₃┘ (6.14)

With a(x) = {03}x³ + {01}x² + {01}x + {02} (a₃ = 03, a₂ = 01, a₁ = 01, a₀ = 02) this is exactly the MixColumns matrix of Eq. 6.3.

5.7 · 6.7Review Questions

Review questions 5.1–5.4 and 6.1–6.14 from the book. Answer first, then open to check.

Chapter 5

5.1 Briefly define a group.

A set of elements with a binary operation that is closed, associative, has an identity element, and gives every element an inverse (A1–A4).

5.2 Briefly define a ring.

A set with two operations, addition and multiplication, that is an abelian group under addition, and whose multiplication is closed and associative and distributes over addition (A1–A5, M1–M3). You can add, subtract and multiply without leaving the set.

5.3 Briefly define a field.

An integral domain in which every nonzero element has a multiplicative inverse (A1–M7): addition, subtraction, multiplication and division all stay inside the set.

5.4 List three classes of polynomial arithmetic.

(1) Ordinary polynomial arithmetic; (2) arithmetic with coefficients mod p (in GF(p)); (3) coefficients in GF(p) and polynomials reduced modulo a polynomial m(x) of degree n.

Chapter 6

6.1–6.2 are answered in the book’s online Appendix H; the answers below follow NIST’s own report on the AES selection (see Sources).

6.1 What was the original set of criteria used by NIST to evaluate candidate AES ciphers?

Security (resistance to cryptanalysis, soundness of the mathematics, randomness of output, relative security); cost (licensing, computational efficiency, memory requirements); and algorithm and implementation characteristics (flexibility, hardware and software suitability, simplicity).

6.2 What was the final set of criteria used by NIST to evaluate candidate AES ciphers?

General security; software implementations; restricted-space environments; hardware implementations; attacks on implementations; encryption vs. decryption; key agility; other versatility and flexibility; potential for instruction-level parallelism.

6.3 What is the difference between Rijndael and AES?

AES is one instantiation of Rijndael. Rijndael supports additional block sizes and key lengths; AES fixes the block at 128 bits and allows only 128-, 192- and 256-bit keys (FIPS 197).

6.4 What is the purpose of the State array?

It holds the 128-bit block as a 4 × 4 byte matrix (filled by column) that every stage of encryption or decryption modifies; at the end it is copied to the output.

6.5 How is the S-box constructed?

Fill row y, column x with {yx}; replace each byte with its multiplicative inverse in GF(2⁸) ({00} stays {00}); then apply the affine transformation of Eq. 6.1 with constant {63}.

6.6 Briefly describe SubBytes.

Each State byte is replaced by an S-box lookup: the left 4 bits pick the row, the right 4 bits the column.

6.7 Briefly describe ShiftRows.

Row 0 is unchanged; rows 1, 2 and 3 are circularly shifted left by 1, 2 and 3 bytes.

6.8 How many bytes in State are affected by ShiftRows?

12 — the bytes of rows 1–3. Row 0’s 4 bytes stay put.

6.9 Briefly describe MixColumns.

Each column is multiplied by a fixed 4 × 4 matrix (entries {01}, {02}, {03}) over GF(2⁸), so each output byte is a function of all four bytes of its column.

6.10 Briefly describe AddRoundKey.

The 128 bits of State are XORed with the 128 bits of the round key, column by column; it is its own inverse.

6.11 Briefly describe the key expansion algorithm.

The 4-word key becomes w[0..3]. For i = 4 … 43, w[i] = w[i − 4] ⊕ w[i − 1], except when i is a multiple of 4, when w[i − 1] is first passed through g: RotWord, SubWord, then XOR with Rcon[i/4]. Result: 44 words, 11 round keys.

6.12 What is the difference between SubBytes and SubWord?

Both use the same S-box. SubBytes acts on all 16 State bytes in each round; SubWord acts on the 4 bytes of one word inside the key expansion.

6.13 What is the difference between ShiftRows and RotWord?

ShiftRows shifts the rows of State by 0–3 bytes during encryption; RotWord rotates one 4-byte word left by one byte during key expansion.

6.14 What is the difference between the AES decryption algorithm and the equivalent inverse cipher?

Standard decryption orders each round InvShiftRows, InvSubBytes, AddRoundKey, InvMixColumns — different from encryption. The equivalent inverse cipher swaps the first two and the last two steps so the order matches encryption, which requires applying InvMixColumns to round keys 1–9.
