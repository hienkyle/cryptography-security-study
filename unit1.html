Unit 1 · Security Foundations

Computer and Network Security Concepts

Stallings, 7th ed. Global · Ch. 1 pp. 19–45 Sections 1.1 – 1.9

This chapter sets the vocabulary for the whole course: what "secure" means (the CIA triad), how X.800 sorts the field into attacks, services and mechanisms, the design principles that guide protection, and two tools for analyzing threats.

After this unit you should be able to
  • Describe the key requirements of confidentiality, integrity and availability.
  • Describe the X.800 security architecture for OSI.
  • Discuss the types of threats and attacks, with examples for different kinds of assets.
  • Explain the fundamental security design principles.
  • Discuss the use of attack surfaces and attack trees.
  • List and briefly describe the key organizations behind cryptography standards.
Area 1 · Cryptographic algorithms & protocols
  • Symmetric encryption hides the contents of data of any size: messages, files, keys, passwords.
  • Asymmetric encryption hides small blocks, such as keys and hash values used in digital signatures.
  • Data integrity algorithms protect blocks of data from alteration.
  • Authentication protocols use crypto algorithms to confirm the identity of entities.
Area 2 · Network & Internet security

Measures to deter, prevent, detect and correct security violations that involve the transmission of information. This area relies heavily on the cryptographic techniques from Area 1.

Terms used before the book defines them
Information vs. data
Information is facts and ideas; data is information in a specific physical form, usually symbols a computer can process. The book (like most security literature) treats them as the same.Stallings Ch. 1, fn. 1, citing RFC 4949
Vulnerability
A weakness in a system, its security procedures, internal controls or implementation that a threat source could exploit or trigger.NIST CSRC Glossary (FIPS 200)
Security policy
The set of rules and practices that say how an organization manages, protects and distributes sensitive information.NIST CSRC Glossary (CNSSI 4009)

Why security is hard: the ten challenges

  1. Requirements sound simple; the mechanisms that meet them are complex and subtle.
  2. Designers must anticipate attacks, which often exploit a weakness from an unexpected angle.
  3. So procedures are often counterintuitive; they only make sense once the threat is considered.
  4. Mechanisms must be placed both physically (where in the network) and logically (which layer, e.g. of TCP/IP).
  5. Mechanisms depend on secret information (keys) that must be created, distributed and protected, and on protocols whose delays can break timing assumptions.
  6. It is a battle of wits: the attacker needs one weakness; the designer must close all of them.
  7. Users and managers see little benefit from security until a failure occurs.
  8. Security needs constant monitoring, which is hard in overloaded environments.
  9. Security is often an afterthought added after design.
  10. Strong security is seen as an obstacle to efficient, user-friendly operation.
Section 1.2

The OSI Security Architecture

Managers need a systematic way to define security requirements and the approaches that satisfy them. ITU-T Recommendation X.800, Security Architecture for OSI, provides it. Because it is an international standard, vendors build product security features around its definitions.

OSI
Open Systems Interconnection, a layered protocol architecture. You do not need to know its layers for this chapter (covered in Appendix L).
ITU-T
The Telecommunication Standardization Sector of the International Telecommunication Union, a UN-sponsored agency. Its standards are called Recommendations.
Protocol layer
One level of a layered communication architecture, such as TCP or an application-layer protocol. Mechanisms can be placed at a particular layer (§1.5).
Security attack
Any action that compromises the security of information owned by an organization.
Security mechanism
A process, or a device incorporating one, designed to detect, prevent or recover from a security attack.
Security service
A processing or communication service that enhances the security of data processing systems and information transfers. Services counter attacks using one or more mechanisms.
Threat (RFC 4949)
A potential for violation of security: a circumstance, capability, action or event that could breach security and cause harm. A possible danger that might exploit a vulnerability.
Attack (RFC 4949)
An actual assault on system security from an intelligent threat: a deliberate attempt to evade security services and violate the security policy.
Section 1.3

Security Attacks

X.800 and RFC 4949 split attacks in two. A passive attack tries to learn or use information but does not affect system resources. An active attack tries to alter system resources or affect their operation.

PASSIVEACTIVE
NatureEavesdropping on or monitoring transmissionsModifying the data stream or creating a false stream
TypesRelease of message contents; traffic analysisMasquerade; replay; modification of messages; denial of service
DetectionVery hard: data is not altered, so sender and receiver are unawareFeasible; the goal is to detect
PreventionFeasible, usually by encryptionHard to prevent absolutely, given the variety of physical, software and network vulnerabilities
EmphasisPreventionDetection and recovery (detection may also deter)
Key term · EncryptionThe common technique for masking message contents so a captured message cannot be read. It defeats release of contents, but not traffic analysis, because the pattern of messages is still visible.
Section 1.4

Security Services

Definition · RFC 4949A security service is a processing or communication service provided by a system to give a specific kind of protection to system resources. Services implement security policies and are implemented by security mechanisms.

X.800 groups services into 5 categories and 14 specific services (Table 1.2). Availability is treated separately.

Peer entities
Two entities are peers if they implement the same protocol in different systems, e.g. two TCP modules in two communicating systems.
Connection-oriented
Deals with a stream of messages over an established logical connection.
Connectionless
Deals with individual messages (data blocks) without regard to any larger context.
Repudiation
Denying having taken part in a communication. Nonrepudiation is protection against it.
Authentication

Assures the communicating entity is the one it claims to be. For an ongoing interaction it checks identities at connection start and guards against a third party masquerading later.

  • Peer entity authentication: confidence in the identities of entities on a logical connection; guards against masquerade and replay of an earlier connection.
  • Data-origin authentication: in a connectionless transfer, the source of data is as claimed. No protection against duplication or modification. Suits email.
Access control

Prevents unauthorized use of a resource: who can access it, under what conditions, and what they may do. Each entity must first be identified or authenticated so rights can be tailored to it.

Data confidentiality

Protects transmitted data from passive attacks.

  • Connection: all user data on a connection (the broadest, most useful form).
  • Connectionless: all user data in a single block.
  • Selective-field: chosen fields in a connection or block.
  • Traffic-flow: hides source, destination, frequency, length and other traffic characteristics.
Data integrity

Data received are exactly as sent (no modification, insertion, deletion or replay). Relates to active attacks, so the focus is detection.

  • Connection integrity with recovery
  • Connection integrity without recovery (detect only)
  • Selective-field connection integrity
  • Connectionless integrity (modification; limited replay detection)
  • Selective-field connectionless integrity
Nonrepudiation

Prevents sender or receiver from denying a transmitted message.

  • Origin: proof the message was sent by the specified party.
  • Destination: proof the message was received by the specified party.
Availability service

Protects a system so it stays accessible and usable on demand by authorized entities, per its performance specification. Addresses denial-of-service attacks. Depends on access control and other services.

Count check: 2 + 1 + 4 + 5 + 2 = 14 specific services (access control is one service with no sub-types).

Section 1.5

Security Mechanisms

X.800 mechanisms (Table 1.3) come in two groups: specific ones that can sit in a particular protocol layer, and pervasive ones not tied to any layer or service.

Specific mechanisms
Encipherment
Mathematical algorithms transform data into an unintelligible form; recovery depends on the algorithm and zero or more keys.
Digital signature
Data appended to, or a cryptographic transformation of, a data unit that lets the recipient prove its source and integrity and protects against forgery.
Access control
Mechanisms that enforce access rights to resources.
Data integrity
Mechanisms that assure the integrity of a data unit or stream.
Authentication exchange
Ensures an entity's identity by exchanging information.
Traffic padding
Inserting bits into gaps in a data stream to frustrate traffic analysis.
Routing control
Selecting physically secure routes, and changing routes when a breach is suspected.
Notarization
Using a trusted third party to assure properties of a data exchange.
Pervasive mechanisms
Trusted functionality
That which is perceived to be correct with respect to some criteria, e.g. a security policy.
Security label
A marking bound to a resource that names its security attributes.
Event detection
Detection of security-relevant events.
Security audit trail
Data collected to support a security audit: an independent review and examination of system records and activities.
Security recovery
Handles requests from mechanisms such as event handling and management functions, and takes recovery actions.
Encipherment, two kindsReversible: an encryption algorithm; data can be encrypted then decrypted.
Irreversible: hash algorithms and message authentication codes, used in digital signatures and message authentication.
Section 1.6

Fundamental Security Design Principles

No technique can systematically exclude all security flaws, so designers follow widely agreed principles. The National Centers of Academic Excellence in Information Assurance/Cyber Defense (NSA and DHS) list 13.

Privilege
A right granted to a user or process to perform an action on a resource (the book's "permission": a permitted access, e.g. read/write a file, connect to a host and port).
Role-based access control
The security policy defines roles for users or processes; each role gets only the permissions needed for its functions.
Multifactor authentication
Requires multiple techniques, such as a password and a smart card, to authorize a user.

Economy of mechanism

Keep security design as simple and small as possible: easier to test and verify, fewer exploitable flaws. The hardest principle to honor, given demand for features.

Fail-safe defaults

Base access on permission, not exclusion; the default is no access.

Why: a mistake fails by refusing access (safe, quickly noticed) instead of allowing it (may go unnoticed).

Complete mediation

Check every access against the access control mechanism; don't rely on cached decisions.

Note: file systems usually skip re-checks after a file is opened; full mediation is resource-intensive and rare.

Open design

The mechanism's design should be public, not secret. Keys stay secret; algorithms are open to scrutiny.

Example: NIST's program of standardizing open encryption and hash algorithms.

Separation of privilege

Require multiple privilege attributes to reach a restricted resource; also, split a program into parts each limited to the privileges its task needs.

Example: multifactor authentication; running high-privilege operations in a separate process.

Least privilege

Every process and user operates with the smallest set of privileges needed. Includes time: hold special privileges only while needed.

Example: role-based access control.

Least common mechanism

Minimize functions shared by different users, reducing unintended communication paths and shared code everyone depends on.

Psychological acceptability

Mechanisms should not unduly hinder users and should match their mental model of protection; otherwise users disable them or make errors.

Isolation

Three contexts: isolate public access systems from critical resources (physically or logically); isolate users' processes and files from each other; isolate security mechanisms themselves from tampering.

Encapsulation

A form of isolation based on object-oriented functionality: a data object's internals are reachable only through the protected subsystem's procedures, called only at designated entry points.

Modularity

Build security functions as separate, protected modules (e.g. one common cryptographic module), in an architecture where parts can be upgraded without redesigning the whole system.

Layering

Use multiple, overlapping protections across people, technology and operations, so one failure doesn't leave the system exposed. Also called defense in depth.

Least astonishment

A program or interface should respond in the way least likely to astonish the user; users should intuitively see how security goals map to mechanisms.

Section 1.7

Attack Surfaces and Attack Trees

Two tools for evaluating and classifying threats.

Attack surface

The reachable and exploitable vulnerabilities in a system. Examples: open ports on outward-facing servers and the code listening on them; services inside a firewall; code that processes incoming data, email, XML and office documents; interfaces, SQL and web forms; an employee with sensitive access who is vulnerable to social engineering.

Port
An entry or exit point on a computer for connecting communications or peripheral devices.NIST CSRC Glossary (SP 800-82r3)
Firewall
A gateway that limits access between networks according to local security policy.NIST CSRC Glossary (SP 800-12 Rev. 1)
Social engineering
Tricking someone into revealing information (e.g. a password) that can be used to attack systems or networks.NIST CSRC Glossary (SP 800-82r3)
Network attack surface

Vulnerabilities over an enterprise network, WAN or the Internet: protocol flaws used for denial of service, disruption of links, intruder attacks.

Software attack surface

Vulnerabilities in application, utility or operating system code, with particular focus on web server software.

Human attack surface

Vulnerabilities created by personnel or outsiders: social engineering, human error, trusted insiders.

An attack surface analysis shows where mechanisms are needed, lets designers shrink the surface, and sets priorities for testing and strengthening.

Attack tree

A branching, hierarchical data structure representing potential techniques for exploiting vulnerabilities.

  • Root node: the attacker's goal (the security incident).
  • Subnodes: subgoals, each possibly with its own subgoals.
  • Leaf nodes: the final nodes on each path; the different ways to initiate an attack.
  • AND-node: all child subgoals must be achieved. OR-node: at least one must be.
  • Branches can be labeled with difficulty, cost or other attributes to compare alternatives.

Analysts use trees to document attacks in a structured form that reveals key vulnerabilities, guiding both system design and the choice and strength of countermeasures.

Strategy (child of root)How it works
User credential compromiseWatching a user to observe a PIN; stealing tokens or notes; hacking the smartcard or brute-forcing the PIN; malware capturing login and password; sniffing the channel; engaging the user directly.

Trying every possible value (here, PINs or username/password pairs) until one works. Stallings Ch. 3 defines the same idea for keys.
Sniffing
Passively capturing data as it crosses the communication channel; a sniffer is also called a packet sniffer or passive wiretap.Stallings Ch. 1; NIST CSRC Glossary (CNSSI 4009-2022)
Pharming
Using technical means to redirect users to a fake website posing as a legitimate one, so they reveal personal information.NIST CSRC Glossary (SP 800-44 v2)
Man-in-the-middle attack
The attacker sits between two communicating parties to intercept and/or alter the data passing between them.NIST CSRC Glossary (SP 1800-21B)
Session hijacking
After a successful authentication, the attacker inserts itself into the session and poses as one party to control the exchanged data.NIST CSRC Glossary (SP 800-63-4)
Section 1.8

A Model for Network Security

Two principals (sender and recipient) cooperate to exchange a message across the Internet. A logical information channel is set up by defining a route and by both using communication protocols such as TCP/IP.

Every technique has two components
  1. A security-related transformation of the information, e.g. encryption that scrambles the message, or adding a code based on its contents to verify the sender.
  2. Secret information shared by the principals and unknown to the opponent, e.g. an encryption key.

A trusted third party may distribute the secret or arbitrate disputes about authenticity.

Four basic tasks in designing a security service
  1. Design an algorithm for the transformation that an opponent cannot defeat.
  2. Generate the secret information for the algorithm.
  3. Develop methods to distribute and share the secret.
  4. Specify a protocol the principals use with the algorithm and secret to achieve the service.

Network access security model (Fig. 1.6)

Some situations don't fit Fig. 1.5: protecting an information system from unwanted access by human opponents (hackers, intruders) or by software (viruses, worms) inserted via disk or, of more concern here, across a network.

Two threats from malicious programs
  • Information access threats: intercept or modify data for users who shouldn't access it.
  • Service threats: exploit service flaws to block use by legitimate users.
Two categories of defense
  • Gatekeeper function: password-based login that denies all but authorized users; screening logic that detects and rejects worms and viruses.
  • Internal controls: once something gets in, monitor activity and analyze stored information to detect intruders.

Section 1.10

Review Questions

The book's review questions. Try each before opening the answer.

1.1What is the OSI security architecture?

ITU-T Recommendation X.800: a systematic way to define security requirements and characterize approaches to satisfying them. It focuses on security attacks, mechanisms and services.

1.2List and briefly define the three key objectives of computer security.

Confidentiality: no unauthorized disclosure (plus privacy). Integrity: no unauthorized modification or destruction of data or system. Availability: timely, reliable access for authorized users.

1.3List and briefly define categories of passive and active security attacks.

Passive: release of message contents (learning what's sent); traffic analysis (learning from the pattern, frequency and length of messages).

Active: masquerade (posing as another entity); replay (capturing and retransmitting data); modification of messages (altering, delaying or reordering); denial of service (preventing normal use or management of facilities).

1.4List and briefly define categories of security services.

Authentication (entity is who it claims); access control (prevents unauthorized resource use); data confidentiality (protects data from disclosure); data integrity (data received exactly as sent); nonrepudiation (no denial of sending or receiving). Plus availability service (accessible on demand).

1.5List and briefly define categories of security mechanisms.

Specific (fit in a protocol layer): encipherment, digital signature, access control, data integrity, authentication exchange, traffic padding, routing control, notarization.

Pervasive (not tied to a layer or service): trusted functionality, security label, event detection, security audit trail, security recovery.

1.6List and briefly define the fundamental security design principles.

Economy of mechanism, fail-safe defaults, complete mediation, open design, separation of privilege, least privilege, least common mechanism, psychological acceptability, isolation, encapsulation, modularity, layering, least astonishment. See the cards in §1.6 for definitions.

1.7Explain the difference between an attack surface and an attack tree.

An attack surface is the set of reachable, exploitable vulnerabilities in a system (network, software, human); it shows where a system can be attacked. An attack tree is a hierarchical structure with the attacker's goal at the root and ways to reach it as AND/OR subgoals and leaves; it shows how a goal can be achieved.

Practice: the chapter's problems (1.1–1.9) include rating CIA impact levels for systems like a cash deposit machine and building an attack tree for opening a physical safe.
