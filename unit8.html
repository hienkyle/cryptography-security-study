Digital Signatures

A MAC protects two parties from outsiders, but not from each other. A digital signature is made with a key only the signer holds and is checked with a public key, so a third party can settle disputes. This chapter covers the properties and requirements of signatures, the attacks they must resist, and five schemes: Elgamal, Schnorr, the NIST Digital Signature Algorithm (DSA), the Elliptic Curve DSA (ECDSA), and RSA-PSS.

13.1Digital Signatures

Every scheme in this chapter has the same shape (Figure 13.1): hash the message, combine the hash with the signer’s private key to get a short signature, and let anyone check it with the signer’s public key.

Private key / public key — the two keys of a public-key pair (Unit 6). The private key PRa is known only to its owner A; the matching public key PUa is published. Deriving the private key from the public key must be computationally infeasible.
Hash value — the fixed-length output h = H(M) of a cryptographic hash function such as SHA-512 (Unit 7). Signing the short hash instead of the whole message keeps the signature short.
Digital signature — a short block computed from the hash of a message and the signer’s private key and attached to the message. A signature generation algorithm produces it; a signature verification algorithm takes the message, the signature and the signer’s public key and returns “valid” or “not valid”.
Redrawn from Figure 13.1, Simplified depiction of essential elements of the digital signature process. Each stage lights up in order.

If the verification algorithm returns “valid”, Alice knows Bob signed the message: no one else holds Bob’s private key, so no one else could make a signature that verifies under Bob’s public key. The message also cannot be altered without that key. The signature therefore authenticates both the source and the data integrity. It does not keep the message secret.

Properties

Message authentication (a MAC with a shared key, Unit 7) protects two parties from a third party, but not from each other. Suppose John sends Mary a MAC-authenticated message:

  • Mary forges. Mary writes a different message and attaches a valid MAC with the shared key, then claims John sent it (e.g. raising the amount in a funds transfer).
  • John denies. Because Mary could have made the MAC, there is no way to prove John sent a message (e.g. stockbroker instructions that turned out badly).

Where sender and receiver do not fully trust each other, a digital signature is needed. It must:

  • verify the author and the date and time of the signature;
  • authenticate the contents at the time of the signature;
  • be verifiable by third parties, to resolve disputes.

So the digital signature function includes the authentication function.

Attacks, Forgeries and Requirements

The attack list says what the attacker may learn; the forgery list says what counts as breaking the scheme. A good scheme resists the strongest attack at the weakest level of success.

A is the user whose signature method is attacked; C is the attacker. Both lists are in order of increasing severity [GOLD88].

Types of attack (what C gets)

  1. Key-only attackC knows only A’s public key.
  2. Known message attackC is given a set of messages and their signatures.
  3. Generic chosen message attackC picks messages before seeing A’s public key and gets A’s signatures on them. The same list works against everyone.
  4. Directed chosen message attackAs above, but the list is chosen after C knows A’s public key (still before seeing any signatures).
  5. Adaptive chosen message attackC uses A as an oracle: each request may depend on signatures already obtained.

Levels of success (what C achieves)

  1. Existential forgeryC forges a signature on at least one message, with no control over which. May be only a minor nuisance.
  2. Selective forgeryC forges a signature on a particular message C chose.
  3. Universal forgeryC finds an efficient signing algorithm that can sign arbitrary messages.
  4. Total breakC determines A’s private key.

Success means C can do the item with non-negligible probability.

Digital signature requirements

  • The signature must be a bit pattern that depends on the message being signed.
  • It must use some information only known to the sender, to prevent both forgery and denial.
  • It must be relatively easy to produce.
  • It must be relatively easy to recognize and verify.
  • It must be computationally infeasible to forge, either by building a new message for an existing signature or by building a fraudulent signature for a given message.
  • It must be practical to retain a copy of the signature in storage.

A secure hash function inside a scheme like Figure 13.1 provides a basis for these requirements, but the details of the scheme must still be designed with care.

Direct Digital Signature

The simplest arrangement: only the two communicating parties are involved. Its weak point is the security of the sender’s private key.

Direct digital signature — a signature scheme that involves only the communicating parties (source and destination). The destination is assumed to know the source’s public key.
Confidentiality function — encryption that hides the message, here the whole message plus signature encrypted with a shared secret key (symmetric encryption).

Order: sign first, then encrypt

Signature inside correct

M→sign (PRa)→M ‖ S→encrypt (K)

The recipient decrypts once and can store the plaintext message with its signature for later disputes. A third party checks the signature without any decryption key.

Signature outside avoid

M→encrypt (K)→sign (PRa)

The signature covers ciphertext, so a third party settling a dispute also needs the decryption key to read the original message.

Threats

  • Claimed key loss. A sender who wants to deny a message can claim the private key was lost or stolen and that someone else forged the signature. Administrative controls weaken this ploy: require a timestamp (date and time) in every signed message and prompt reporting of compromised keys to a central authority.
  • Actual key theft. If X’s private key is stolen at time T, the opponent can sign messages stamped with a time before or equal to T.
Next unitThe universally accepted answer to these threats is digital certificates and certificate authorities (Chapter 14, Unit 9).

13.2Elgamal Digital Signature Scheme

Elgamal and Schnorr are the building blocks of the NIST DSA. Elgamal signs with the private key and verifies with the public key, the reverse of Elgamal encryption (Unit 6). Its security rests on the difficulty of discrete logarithms.

Order of a (mod q) — the least positive exponent m with am ≡ 1 (mod q) (Unit 2).
Primitive root — α is a primitive root of prime q if its order is q − 1, so α, α2, …, αq−1 are distinct (mod q) and give every value 1 to q − 1. The primitive roots of 19 are 2, 3, 10, 13, 14, 15.
Multiplicative inverse — K−1 mod n is the value with K·K−1 ≡ 1 (mod n). It exists only when gcd(K, n) = 1, and the extended Euclidean algorithm finds it (Unit 2).
Discrete logarithm — for b ≡ αi (mod q), the exponent i is dlogα,q(b). Computing αi is easy; recovering i is infeasible for large q.

The scheme needs one number-theory result. If α is a primitive root of q, then:

  1. for any integer m, αm ≡ 1 (mod q) if and only if m ≡ 0 (mod q − 1);
  2. for any integers i, j, αi ≡ αj (mod q) if and only if i ≡ j (mod q − 1).

So exponents are worked mod (q − 1), not mod q.

Global elements and keys

q prime number α primitive root of q XA random, 1 < XA < q − 1 (private) YA = αXA mod q (public: {q, α, YA})

Signing (hash m = H(M), 0 ≤ m ≤ q − 1)

1. random K, 1 ≤ K ≤ q − 1, gcd(K, q − 1) = 1 2. S1 = αK mod q (= C1 of Elgamal encryption) 3. K−1 mod (q − 1) 4. S2 = K−1(m − XAS1) mod (q − 1) 5. signature = (S1, S2)

Verification (any user B)

V1 = αm mod q V2 = (YA)S1(S1)S2 mod q valid if V1 = V2

13.3Schnorr Digital Signature Scheme

Also based on discrete logarithms, but designed so that most of the signing work does not depend on the message and can be done in advance, during the processor’s idle time.

The message-dependent part of signing is only a multiplication of a 2n-bit integer by an n-bit integer. The modulus p is prime and p − 1 has a prime factor q of appropriate size, i.e. p − 1 ≡ 0 (mod q). Typically p ≈ 21024 and q ≈ 2160, the length of a SHA-1 hash.

Key generation

1. primes p, q with q | (p − 1) 2. α with αq = 1 mod p (p, q, α: global public key, common to a group of users) 3. random s, 0 < s < q (private key) 4. v = α−s mod p (public key)

Signing

1. random r, 0 < r < q; x = αr mod p (preprocessing: independent of M) 2. e = H(M ‖ x) 3. y = (r + se) mod q signature = (e, y)

Verification

1. x′ = αyve mod p 2. valid if e = H(M ‖ x′) because x′ ≡ αyve ≡ αyα−se ≡ αy−se ≡ αr ≡ x (mod p), so H(M ‖ x′) = H(M ‖ x)

The step αy−se ≡ αr uses αq = 1 mod p: exponents can be reduced mod q, and y − se ≡ r (mod q).

Here H(M ‖ x) is SHA-256 of the text M followed by the decimal digits of x, reduced mod q so it fits these toy numbers. Real parameters use a full hash and a q of at least 160 bits.

13.4NIST Digital Signature Algorithm

DSA (FIPS 186) is built from the Elgamal and Schnorr ideas. It is a public-key technique that provides only the digital signature function: unlike RSA, it cannot be used for encryption or key exchange.

The DSA uses the Secure Hash Algorithm (SHA). FIPS 186-4 (2013) also includes signature algorithms based on RSA and on elliptic curve cryptography.

The DSA approach compared with RSA (Figure 13.2)

(a) RSA approach

M→H→E(PRa, H(M))→ sendM ‖ signature
H(M)vsD(PUa, signature)→compare

The hash code is encrypted with the sender’s private key. The recipient hashes the message, decrypts the signature with the sender’s public key, and accepts if the two match.

(b) DSA approach

H(M)+k+PRa+PUG→Sig→(s, r)
H(M′), s, r+PUa+PUG→Ver→v = r ?

The hash code goes into a signature function with a random number k made for this signature, the private key and the global public key. The verification function outputs a value equal to r if the signature is valid.

Global public key (PUG) — a set of parameters known to a group of communicating principals and shared by all of them. (They could vary per user as part of each user’s public key, but a separate global public key is more likely in practice.)
Per-message secret number k — a random or pseudorandom integer generated for each signature and kept secret. Because k changes, signing the same message twice gives two different signatures.

The Digital Signature Algorithm

DSA relies on the difficulty of discrete logarithms, and its global public-key components are the same as in the Schnorr scheme.

q divides (p − 1) — written q | (p − 1): (p − 1)/q leaves no remainder (Unit 2).

  • Precomputation. The only demanding signing step, gk mod p, does not depend on the message, so values of r can be computed ahead of time. So can the inverses k−1.

13.5Elliptic Curve Digital Signature Algorithm

ECDSA (in FIPS 186 since 2009) follows the DSA pattern on an elliptic curve group. It is gaining acceptance because elliptic curve cryptography gives comparable security with a smaller key bit length.

Elliptic curve Eq(a, b) — the points (x, y) with y2 = x3 + ax + b over Zq (q prime), plus a point at infinity O (Unit 6). ECDSA uses these prime curves, not binary curves over GF(2m).
Point addition and scalar multiple — points on the curve can be added, with O as the identity. kG means G added to itself k times; computing kG is easy, but recovering k from G and kG is infeasible for large curves.
Order of a point — the smallest positive integer n with nG = O.

The four elements of ECDSA:

  1. All participants use the same global domain parameters, which define a curve and a point of origin (base point) on it.
  2. A signer generates a key pair: a random private number, and the public key, another curve point computed from it and the base point.
  3. A hash of the message, the private key and the domain parameters give a signature of two integers, r and s.
  4. The verifier uses the signer’s public key, the domain parameters and s to compute a value v, and accepts if v = r.

Global domain parameters

q a prime number a, b curve y2 = x3 + ax + b over Zq G base point (xg, yg) on the curve n order of G (smallest n, nG = O); also the number of points on the curve

Key generation (Bob)

1. random d ∈ [1, n − 1] (private key) 2. Q = dG, a point in Eq(a, b) (public key)

Signing message m

1. random k ∈ [1, n − 1] 2. P = (x, y) = kG; r = x mod n if r = 0, go to 1 3. t = k−1 mod n 4. e = H(m) (SHA-2 or SHA-3) 5. s = k−1(e + dr) mod n if s = 0, go to 1 6. signature = (r, s)

Verification (Alice)

1. check r, s are integers in [1, n − 1] 2. e = H(m) 3. w = s−1 mod n 4. u1 = ew, u2 = rw 5. X = (x1, y1) = u1G + u2Q 6. if X = O reject, else v = x1 mod n 7. accept if and only if v = r

Why it works: k = s−1(e + dr) = we + wdr = u1 + u2d (mod n), so u1G + u2Q = u1G + u2dG = (u1 + u2d)G = kG. X is the same point as kG, so its x-coordinate mod n equals r.

13.6RSA-PSS Digital Signature Algorithm

FIPS 186 also includes RSA-based signatures. The RSA Probabilistic Signature Scheme (RSA-PSS) is the newest of them, and the one RSA Laboratories recommends as the most secure.

RSA keys — private key {d, n}, public key {e, n}, where n is the product of two large primes and ed ≡ 1 (mod φ(n)) (Unit 6). Signing raises a value to d; verifying raises it to e.
Octet — an 8-bit byte. RSA-PSS lengths are counted in octets.
Message representative / padding — the block that is actually signed with RSA, formed by embedding the hash value with fixed constants (padding) and other fields.

The three main RSA signature schemes differ mainly in the padding format used to embed the hash into a message representative, and in how verification decides that the hash and the representative are consistent. For the schemes before PSS, no mathematical proof shows the scheme is as secure as the underlying RSA primitive. PSS adds a randomization process that lets its security be shown to be closely related to the security of RSA itself.

Mask generation function (MGF)

Mask generation function — MGF(X, maskLen): a pseudorandom function with input bit string X of any length and output length maskLen octets. An MGF built on a secure hash (e.g. SHA-1) is a secure way to produce a hash of variable length from a hash with fixed-length output.
MGF1, with hash function Hash of output hLen octets input X (octet string to be masked), maskLen T = empty string k = ⌈maskLen/hLen⌉ − 1 for counter = 0 to k C = counter as a 32-bit string T = T ‖ Hash(X ‖ C) output mask = the leading maskLen octets of T

If maskLen = hLen the output is just Hash(X ‖ 0). Otherwise MGF1 keeps appending Hash(X ‖ 1) ‖ Hash(X ‖ 2) ‖ … until T is long enough, then truncates.

Redrawn from Figure 13.6, RSA-PSS encoding.
  • All the RSA-based standard schemes append constants (here padding1 and padding2) while forming the digest. This makes it harder to find another message that maps to the same digest as a given message, or two messages with the same digest.
  • The salt changes with every use, so signing the same message twice with the same private key gives two different signatures, an added measure of security.

Forming the signature

Treat EM as an unsigned nonnegative integer m and compute s = md mod n. Convert s to an octet string S of k octets, where k is the length of n in octets (a 2048-bit key gives k = 2048/8 = 256).

Signature verification

Decryption: treat S as an integer s, compute m = se mod n, and convert m to EM of emLen = ⌈(modBits − 1)/8⌉ octets (modBits = bit length of n). EM verification:

1. mHash = Hash(M) 2. if emLen < hLen + sLen + 2: inconsistent 3. if the rightmost octet of EM ≠ BC: inconsistent 4. maskedDB = leftmost emLen − hLen − 1 octets; H = next hLen octets 5. if the leftmost 8emLen − emBits bits of maskedDB are not all 0: inconsistent 6. dbMask = MGF(H, emLen − hLen − 1) 7. DB = maskedDB ⊕ dbMask 8. set the leftmost 8emLen − emBits bits of DB to 0 9. if the leftmost emLen − hLen − sLen − 1 octets of DB ≠ padding2: inconsistent 10. salt = last sLen octets of DB 11. M′ = padding1 ‖ mHash ‖ salt 12. H′ = Hash(M′) 13. consistent if H = H′, otherwise inconsistent

The verifier does not know the salt and does not compare it. The salt plays the same role as k in DSA and ECDSA: a signer-generated pseudorandom value that makes repeated signatures of one message differ, which the verifier does not need to know.

13.7Review Questions

Review questions 13.1–13.6 from the book. Answer first, then open to check.

13.1 List two disputes that can arise in the context of message authentication.

(1) The receiver forges a different message, attaches a valid authentication code with the shared key, and claims the sender sent it. (2) The sender denies sending a message; since the receiver could have forged it, there is no proof the sender did send it.

13.2 What are the properties a digital signature should have?

It must verify the author and the date and time of the signature; authenticate the contents at the time of the signature; and be verifiable by third parties to resolve disputes.

13.3 What requirements should a digital signature scheme satisfy?

The signature depends on the message; it uses information only the sender knows (preventing forgery and denial); it is relatively easy to produce, and to recognize and verify; it is computationally infeasible to forge, whether by a new message for an existing signature or a fraudulent signature for a given message; and it is practical to keep a copy in storage.

13.4 What is the difference between direct and arbitrated digital signature?

A direct digital signature involves only the source and destination, with the destination knowing the source’s public key; it depends entirely on the security of the sender’s private key. The 7th edition defines only the direct scheme. By contrast, an arbitrated scheme adds a trusted third party (an arbiter) between the two, which checks each signed message, dates it, and vouches for it to the recipient, so disputes can rely on the arbiter rather than only on the sender’s key. The book’s answer to the weaknesses of direct signatures is certificates and certificate authorities (Chapter 14).

13.5 In what order should the signature function and the confidentiality function be applied to a message, and why?

Sign first, then apply the outer confidentiality function (encrypt message plus signature). If the signature were computed on the ciphertext, a third party resolving a dispute would also need the decryption key to read the original message. With the signature inside, the recipient can store the plaintext and its signature for later dispute resolution.

13.6 What are some threats associated with a direct digital signature scheme?

A sender can deny a message by claiming the private key was lost or stolen and the signature forged. And a private key may actually be stolen at time T, letting the opponent sign messages stamped with a time at or before T. Timestamps and prompt reporting of compromised keys weaken these threats; certificates and certificate authorities address them.

  • NIST, “NIST Retires SHA-1 Cryptographic Algorithm” (2022) — reason the RSA-PSS lab defaults to SHA-256.
  • MDN, SubtleCrypto.sign() / RSA-PSS — the browser API used to generate keys and cross-check the RSA-PSS lab.
Content follows W. Stallings, Cryptography and Network Security: Principles and Practice, 7th ed., Global Edition, Chapter 13. The Elgamal, Schnorr, DSA and ECDSA labs use toy-sized numbers so each step can be followed by hand; the RSA-PSS lab uses a real 1024-bit key. Everything runs in your browser; nothing is sent anywhere. Random values come from crypto.getRandomValues and are for study only.
