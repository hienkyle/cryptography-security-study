16.1Network Access Control

Authenticating a user is not enough once devices arrive from anywhere. Network access control also checks the health of the device before deciding what it may reach.

Network access control (NAC) — an umbrella term for managing access to a network: it authenticates users logging in, determines what data they can access and what actions they can perform, and examines the health of the user’s computer or mobile device (the endpoint).

Elements of a NAC system

Access requestor (AR)

The node trying to access the network: any device the NAC system manages (workstations, servers, printers, cameras, other IP-enabled devices). Also called a supplicant or client.

Policy server

Decides what access to grant, from the AR’s posture (its security state) and the enterprise policy. Often relies on backend systems such as antivirus, patch management or a user directory.

Network access server (NAS)

Access control point for remote users connecting to the internal network. Also called a media gateway, remote access server (RAS) or policy server. May authenticate itself or rely on a separate authentication service.

The first step is to authenticate the AR, usually with a secure protocol and cryptographic keys. The NAS may authenticate it directly, or mediate between the supplicant and an authentication server that is part of, or reached by, the policy server. Authentication verifies the claimed identity (so the policy server can set privileges) and may establish session keys for later secure communication with enterprise resources.

Next come health checks (also called suitability, screening or assessment checks): software on the user’s system verifies compliance with the organization’s secure configuration baseline, for example up-to-date antimalware, a fully patched OS, and a computer owned and controlled by the organization. These checks should run before the AR is admitted.

Quarantine network — a restricted part of the enterprise network holding the policy server and related AR suitability servers (and perhaps application servers that do not require the normal security threshold), where a device that fails its health check can be fixed by authorized personnel.

Once an AR is authenticated and cleared for some level of access, the NAS lets it interact with enterprise resources. The NAS may mediate every exchange to enforce the policy, or use other methods to limit the AR’s privileges.

Network access enforcement methods

Enforcement methods are the actions applied to ARs to regulate access. Vendors often support several at once.

Local area network (LAN) — a network of devices sharing a transmission medium over a small area (a building, a campus). Virtual LAN (VLAN) — a logical subgroup within a LAN created in software rather than by moving cables; it groups stations and devices regardless of their physical segment. VLANs are implemented in port-switching hubs and LAN switches.
IP address — the network-layer address that identifies a host on an IP network. Dynamic Host Configuration Protocol (DHCP) — an Internet protocol that dynamically allocates IP addresses to hosts.

16.2Extensible Authentication Protocol

EAP is a framework, not one authentication method: it carries whichever method both ends support, over whatever link is in use.

Extensible Authentication Protocol (EAP) — defined in RFC 3748; a framework for network access and authentication protocols. It provides a set of protocol messages that encapsulate various authentication methods between a client and an authentication server, and runs over point-to-point links, LANs and other networks.
EAP method — a specific authentication protocol installed in both the EAP client and the authentication server that extends EAP’s generic transport service. Supporting many methods is what makes EAP “extensible”.
Redrawn from Figure 16.2, EAP layered context.
Transport Layer Security (TLS) (Unit 11) — the protocol that sets up an authenticated, encrypted channel; its handshake protocol authenticates the parties and agrees keys.
Pre-shared key (PSK) — a secret key placed with both parties in advance, outside the protocol.

Common EAP methods

EAP-TLS RFC 5216

Encapsulates the TLS handshake (not TLS encryption) in EAP messages. Client and server authenticate each other with digital certificates. The client encrypts a random number with the server’s public key to make a pre-master secret and sends it; both sides derive the same secret key from it.

EAP-TTLS RFC 5281

Tunneled TLS: only the server has a certificate and authenticates first. The secure connection (the “tunnel”) is then used to authenticate the client, and possibly the server again, with any EAP method or a legacy method such as PAP or CHAP.

EAP-GPSK RFC 5433

Generalized Pre-Shared Key: mutual authentication and session key derivation from a PSK, using only secret-key algorithms, so cheap in messages and computation (minimum four messages, no public-key cryptography). Needs a PSK between each peer and the EAP server, set up at peer registration. Designed for insecure networks such as IEEE 802.11.

EAP-IKEv2 RFC 5106

Based on Internet Key Exchange version 2 (Unit 11, Chapter 20). Mutual authentication and session key establishment by a variety of methods.

PAP (Password Authentication Protocol) and CHAP (Challenge-Handshake Authentication Protocol) — older authentication methods used with point-to-point links; PAP sends a password, CHAP answers a challenge with a value computed from a shared secret.
CorrectionThe book’s EAP-IKEv2 bullet says “EAP-TLS is defined in RFC 5106”; RFC 5106 defines EAP-IKEv2. EAP-TLS for TLS 1.3 is now specified in RFC 9190.

EAP exchanges

RFC 3748 defines successful authentication as an exchange of EAP messages after which the authenticator decides to allow access by the peer and the peer decides to use this access. The authenticator’s decision covers authentication and authorization: a peer may authenticate successfully yet be refused for policy reasons.

EAP peer — the client computer trying to access a network. EAP authenticator — an access point or NAS that requires EAP authentication before granting access. Authentication server — negotiates the EAP method with the peer, validates its credentials and authorizes access; typically a RADIUS (Remote Authentication Dial-In User Service) server.
EAP pass-through mode — the usual arrangement: the authentication server acts as a backend for many authenticators, and the authenticator then decides whether to grant access. Less commonly the authenticator itself is the EAP server, so only two parties are involved.

A lower-level protocol such as PPP (point-to-point protocol) or IEEE 802.1X first connects the peer to the authenticator; the software entity in the peer at this level is the supplicant.

EAP message fields

  • Code: the type of message. Request (1), Response (2), Success (3), Failure (4).
  • Identifier: matches Responses with Requests.
  • Length: length in octets of the whole message, including Code, Identifier, Length and Data.
  • Data: authentication information, typically a Type subfield (kind of data carried) and a Type-Data field. Success and Failure messages have no Data field.
Lab · Build an EAP packetRFC 3748 §4

Byte layout from RFC 3748: Code and Identifier are one octet each, Length is two octets (big-endian), Type is one octet. Type numbers from the IANA EAP registry. An Identity response carries the claimed identity as text.

16.3IEEE 802.1X Port-Based Network Access Control

802.1X turns a LAN port into a gate: until authentication succeeds, only authentication traffic gets through.

Protocol data unit (PDU) — the block of data a protocol layer exchanges as one unit. MAC address — the physical (link-layer) address of a LAN interface. Bridge — a link-layer device joining LAN segments; its connection points are bridge ports.
Term (Table 16.1)Meaning
SupplicantEntity at one end of a point-to-point LAN segment that seeks to be authenticated by an authenticator at the other end.
AuthenticatorEntity at one end of a point-to-point LAN segment that facilitates authentication of the entity at the other end.
Authentication server (AS)Provides an authentication service to an authenticator: decides from the supplicant’s credentials whether it may use the services of the authenticator’s system.
Authentication exchangeThe two-party conversation between systems performing an authentication process.
Authentication processThe cryptographic operations and supporting data frames that perform the actual authentication.
Authentication transportThe datagram session that transfers the authentication exchange between two systems.
Bridge port / edge portA port of an IEEE 802.1D or 802.1Q bridge / a bridge port on a LAN with no other bridges attached.
Network access portA point of attachment to a LAN: physical (one LAN MAC on a segment) or logical (an IEEE 802.11 association between a station and an access point).
Port access entity (PAE)The protocol entity associated with a port; can act as authenticator, supplicant or both.

Supplicant, network access point and authentication server correspond to the EAP terms peer, authenticator and authentication server. Until the AS authenticates the supplicant, the authenticator passes only control and authentication messages: the 802.1X control channel is unblocked but the data channel is blocked. Once the supplicant is authenticated and keys are provided, data is forwarded, subject to the supplicant’s access limits.

Uncontrolled port — lets PDUs pass between supplicant and AS regardless of the supplicant’s authentication state. Controlled port — lets PDUs pass between the supplicant and other systems only if the supplicant’s current state authorizes it. Ports are logical entities in the authenticator, each mapped to a physical connection.

EAPOL (EAP over LAN) — the essential protocol defined in 802.1X. It runs over an IEEE 802 LAN (Ethernet, Wi-Fi) at the link level, lets a supplicant talk to an authenticator, and carries EAP packets for authentication.
Frame type (Table 16.2)Definition
EAPOL-EAPContains an encapsulated EAP packet.
EAPOL-StartThe supplicant can send this instead of waiting for a challenge from the authenticator.
EAPOL-LogoffReturns the port to unauthorized when the supplicant has finished using the network.

On first connecting, the supplicant does not know the authenticator’s MAC address, or whether one exists. It sends EAPOL-Start to a special group-multicast address reserved for 802.1X authenticators. Often the authenticator already knows a device connected (a hub sees the cable plugged in) and preempts Start with its own message. Either way, it sends an EAP-Request/Identity inside an EAPOL-EAP packet.

EAPOL packet fields: protocol version; packet type (start, EAP, key, logoff…); packet body length; packet body (e.g. an EAP packet).

16.4Cloud Computing

Many organizations move much or all of their IT operations to Internet-connected infrastructure. The security questions that follow depend on which parts the provider runs.

Cloud computing (NIST SP 800-145) — a model for enabling ubiquitous, convenient, on-demand network access to a shared pool of configurable computing resources (networks, servers, storage, applications, services) that can be rapidly provisioned and released with minimal management effort or service provider interaction. It has five essential characteristics, three service models and four deployment models.
Multi-tenant model — one provider’s resources serve multiple consumers (tenants) at once, with resources assigned and reassigned dynamically. Virtual machine — a software-emulated computer running alongside others on shared physical hardware.

Five essential characteristics

  • Broad network access: capabilities are available over the network through standard mechanisms used by heterogeneous thin or thick clients (phones, laptops, PDAs) and other software services.
  • Rapid elasticity: resources expand and shrink with the requirement, e.g. many servers for one task, released when it finishes.
  • Measured service: a metering capability (storage, processing, bandwidth, active accounts) controls and optimizes use; usage is monitored, controlled and reported for both provider and consumer.
  • On-demand self-service: a consumer provisions capabilities (server time, storage) automatically, without human interaction with the provider. Resources are not permanent parts of your IT infrastructure.
  • Resource pooling: resources are pooled to serve many consumers with a multi-tenant model. Location independence: the customer generally cannot control or know the exact location but may specify country, state or data center. Even private clouds pool resources between parts of one organization.

Three service models

16.6Data Protection in the Cloud

For many clients the worst outcome of a breach is losing or leaking data, and the cloud multiplies the ways data can be compromised.

Ways to compromise data: deleting or altering records with no backup; unlinking a record from its larger context; storage on unreliable media; losing an encoding key (effective destruction); and access by unauthorized parties.

Database models

Database management system (DBMS) — software that stores a database and handles queries, users and access rights. Multi-instance model — each subscriber gets its own DBMS on its own virtual machine instance, with complete control over roles, user authorization and other security administration. Multi-tenant model (for databases) — a predefined environment shared with other tenants, typically by tagging data with a subscriber identifier; it looks exclusive but relies on the CP to maintain a sound, secure database environment.

Data must be secured at rest, in transit and in use, and access controlled. Encryption in transit involves key management responsibilities for the CP; access control involves the CP to a degree depending on the service model. For data at rest, the ideal is for the client to encrypt the database and store only ciphertext, with the CP having no key: then the CP cannot read the data, though corruption and denial of service remain risks.

Encrypting the whole database is inflexible: the user would download and decrypt entire tables to search them. It must be possible to work with the database in encrypted form.

An encryption scheme for a cloud-based database

Relation — the basic building block of a relational database: a flat table. Rows are tuples; columns are attributes. Primary key — one or more columns whose value uniquely identifies a row (e.g. employee ID). A primary key is a means of indexing, unrelated to cryptographic keys.
  • Data owner: produces data for controlled release, inside or outside the organization.
  • User: a human who presents queries (an employee, or an authenticated external user).
  • Client: front end that transforms user queries into queries on the encrypted data.
  • Server: receives encrypted data from the owner and makes it available to clients; here, a cloud server, usually run by an external provider.

Simplest arrangement: every item is encrypted separately with the same key; the server stores the encrypted database without the key, the client holds a copy of the key.

Lab · Querying an encrypted tableFigure 16.10

Real AES-128 through your browser’s Web Crypto API. Each item is encrypted on its own with one shared key and a fixed IV (AES-CBC), so equal values give equal ciphertexts and the server can match an encrypted primary key. That same determinism is what the scheme relies on; ciphertexts keep no ordering, so a range query on salary has no server-side answer.

Extensions exist: e.g. associate an unencrypted index value with an attribute and partition the table on it, so a user can retrieve a portion of the table. The details are beyond the chapter.

Security functions themselves can be bought from the cloud, shifting work from the enterprise to a security service provider.

Security as a Service (SecaaS) — a package of security services (authentication, antivirus, antimalware/spyware, intrusion detection, security event management) offered by a service provider. In cloud computing, a segment of a CP’s SaaS offering. Cloud Security Alliance: provision of security applications and services via the cloud, to cloud-based infrastructure and software or from the cloud to customers’ on-premise systems.
Intrusion detection system (IDS) — automated tools that detect unauthorized access to a host. Intrusion prevention system (IPS) — IDS functions plus mechanisms that block intruders’ traffic. Virtual private network (VPN) — an encrypted tunnel that makes traffic over a public network behave like a private link.

18.1Wireless Security

Wireless networks carry every risk of wired ones plus their own: anyone in radio range can listen, and the devices are small, mobile and often unattended.

Why wireless is riskier

  • Channel: broadcast communication is far more open to eavesdropping and jamming, and to active attacks on protocol weaknesses.
  • Mobility: wireless devices are far more portable than wired ones, which brings its own risks.
  • Resources: smartphones and tablets run sophisticated operating systems on limited memory and processing, with less to spend against threats such as denial of service and malware.
  • Accessibility: sensors and robots may be left unattended in remote or hostile places, open to physical attack.
Redrawn from Figure 18.1, Wireless networking components.

The wireless client (cell phone, Wi-Fi laptop or tablet, sensor, Bluetooth device), the wireless access point (cell tower, Wi-Fi hotspot, access point to a wired LAN or WAN) and the transmission medium carrying the radio waves are all points of attack.

Wireless network threats

Bluetooth — a short-range radio standard for personal-area devices. Denial of service (DoS) — preventing or inhibiting normal use of a facility, e.g. by overloading it.
ThreatWhat happens
Accidental associationOverlapping ranges of nearby networks: a user meaning to join one LAN locks onto a neighbor’s access point, exposing that LAN’s resources.
Malicious associationA wireless device poses as a legitimate access point, steals users’ passwords, then penetrates the wired network through a legitimate access point.
Ad hoc networksPeer-to-peer networks between wireless computers with no access point, so no central point of control.
Nontraditional networksBluetooth personal devices, barcode readers, handheld PDAs: eavesdropping and spoofing risks.
Identity theft (MAC spoofing)An eavesdropper learns the MAC address of a computer with network privileges.
Man-in-the-middleUser and access point believe they talk directly while traffic passes through an attacking device (Unit 6, Diffie–Hellman). Wireless networks are particularly vulnerable.
Denial of serviceThe attacker keeps bombarding an access point or other wireless port with protocol messages that consume resources; easy because many messages are easy to direct at a target.
Network injectionTargets access points exposed to nonfiltered traffic such as routing or network management messages, e.g. bogus reconfiguration commands that degrade routers and switches.

Wireless security measures

Service set identifier (SSID) — the name of a wireless LAN, broadcast by access points so devices can find it.

Securing transmissions

Threats: eavesdropping, altering or inserting messages, disruption. Against eavesdropping: signal hiding (turn off SSID broadcasting, cryptic SSIDs, lowest workable signal strength, access points inside the building away from windows and outer walls, directional antennas, shielding) and encryption (effective as long as keys are secure). Encryption and authentication protocols counter altering and inserting. Against unintentional DoS: site surveys for devices on the same frequencies, adjusted signal strength, shielding.

Securing access points

Main threat: unauthorized access to the network. Principal defense: IEEE 802.1X port-based access control (16.3), which authenticates devices before they attach and stops rogue access points and other unauthorized devices becoming insecure backdoors.

Securing networks

(1) Use encryption. (2) Antivirus, antispyware and a firewall on every endpoint. (3) Turn off identifier broadcasting. (4) Change the router’s identifier from the default. (5) Change the router’s pre-set administration password. (6) Allow only specific MAC addresses (spoofable, so only one element of a strategy).

18.2Mobile Device Security

The old model of IT-controlled PCs behind a clear perimeter no longer holds. The mobile device is now central to the network, and security policy has to follow it.

  • Growing use of new devices: employees use a combination of endpoint devices day to day.
  • Cloud-based applications: applications run anywhere (physical servers, mobile virtual servers, the cloud), and users rely on cloud services for personal and professional use.
  • De-perimeterization: instead of one static perimeter there are many dynamic perimeters around devices, applications, users and data, adapting to user role, device type, server virtualization mobility, network location and time of day.
  • External business requirements: guests, contractors and partners need access from many devices and locations.

An organization implements policy through security features built into the devices plus controls in network components that regulate their use.

Seven security concerns, and responses

QR (Quick Response) code — a two-dimensional barcode read by a device camera; it translates to a URL. Sandbox — an isolated environment that keeps an application’s data and code apart from everything else on the device. Whitelisting — allowing only items on an approved list.

Mobile device security strategy

Device security

Organization-issued or BYOD (bring-your-own-device) devices should be inspected before network access; no “rooted” or “jail-broken” devices; no corporate contacts on local storage. Controls: auto-lock; PIN or password protection (can also encrypt email and data); no auto-complete of user names or passwords; remote wipe; SSL enabled; software up to date; antivirus; sensitive data prohibited or encrypted; IT can remotely access, wipe and disable a lost device; app restrictions (signed apps with a certificate from an approved authority); restrictions on synchronization and cloud storage; training and disabling cameras against untrusted content; location services disabled.

Traffic security

Usual encryption and authentication: all traffic encrypted and carried by secure means such as SSL or IPv6; a VPN can carry all traffic between device and organization. Use a strong authentication protocol and preferably two layers: authenticate the device, then the user.

Barrier security

Protect the network from unauthorized access with firewall policies specific to mobile traffic, limiting the scope of data and application access, and intrusion detection and prevention systems with tighter rules for mobile traffic.

18.3IEEE 802.11 Wireless LAN Overview

802.11i security sits inside the 802.11 architecture, so its terms (stations, BSSs, MPDUs, association) come first.

IEEE 802 — the committee that develops LAN standards. IEEE 802.11 — its working group for wireless LAN (WLAN) protocols and transmission specifications. Wi-Fi — the term for products certified interoperable by the Wi-Fi Alliance (first for 802.11b, extended to 802.11g; 802.11a certification is called Wi-Fi5). The Alliance also certifies security: Wi-Fi Protected Access (WPA); its version WPA2 includes all features of IEEE 802.11i.

IEEE 802 protocol architecture

  • Physical layer: encoding/decoding of signals, bit transmission/reception, the transmission medium; for 802.11 also frequency bands and antenna characteristics.
  • Media access control (MAC): controls access to the shared medium. Receives an MSDU from the layer above (typically LLC); on transmission assembles a frame (an MPDU) with address and error-detection fields; on reception disassembles, recognizes addresses and detects errors; governs access to the medium.
  • Logical link control (LLC): the MAC layer detects errors and discards bad frames; LLC optionally tracks which frames arrived and retransmits unsuccessful ones.
Cyclic redundancy check (CRC) — an error-detecting code computed over the bits of the whole MPDU, also called the Frame Check Sequence (FCS). The sender appends it; the receiver recomputes and compares, and a mismatch means bits changed in transit. It detects errors, not deliberate tampering.

MAC header: MAC Control, destination and source addresses; MAC trailer: CRC. Stand-in code: CRC-32, the polynomial used for IEEE 802 frame check sequences; MAC Control is shown as two zero bytes.

Network components and architectural model

The smallest building block is a BSS: wireless stations running the same MAC protocol and competing for the same shared medium. A BSS may be isolated or connect to a backbone DS through an AP, which acts as a bridge and relay point. Stations in a BSS do not talk directly: a frame goes from the station to the AP, then to the destination (or over the DS to a remote station). A BSS corresponds to a cell; the DS can be a switch, a wired network or a wireless network.

Independent BSS (IBSS) — a BSS whose stations are all mobile and communicate directly with no AP; typically an ad hoc network.

BSSs may overlap, and the association between a station and a BSS is dynamic. An ESS is two or more BSSs joined by a DS, appearing as a single logical LAN to the LLC level.

Station services are in every station, APs included; distribution services are provided between BSSs, in an AP or a special device on the DS. Three services control LAN access and confidentiality; six support MSDU delivery. An MSDU too large for one MPDU may be fragmented into several MPDUs.

  • Distribution: the primary service for exchanging MPDUs that must cross the DS from one BSS to another (STA 2 → AP 1 → DS → AP 2 → STA 7). Within one BSS it logically goes through that BSS’s single AP.
  • Integration: transfers data between a station on an 802.11 LAN and one on an integrated IEEE 802.x LAN (a wired LAN physically connected to the DS), handling address translation and media conversion.

Mobility and association

Before the distribution service can deliver to or accept from a station, the station must be associated. Three transition types, by mobility:

No transition

Stationary, or moving only within direct range of one BSS’s stations.

BSS transition

From one BSS to another within the same ESS; addressing must recognize the station’s new location.

ESS transition

From a BSS in one ESS to a BSS in another; supported only in that the station can move. Upper-layer connections cannot be guaranteed; disruption is likely.

To deliver within a DS, the distribution service must know which AP to send to, so a station keeps an association with the AP of its current BSS:

  • Association: establishes the initial station–AP association, making the station’s identity and address known; the AP can share this with other APs in the ESS for routing.
  • Reassociation: transfers an established association to another AP, letting a station move between BSSs.
  • Disassociation: notification by station or AP that an association has ended; a station should send it before leaving an ESS or shutting down, but MAC management also copes with stations that vanish.

18.4IEEE 802.11i Wireless LAN Security

A wired LAN gives a crude form of authentication and privacy for free: you must plug in to send or receive. A wireless LAN gives neither, since any station in radio range can transmit and receive.

Wired Equivalent Privacy (WEP) — the original 802.11 privacy algorithm, with major weaknesses. Robust Security Network (RSN) — the final form of the 802.11i standard. WPA was a set of mechanisms based on an interim state of 802.11i; WPA2 certifies the full 802.11i specification.

802.11i services

  • Authentication: a protocol defines an exchange between a user and an AS that provides mutual authentication and generates temporary keys for use between the client and the AP over the wireless link.
  • Access control: enforces use of the authentication function, routes messages properly and facilitates key exchange; works with a variety of authentication protocols. (Access control as a security function, not media access control.)
  • Privacy with message integrity: MAC-level data (e.g. an LLC PDU) are encrypted along with a message integrity code that ensures they were not altered.
Message integrity code (MIC) — 802.11i’s name for a message authentication code (Unit 7), because MAC already means media access control in networking.

802.11i protects only the link between a STA and its AP. (1) Two STAs in one BSS via the AP: each secures its link to the AP. (2) STAs in an ad hoc IBSS: the AP function lives in a STA. (3) STAs in different BSSs: protected only within each BSS, not across the DS. (4) STA to a wired end station: only STA to AP. End-to-end security must come from a higher layer.

Five phases of operation

Redrawn from Figure 18.7, IEEE 802.11i phases of operation.
  1. Discovery: the AP advertises its 802.11i security policy in Beacons and Probe Responses; the STA identifies an AP, associates, and selects the cipher suite and authentication mechanism when there is a choice.
  2. Authentication: STA and AS prove their identities to each other. The AP blocks non-authentication traffic until success and only forwards traffic between STA and AS.
  3. Key generation and distribution: AP and STA generate cryptographic keys and place them on both; frames pass between AP and STA only.
  4. Protected data transfer: frames go between STA and end station through the AP; protection covers STA to AP only.
  5. Connection termination: AP and STA exchange frames; the secure connection is torn down and restored to its original state.

Discovery and Authentication Phases

Discovery agrees what protection to use; authentication proves both sides are genuine before any key exists.

Security capabilities

The STA and AP decide: confidentiality and MPDU integrity protocols for unicast traffic (between this STA and AP only); the authentication method; the key management approach. Protocols for multicast/broadcast traffic are dictated by the AP, since all STAs in a group must use the same ones.

Cipher suite — the specification of a protocol plus its chosen key length (if variable). Confidentiality and integrity options: WEP (40- or 104-bit key, for backward compatibility), TKIP, CCMP, vendor-specific. Authentication and key management (AKM) suite — how AP and STA mutually authenticate and derive a root key. Options: IEEE 802.1X; pre-shared key (no explicit authentication; mutual authentication implied by sharing a unique secret); vendor-specific.
RSN Information Element (RSN IE) — the field in which an AP advertises its security capabilities.

The discovery phase has three exchanges, and the 802.1X controlled ports stay blocked throughout: no user traffic goes beyond the AP.

IEEE 802.1X access control approach

802.11i uses 802.1X, with EAP as the authentication protocol. Supplicant and authenticator correspond to the wireless station and the AP; the AS is typically a separate device on the wired side (reached over the DS) but could sit on the authenticator. Before the AS authenticates the supplicant, the AP passes only control or authentication messages; afterwards, with keys provided, the data channel is unblocked. An AP may have just two physical ports, one to the DS and one for wireless communication in its BSS, with each logical port mapped to one of them. For an IBSS, with no AP, 802.11i uses pairwise authentication between stations.

MPDU exchange

  • Connect to AS: the STA asks its AP for a connection to the AS; the AP acknowledges and sends an access request to the AS.
  • EAP exchange: authenticates STA and AS to each other.
  • Secure key delivery: the AS generates a master session key (MSK), also called the AAA key (Authentication, Authorization and Accounting), and sends it to the STA. All keys the STA needs with its AP come from it. 802.11i relies on EAP for secure delivery.

The controlled port is still blocked to general user traffic until the temporal keys are installed in the 4-way handshake.

Key Management Phase

One master secret per STA–AP pair is expanded into short-lived keys with separate jobs, so the master key itself never protects traffic.

Pairwise keys protect communication between a pair of devices (usually STA and AP); group keys protect multicast. Each STA holds one set of pairwise keys; the AP holds one set per STA.

Pairwise keys

  • Top of the hierarchy: a pre-shared key (PSK) installed outside 802.11i, or the MSK (AAAK) generated by 802.1X during authentication (method-dependent). Either way it is unique to one AP–STA pair.
  • Pairwise master key (PMK): the PSK itself, or the MSK truncated if necessary. Both sides have it by the 802.1X EAP Success message.
  • Pairwise transient key (PTK): HMAC-SHA-1 applied to the PMK, both MAC addresses and nonces. Addresses protect against session hijacking and impersonation; nonces add random keying material.
  • PTK parts: EAPOL-KCK (key confirmation key) gives integrity and data origin authenticity of STA-to-AP control frames during setup, and proves possession of the PMK (an access control function); EAPOL-KEK (key encryption key) protects confidentiality of keys and other data during association procedures; TK (temporal key) protects user traffic.

Group keys

The group master key (GMK) is a key-generating key used to derive the group temporal key (GTK). Unlike the PTK, the GTK is generated by the AP alone (method undefined, but it must be computationally indistinguishable from random), sent to its STAs under the pairwise keys, and changed every time a device leaves the network.

4-way handshake and group key handshake

Nonce (Unit 9) — a value used once. Here ANonce is the AP’s nonce and SNonce the STA’s.

The handshake confirms both sides hold the PMK, verifies the cipher suite selection, and derives a fresh PTK for the coming session.

Protected Data Transfer and the PRF

Two schemes protect data MPDUs, one built to run on old WEP hardware and one for newer hardware. A single pseudorandom function supplies their keys and nonces.

TKIP · Temporal Key Integrity Protocol

Requires only software changes to WEP devices. Message integrity: a MIC after the data field, computed by Michael into 64 bits from the source and destination MAC addresses, the Data field and key material. Confidentiality: MPDU plus MIC encrypted with RC4 (Unit 5). The 256-bit TK splits into two 64-bit Michael keys (STA→AP and AP→STA) and 128 bits for the RC4 key. A monotonically increasing TKIP sequence counter (TSC) in each MPDU, protected by the MIC, defeats replay; combined with the TK it gives a per-MPDU encryption key.

CCMP · Counter Mode-CBC MAC Protocol

For newer devices with hardware support. Message integrity: CBC-MAC (Unit 7). Confidentiality: AES in CTR mode (Unit 5). The same 128-bit AES key serves both. A 48-bit packet number builds a nonce that prevents replay.

Beyond the bookThe Wi-Fi Alliance began deprecating TKIP in 2015, and WPA3 no longer supports WPA-TKIP.

The 802.11i pseudorandom function

A PRF generates nonces, expands pairwise keys and generates the GTK. Good practice is separate streams for separate purposes, but for efficiency one function serves all, distinguished by a purpose string. It is built on HMAC-SHA-1 (Unit 7): a 160-bit output where changing one input bit gives an unrelated hash.

Review Questions

Review questions 16.1–16.9 and 18.1–18.8 from the book. Answer first, then open to check.

Chapter 16

16.1 Provide a brief definition of network access control.

An umbrella term for managing access to a network: NAC authenticates users logging in, determines what data they can access and what actions they can perform, and examines the health of their endpoints (computers or mobile devices).

16.2 What is an EAP?

The Extensible Authentication Protocol (RFC 3748): a framework for network access and authentication that provides protocol messages encapsulating various authentication methods between a client and an authentication server. It runs over many link types (point-to-point, LANs and others) and is extended by methods installed in both the client and the server.

16.3 List and briefly define four EAP authentication methods.

EAP-TLS: TLS handshake in EAP; client and server authenticate each other with certificates and derive a key from a pre-master secret. EAP-TTLS: only the server has a certificate; the TLS tunnel then carries client authentication by any EAP or legacy method (PAP, CHAP). EAP-GPSK: mutual authentication and session key derivation from a pre-shared key using only secret-key algorithms. EAP-IKEv2: mutual authentication and session key establishment based on IKEv2.

16.4 What is DHCP? How useful is it to help achieve security of IP addresses?

The Dynamic Host Configuration Protocol dynamically allocates IP addresses to hosts. As a NAC method, a DHCP server intercepts DHCP requests and assigns addresses, enforcing access at the IP layer by subnet and address assignment. It is easy to install and configure but subject to various forms of IP spoofing, so it provides only limited security.

16.5 Why is EAPOL an essential element of IEEE 802.1X?

EAPOL is the protocol that lets a supplicant communicate with an authenticator over an IEEE 802 LAN and carries the EAP packets used for authentication. Its frames start the exchange (EAPOL-Start), carry EAP (EAPOL-EAP), deliver keys (EAPOL-Key) and end the session (EAPOL-Logoff), all over the uncontrolled port before the supplicant has any other access.

16.6 What are the essential characteristics of cloud computing?

Broad network access, rapid elasticity, measured service, on-demand self-service and resource pooling.

16.7 List and briefly define the deployment models of cloud computing.

Public: available to the public or a large industry group, owned by a cloud seller responsible for infrastructure and control. Private: operated solely for one organization, on or off premise; the provider handles only infrastructure. Community: shared by several organizations with shared concerns. Hybrid: two or more clouds kept distinct but bound by technology for data and application portability.

16.8 What is the cloud computing reference architecture?

NIST SP 500-292: a model of what cloud services provide (not how to build them), used to describe, discuss and develop system-specific architectures with a common frame of reference. It defines five actors: cloud consumer, cloud provider, cloud auditor, cloud broker and cloud carrier, with the provider’s service orchestration (SaaS/PaaS/IaaS, resource abstraction, physical resources), service management, security and privacy.

16.9 Describe some of the main cloud-specific security threats.

Abuse and nefarious use (easy registration lets attackers spam, spread malware, launch DoS); insecure interfaces and APIs; malicious insiders at the provider; shared technology issues (components not designed for strong multi-tenant isolation); data loss or leakage; account or service hijacking with stolen credentials; and an unknown risk profile, since the client cedes control to the provider.

Chapter 18

18.1 What is the basic building block of an 802.11 WLAN?

The basic service set (BSS): wireless stations executing the same MAC protocol and competing for the same shared medium, possibly connected to a distribution system through an access point.

18.2 List and briefly define threats to a wireless network.

Accidental association (locking onto a neighbor’s access point); malicious association (a fake access point steals passwords); ad hoc networks (no central control); nontraditional networks (Bluetooth, barcode readers, PDAs: eavesdropping and spoofing); identity theft by MAC spoofing; man-in-the-middle; denial of service by bombarding access points; network injection of bogus routing or management messages.

18.3 List and briefly define IEEE 802.11 services.

Association: initial station–AP association. Reassociation: moving it to another AP. Disassociation: ending it. Authentication and deauthentication: establishing and ending a station’s identity for LAN access. Privacy: protecting message contents. Distribution: moving MPDUs across the DS between BSSs. Integration: transfer between an 802.11 station and one on an integrated 802.x LAN. MSDU delivery: the basic delivery of data.

18.4 List some security threats related to mobile devices.

Lack of physical security controls (theft, tampering); use of untrusted mobile devices; use of untrusted networks; applications created by unknown parties; interaction with other systems (synchronization, cloud storage); untrusted content such as malicious QR codes; and location services revealing where the device and user are.

18.5 How is the concept of an association related to that of mobility?

The DS must know which AP currently serves a destination station. Association records a station with the AP of its current BSS. With no transition nothing changes; for a BSS transition within an ESS, reassociation moves the association to the new AP so delivery continues; an ESS transition is supported only in that the station can move, and connections are likely disrupted.

18.6 What security areas are addressed by IEEE 802.11i?

Authentication (mutual, between user and AS, generating temporary keys), access control (enforcing authentication, routing messages, facilitating key exchange) and privacy with message integrity (encrypting MAC-level data with a message integrity code).

18.7 Briefly describe the five IEEE 802.11i phases of operation.

Discovery: the AP advertises its policy; the STA associates and selects cipher and authentication suites. Authentication: STA and AS prove identities while the AP forwards only authentication traffic. Key generation and distribution: AP and STA generate and install keys. Protected data transfer: frames between STA and end station through the AP, protected STA–AP only. Connection termination: the secure connection is torn down.

18.8 What is the difference between TKIP and CCMP?

TKIP needs only software changes to WEP devices: Michael MIC for integrity and RC4 for confidentiality, with a TSC against replay. CCMP is for newer hardware: AES-CBC-MAC for integrity and AES-CTR for confidentiality, one 128-bit key, a 48-bit packet number for replay protection.
