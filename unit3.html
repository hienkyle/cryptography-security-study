Classical Ciphers & DES

Chapter 3 builds the vocabulary of symmetric encryption and the two building blocks of every cipher, substitution and transposition, using pre-computer ciphers and the attacks that break them. Chapter 4 combines those blocks into the Feistel structure and the Data Encryption Standard (DES).

3.1Symmetric Cipher Model

Symmetric (also called conventional or single-key) encryption: sender and receiver use the same key. It is by far the more widely used of the two types of encryption.

Basic terms

Plaintext — the original message.
Ciphertext — the coded message.
Encryption (enciphering) — plaintext → ciphertext.
Decryption (deciphering) — ciphertext → plaintext.
Cryptography — the study of encryption schemes.
One such scheme is a cipher (cryptographic system).
Cryptanalysis — deciphering a message without knowing the enciphering details (“breaking the code”).
Cryptology = cryptography + cryptanalysis.

The five ingredients (Figure 3.1)

Redrawn from Figures 3.1–3.2. Decryption is essentially encryption run in reverse.
  1. Plaintext — intelligible input data.
  2. Encryption algorithm — performs substitutions and transformations on the plaintext.
  3. Secret key — a value independent of plaintext and algorithm; the exact substitutions and transformations depend on it.
  4. Ciphertext — the scrambled output; depends on plaintext and key (two keys → two different ciphertexts).
  5. Decryption algorithm — takes ciphertext and key, returns plaintext.

Two requirements for secure use

  1. A strong algorithm: an opponent who knows the algorithm and holds many ciphertexts — even with their plaintexts — still cannot decrypt or find the key.
  2. Sender and receiver obtain the key securely and keep it secret.
Only the key is secret. The algorithm is assumed known. That is what allows cheap, widely available hardware implementations — and it makes key secrecy the principal security problem.

Three ways to classify a cryptographic system

1 · Type of operation

Substitution: each element is mapped to another element. Transposition: elements are rearranged. No information may be lost (all operations reversible). Product systems use multiple stages of both.

2 · Number of keys

Same key both sides → symmetric (single-key, secret-key, conventional). Different keys → asymmetric (two-key, public-key).

3 · How plaintext is processed

Block cipher: one block in, one block out. Stream cipher: elements processed continuously, one output element at a time.

Cryptanalysis vs. brute-force attack

Attacks usually aim to recover the key, not just one plaintext. If the key falls, every past and future message under it is compromised.

Cryptanalysis. Exploits the nature of the algorithm, plus some knowledge of plaintext characteristics or sample plaintext–ciphertext pairs, to deduce a plaintext or the key.
Brute-force attack. Try every key until an intelligible plaintext appears. With X possible keys, success comes after X/2 tries on average. The attacker must also be able to recognize plaintext — harder if it is compressed or non-text data.
Table 3.1: attacks by what the cryptanalyst knows. Every attack also assumes the encryption algorithm and the ciphertext to be decoded are known.
AttackAdditionally known to the cryptanalyst
Ciphertext onlyNothing more. The hardest case for the attacker, easiest to defend against; usually needs statistical tests and a general idea of the plaintext type (English text, an EXE file, …).
Known plaintextOne or more plaintext–ciphertext pairs formed with the secret key (e.g., a standard file header). A probable-word attack is a close relative: specific words are expected at known places.

Only weak algorithms fail against ciphertext-only attacks; algorithms are generally designed to withstand known-plaintext attacks.

Two security levels

Unconditionally secure: the ciphertext does not contain enough information to determine the plaintext uniquely, however much ciphertext and time the opponent has.one-time pad only
Computationally secure: the cost of breaking exceeds the value of the information, or the time to break exceeds the information’s useful lifetime.practical goal

All cryptanalysis of symmetric schemes exploits traces of plaintext structure that survive into the ciphertext. (Public-key cryptanalysis instead tries to deduce one key of the pair from the other.)

3.2Substitution Techniques

A substitution technique replaces letters of plaintext with other letters, numbers or symbols (or, for bits, plaintext bit patterns with ciphertext bit patterns).

Book convention: plaintext in lowercase, ciphertext in UPPERCASE. Letters are numbered a = 0, b = 1, …, z = 25.

Caesar cipher

Replace each letter with the letter k places further down the alphabet, wrapping Z back to A (the classic version uses k = 3).

C = E(k, p) = (p + k) mod 26 k ∈ 1 … 25 (3.1) p = D(k, C) = (C − k) mod 26 (3.2)

Monoalphabetic ciphers

Permutation. An ordered sequence of all elements of a finite set, each appearing exactly once. A set of n elements has n! permutations (e.g., {a, b, c} → abc, acb, bac, bca, cab, cba).
Monoalphabetic substitution cipher. The cipher alphabet is any permutation of the 26 letters, and a single cipher alphabet is used for the whole message. Key space: 26! > 4 × 10²⁶ keys — far beyond brute force.

Weakness: the ciphertext keeps the letter frequencies of the plaintext language. If the analyst knows the plaintext is ordinary English, the regularities of the language break it.

Book walkthrough (adapted from [SINK09])
  1. Count ciphertext letter frequencies and compare with English (Figure 3.5). P (13.33%) and Z (11.67%) are probably e and t.
  2. Use digrams (two-letter combinations): the most common English digram is th; the most common ciphertext digram is ZW → Z = t, W = h, so P = e and ZWP = “the”, the most frequent trigram.
  3. ZWSZ looks like “th_t” → S = a. Continue by frequency plus trial and error.

Homophones. A countermeasure that gives one plaintext letter several cipher symbols (e.g., e → 16, 74, 35, 21). With symbols allotted in proportion to frequency, single-letter frequencies vanish — but each plaintext letter still affects only one ciphertext symbol, so multi-letter patterns such as digram frequencies survive.

Two ways to hide more structure: encrypt multiple letters at once (Playfair, Hill) or use multiple cipher alphabets (polyalphabetic ciphers).

Playfair cipher

Treats plaintext digrams as single units. Uses a 5 × 5 matrix built from a keyword: write the keyword’s letters (no duplicates) left-to-right, top-to-bottom, then the rest of the alphabet in order. I and J share one cell.

  1. Repeated letters in a pair are split with a filler such as x: balloon → ba lx lo on.
  2. Same row: replace each with the letter to its right (wrapping). ar → RM.
  3. Same column: replace each with the letter beneath (wrapping). mu → CM.
  4. Otherwise: each letter is replaced by the letter in its own row and the other letter’s column (the opposite corners of the rectangle). hs → BP, ea → IM (or JM).

Strength: 26 × 26 = 676 digrams, and digram frequencies have a much smaller range than single-letter ones. Weakness: it still leaves much plaintext structure intact; a few hundred letters of ciphertext are generally enough to break it.

A perfectly flat curve would make ciphertext-only cryptanalysis effectively impossible.

Hill cipher

Encrypts m letters at a time using m linear equations mod 26. First, the linear-algebra terms it needs:

Identity matrix I. A square matrix of all zeros except ones on the main diagonal (upper-left to lower-right).
Determinant. For a 2 × 2 matrix (k₁₁ k₁₂; k₂₁ k₂₂): det = k₁₁k₂₂ − k₁₂k₂₁. (In general: the signed sum of all products taking exactly one element from each row and each column.)
Inverse matrix M⁻¹. The matrix with M M⁻¹ = M⁻¹ M = I. It does not always exist. Mod 26 it is [M⁻¹]ᵢⱼ = (det M)⁻¹ (−1)^(i+j) Dⱼᵢ, where Dⱼᵢ is the subdeterminant after deleting row j and column i, and (det M)⁻¹ is the multiplicative inverse of det M mod 26 (Unit 2) — which exists only if det M is relatively prime to 26.

Strength: it completely hides single-letter frequencies; a larger matrix hides more (3 × 3 also hides two-letter frequencies). Strong against ciphertext-only attacks.

Weakness — known-plaintext attack. With m plaintext–ciphertext pairs of length m, stack them as rows of matrices X (plaintexts) and Y (ciphertexts): Y = XK. If X is invertible, K = X⁻¹Y; otherwise add pairs until an invertible X is found.

Polyalphabetic ciphers

Use different monoalphabetic substitutions as the message proceeds. Common features: (1) a set of related monoalphabetic substitution rules, and (2) a key that selects which rule is used for each transformation.

Vigenère cipher

The rules are the 26 Caesar ciphers (shifts 0–25), each named by its key letter (the letter that plaintext a becomes). A keyword of length m repeats over the plaintext:

Cᵢ = (pᵢ + k₍ᵢ mod m₎) mod 26 (3.3) pᵢ = (Cᵢ − k₍ᵢ mod m₎) mod 26 (3.4)
Try it · Vigenère and autokey
Repeated ciphertext trigrams are highlighted. With the repeating key, “red” falls 9 positions apart twice and becomes VTW both times — the clue to the key length.

Breaking it:

  1. Mono or poly? Monoalphabetic ciphertext has the same frequency profile as the language (one letter near 12.7%, one near 9.06%, …).
  2. Find the key length. Identical plaintext sequences a multiple of the keyword length apart give identical ciphertext. Common factors of the distances between repeats suggest the length (VTW at distance 9 → length 3 or 9).
  3. Split the problem. With key length m, the cipher is m monoalphabetic ciphers (positions 1, 10, 19, … share one). Attack each with frequency analysis.
Autokey system. Removes the periodic key: the keyword is followed by the plaintext itself as a running key. Still breakable, because key and plaintext share the same letter frequencies — e.g., e enciphered by e occurs with probability ≈ (0.127)² ≈ 0.016, about twice as often as t by t.

Vernam cipher

Works on bits: cᵢ = pᵢ ⊕ kᵢ and, because XOR undoes itself, pᵢ = cᵢ ⊕ kᵢ (⊕ = exclusive-OR). Its proposed key was a long tape loop that eventually repeated, so with enough ciphertext or known/probable plaintext it can still be broken.

One-time pad

One-time pad. A truly random key as long as the message, used for one message only and then discarded. It is unbreakable: the ciphertext bears no statistical relationship to the plaintext. It is the only cryptosystem with perfect secrecy (Appendix F).

Why: for any plaintext of the right length there is a key that yields it, so exhausting all keys produces every legible plaintext with no way to tell which was intended.

The key shown is whatever key would turn this ciphertext into your plaintext, using pᵢ = (Cᵢ − kᵢ) mod 27. The two book keys reproduce the two book plaintexts.
Two practical difficulties: (1) making large quantities of truly random keys; (2) distributing and protecting a key as long as every message, for both parties. So the one-time pad is useful mainly for low-bandwidth channels needing very high security.

3.3Transposition Techniques

A transposition cipher performs a permutation on the plaintext letters instead of substituting them.

Rail fence. Write the plaintext as a sequence of diagonals, read it off row by row. Depth 2: meet me after the toga party → MEMATRHTGPRYETEFETEOAAT.
Columnar transposition. Write the message in a rectangle row by row; read it off column by column in a permuted order. The column order is the key.
Try it · rail fence and columnar transposition
Rail fence:
Columnar: incomplete rows are padded with x, y, z, … as in the book. Green headers are the key; the column labelled 1 is read first.

Recognizing it: a pure transposition has exactly the plaintext’s letter frequencies. Single columnar transposition is fairly easy to break by laying the ciphertext in a matrix and shuffling columns; digram and trigram tables help.

Double transposition is much stronger. Numbering the 28 letters 01–28: after one pass the order still has regular structure (03 10 17 24 04 11 18 25 …); after two passes (17 09 05 27 24 16 12 07 …) it is far less structured.

3.4Rotor Machines

Multiple stages of encryption make cryptanalysis much harder, for substitution as well as transposition. Rotor machines apply that principle and point toward DES.

  • Each cylinder has 26 input and 26 output pins; internal wiring connects each input to a unique output. One fixed cylinder = a monoalphabetic substitution.
  • After each keystroke the cylinder rotates one position, defining a new substitution. One cylinder → a polyalphabetic cipher with period 26.
  • With several cylinders, the outputs of one feed the inputs of the next. They step like an odometer: the fast rotor moves every keystroke, the medium rotor once per full turn of the fast one, the slow rotor once per full turn of the medium one.

3.5Steganography

Strictly speaking not encryption: steganography conceals the existence of a message, while cryptography makes the message unintelligible.

Simple form: an arrangement of words or letters inside innocent text spells the real message (e.g., the first letter of each word). Other techniques:

  • Character marking — selected letters overwritten in pencil; visible only at an angle to bright light.
  • Invisible ink — leaves no trace until heat or a chemical is applied.
  • Pin punctures — small holes on selected letters, visible when held up to light.
  • Typewriter correction ribbon — text typed with correction tape between lines, visible only under strong light.
  • Least significant bits — in a 24-bit RGB image, the last bit of each pixel can be changed without visibly affecting the image (a single Kodak Photo CD frame, 3096 × 6144 pixels, can hide a 130-kB message).

4.1Traditional Block Cipher Structure

Many important symmetric block ciphers, including DES, are built on the Feistel structure. This section explains why it exists and how it works.

Stream ciphers and block ciphers

Stream cipher

Encrypts a digital data stream one bit or one byte at a time (e.g., autokey Vigenère, Vernam). A true one-time pad keystream is impractical, so a key-controlled bit-stream generator produces the keystream; both users only share its key. Its output must be unpredictable from earlier portions.

Block cipher

Treats a block of plaintext as a whole and produces a ciphertext block of equal length — typically 64 or 128 bits. Used by the vast majority of network symmetric applications; with modes of operation (Unit 5) it can act like a stream cipher.

Motivation: the ideal block cipher

Reversible (nonsingular) mapping. An n-bit block cipher maps the 2ⁿ possible plaintext blocks to ciphertext blocks. For decryption to work, each plaintext must give a unique ciphertext. The number of reversible mappings is (2ⁿ)!.

The ideal block cipher allows any reversible mapping, defined by a lookup table (Table 4.1). The dilemma:

  • Small n (e.g., 4) is just a classical substitution cipher → vulnerable to statistical analysis.
  • Large n hides statistics, but the key is the table: n × 2ⁿ bits. For n = 64 that is 64 × 2⁶⁴ = 2⁷⁰ bits — impractical.
  • A simple linear mapping (each output bit a mod-2 linear combination of input bits, key size n²) is the Hill cipher on bits, and just as vulnerable.

The Feistel cipher

Product cipher. Two or more simple ciphers executed in sequence so that the result is cryptographically stronger than any component. Feistel’s idea: a k-bit key and n-bit block giving 2ᵏ transformations, approximating the ideal cipher’s (2ⁿ)!.
Substitution. Each plaintext element or group of elements is uniquely replaced by a corresponding ciphertext element or group.
Permutation. The sequence of elements is reordered; nothing is added, deleted or replaced.

Diffusion and confusion

Two methods for frustrating statistical cryptanalysis. They are the cornerstone of modern block cipher design.

Diffusion

Dissipates the statistical structure of the plaintext into long-range statistics of the ciphertext: each plaintext digit affects many ciphertext digits. Goal: make the plaintext ↔ ciphertext statistical relationship as complex as possible. In binary ciphers: repeated permutation followed by a function.

Confusion

Makes the relationship between ciphertext statistics and the key as complex as possible, so even known ciphertext statistics don’t reveal how the key was used. Achieved with a complex (nonlinear) substitution; a linear substitution adds little confusion.

Permutation by itself is not diffusion: reordering does not change the statistics of individual letters or permuted blocks.

Feistel structure

The 2w-bit plaintext block is split into halves LE₀ and RE₀, which pass through n rounds. Round i uses subkey Kᵢ derived from the key K. Every round has the same structure:

One round, after Figure 4.3.
LEᵢ = REᵢ₋₁ REᵢ = LEᵢ₋₁ ⊕ F(REᵢ₋₁, Kᵢ)

Substitution on the left half (XOR with the round function F of the right half), then a permutation (swap the halves). This is a form of Shannon’s substitution-permutation network (SPN). After the last round the halves are swapped once more, which cancels that round’s swap.

Design parameters

Two further considerations: fast software encryption/decryption (often no hardware is available), and ease of analysis (a concisely explained algorithm is easier to check for weaknesses — DES is not easily analyzed).

Feistel decryption

Rule. Decrypt with the same algorithm: feed in the ciphertext and use the subkeys in reverse order (Kₙ first, K₁ last). Only one algorithm needs to be implemented.

At every stage the decryption value equals the encryption value with halves swapped: LD₁₆₋ᵢ ‖ RD₁₆₋ᵢ = REᵢ ‖ LEᵢ. Rearranging the round equations shows why:

REᵢ₋₁ = LEᵢ LEᵢ₋₁ = REᵢ ⊕ F(REᵢ₋₁, Kᵢ) = REᵢ ⊕ F(LEᵢ, Kᵢ) uses [A ⊕ B] ⊕ C = A ⊕ [B ⊕ C], D ⊕ D = 0, E ⊕ 0 = E
F need not be reversible. The derivation only ever recomputes F on the same input and XORs it away. Even a constant F (e.g., all ones) satisfies the equations.

4.2The Data Encryption Standard

DES (FIPS PUB 46; the algorithm is the Data Encryption Algorithm, DEA) encrypts 64-bit blocks with a 56-bit key. It is now for legacy use only, but triple DES (Unit 5) uses the same algorithm, so its structure still matters.

Redrawn from Figure 4.5. K1, K2, …, K16 are the subkeys fed to rounds 1–16. Small gray numbers are bit widths on that line: 64-bit blocks, the 56 key bits kept by PC-1, and 48-bit subkeys out of every PC-2.

Data path (left)

  1. Initial permutation (IP) rearranges the 64 plaintext bits → permuted input.
  2. 16 rounds of the same function, each using permutation and substitution, with subkey Kᵢ.
  3. Swap the left and right halves → preoutput.
  4. Inverse initial permutation (IP⁻¹) → 64-bit ciphertext.

Apart from IP and IP⁻¹, DES is exactly a 16-round Feistel cipher.

Key path (right)

The function takes a 64-bit key but uses only 56 bits; the other 8 can be parity bits. Permuted choice 1 selects and permutes the 56 bits. Each round then applies a left circular shift and permuted choice 2, giving a 48-bit subkey. PC-2 is the same every round; the subkeys differ because of the repeated shifts.

Decryption

As with any Feistel cipher: same algorithm, subkeys in reverse order (K₁₆ … K₁), and the initial and final permutations reversed.

Inside one round (details: Appendix S, used in Problem 4.11)

E[Rᵢ₋₁] expand the 32-bit right half to 48 bits A = E[Rᵢ₋₁] ⊕ Kᵢ XOR with the 48-bit subkey B = S(A) eight 6-bit groups → eight S-boxes (substitution tables) → 8 × 4 = 32 bits P(B) permutation P Rᵢ = P(B) ⊕ Lᵢ₋₁, Lᵢ = Rᵢ₋₁

So F(R, K) = P(S(E(R) ⊕ K)). The S-boxes provide the nonlinear substitution (confusion); E and P spread bits across S-boxes (diffusion).

Avalanche effect. A change of one bit in the plaintext or the key should change many bits of the ciphertext. A small change would let an attacker shrink the plaintext or key space to search. About half the bits differing is ideal — almost all differing would be as revealing as almost none.

4.4The Strength of DES

Concerns fall into two areas: key size and the nature of the algorithm.

The use of 56-bit keys

2⁵⁶ ≈ 7.2 × 10¹⁶ keys. At one encryption per microsecond, searching half the space takes over a thousand years — but that rate is far too conservative. Today’s multicore computers reach about 10⁹ keys/s, and supercomputers about 10¹³ encryptions/s.

A single PC breaks DES in about a year; a supercomputer in about an hour. Keys of 128 bits or more are effectively unbreakable by brute force alone — even 10¹² times faster, a 128-bit key would take over 100,000 years. The main alternatives are AES (Unit 4) and triple DES (Unit 5).

The nature of the DES algorithm

The concern is the eight S-boxes: their design criteria were never made public, raising suspicion of a hidden weakness. Regularities and unexpected behaviors have been found, but no fatal weakness has been publicly discovered.

Timing attacks

Timing attack. Information about the key or plaintext is obtained by observing how long an implementation takes to decrypt various ciphertexts, since algorithms often take slightly different times on different inputs.

One approach against DES yields the Hamming weight (number of 1 bits) of the key — far from the key itself. DES appears fairly resistant; success against DES, triple DES or AES seems unlikely.

4.5Block Cipher Design Principles

A Feistel cipher’s strength comes from three design aspects.

1 · Number of rounds

More rounds make cryptanalysis harder, even with a weak F. Criterion: choose enough rounds that known cryptanalytic attacks need more effort than brute force. For 16-round DES, differential cryptanalysis needs 255.1 operations vs. 255 for brute force; with 15 or fewer rounds it would beat brute force. If the criterion holds, strength can be judged by key length alone.

2 · Design of F

F provides the confusion, so it must be hard to “unscramble”. It should be nonlinear (hard to approximate by linear equations) and have good avalanche properties.

3 · Key schedule

One subkey per round, chosen to make it hard to deduce individual subkeys or work back to the main key. No general principles yet; at minimum it should guarantee key/ciphertext SAC and BIC.

Strict avalanche criterion (SAC). Any output bit j of an S-box changes with probability 1/2 when any single input bit i is inverted, for all i, j. Can be applied to F as a whole.
Bit independence criterion (BIC). Output bits j and k change independently when any single input bit i is inverted, for all i, j, k.

SAC and BIC appear to strengthen the effectiveness of the confusion function.

3.6 · 4.6Review Questions

Review questions 3.1–3.14 and 4.1–4.7 from the book. Answer first, then open to check.

Chapter 3

3.1 Describe the main requirements for the secure use of symmetric encryption.

A strong algorithm (an opponent with the algorithm and many plaintext–ciphertext pairs still can’t decrypt or find the key), and a key obtained securely by sender and receiver and kept secret.

3.2 What are the two basic functions used in encryption algorithms?

Substitution (map each element to another) and transposition (rearrange elements).

3.3 Differentiate between secret-key encryption and public-key encryption.

Secret-key (symmetric): sender and receiver use the same key. Public-key (asymmetric): they use different keys.

3.4 What is the difference between a block cipher and a stream cipher?

A block cipher processes one block of elements at a time, producing an output block per input block; a stream cipher processes elements continuously, producing output one element at a time.

3.5 What are the two general approaches to attacking a cipher?

Cryptanalysis (exploit the algorithm and knowledge of the plaintext or sample pairs) and brute force (try every key).

3.6 List and briefly define types of cryptanalytic attacks based on what is known to the attacker.

Ciphertext only; known plaintext (plus plaintext–ciphertext pairs); chosen plaintext (plus ciphertexts of attacker-chosen plaintexts); chosen ciphertext (plus decryptions of attacker-chosen ciphertexts); chosen text (both). See Table 3.1.

3.7 What is the difference between an unconditionally secure cipher and a computationally secure cipher?

Unconditionally secure: the ciphertext doesn’t contain enough information to determine the plaintext, no matter the time or ciphertext available (only the one-time pad). Computationally secure: breaking costs more than the information’s value or takes longer than its useful life.

3.8 Why is the Caesar cipher vulnerable to brute-force cryptanalysis?

The algorithms are known, there are only 25 keys, and the plaintext language is known and easily recognized.

3.9 How much key space is available with a monoalphabetic substitution cipher?

26! > 4 × 10²⁶ possible keys.

3.10 What is the drawback of a Playfair cipher?

It still leaves much of the plaintext language’s structure intact; a few hundred letters of ciphertext are generally enough to break it.

3.11 What is the difference between a monoalphabetic and a polyalphabetic cipher?

Monoalphabetic uses a single cipher alphabet for the whole message; polyalphabetic uses a set of related monoalphabetic rules, with a key choosing the rule for each letter.

3.12 What are two problems with the one-time pad?

Producing large quantities of truly random keys, and distributing and protecting a key as long as each message for both parties.

3.13 What is a transposition cipher?

A cipher that performs a permutation on the plaintext letters rather than substituting them.

3.14 What are the drawbacks of steganography?

High overhead to hide relatively few bits, and once the system is discovered it becomes virtually worthless.

Chapter 4

4.1 Briefly define a nonsingular transformation.

A reversible mapping: each plaintext block produces a unique ciphertext block, so decryption is possible.

4.2 What is the difference between a block cipher and a stream cipher?

A stream cipher encrypts a data stream one bit or byte at a time; a block cipher treats a whole block of plaintext as a unit and produces a ciphertext block of equal length.

4.3 Why is it not practical to use an arbitrary reversible substitution cipher of the kind in Table 4.1?

For a small block it is just a classical substitution cipher, open to statistical analysis. For a large block the mapping table, which is the key, is enormous (n × 2ⁿ bits), impractical for implementation and performance.

4.4 Briefly define the terms substitution and permutation.

Substitution: each plaintext element or group is uniquely replaced by a corresponding ciphertext element or group. Permutation: the plaintext sequence is reordered, with no elements added, deleted or replaced.

4.5 What is the difference between diffusion and confusion?

Diffusion spreads plaintext statistics over the ciphertext (each plaintext digit affects many ciphertext digits). Confusion makes the relationship between ciphertext statistics and the key as complex as possible, via complex substitution.

4.6 Which parameters and design choices determine the actual algorithm of a Feistel cipher?

Block size, key size, number of rounds, subkey generation algorithm, and round function F; plus fast software encryption/decryption and ease of analysis.

4.7 What are the critical aspects of Feistel cipher design?

The number of rounds, the design of the function F, and the key schedule algorithm.
