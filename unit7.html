Hashes & MACs

Encryption hides data; data integrity algorithms detect when data has been changed. Chapter 11 covers cryptographic hash functions: what they are used for, the resistance properties they need, the birthday attack, and the SHA-2 (SHA-512) and SHA-3 (Keccak) designs. Chapter 12 adds a secret key to get message authentication codes: HMAC, CMAC, the authenticated-encryption modes CCM and GCM, key wrapping, and PRNGs built from hashes and MACs.

11.1Applications of Cryptographic Hash Functions

A hash function is the most versatile algorithm in this book. Its uses (message authentication, digital signatures, password files, intrusion detection, PRNGs) decide which security properties it needs in 11.3.

Hash function — a function H that accepts a variable-length block of data M and produces a fixed-size hash value h = H(M). A “good” hash function spreads outputs evenly and apparently randomly over a large set of inputs, so a change to any bit of M changes h with high probability.
Computationally infeasible — no attack is significantly more efficient than brute force (trying inputs one by one), and brute force takes far too long.
Cryptographic hash function — a hash function for which it is computationally infeasible to find either (a) a data object that maps to a pre-specified hash value (the one-way property) or (b) two data objects that map to the same hash value (the collision-free property).

The input is normally padded to a whole number of fixed-size blocks (e.g. 1024 bits), and the padding includes the original message length in bits. The length field makes it harder to find a second message with the same hash.

Redrawn from Figure 11.1, Cryptographic hash function h = H(M).

Message authentication

Message authentication — a mechanism or service that verifies the integrity of a message: data received are exactly as sent (no modification, insertion, deletion or replay), and often that the claimed sender is genuine. The same ideas apply to data at rest, such as a stored file. When a hash is used this way its value is called a message digest.

The sender transmits M together with H(M); the receiver recomputes H(M) and compares. The hash value itself must be protected: otherwise an attacker in the middle (Darth) can replace the data and attach a fresh hash of the replacement, and Bob sees no mismatch (Figure 11.2b).

Reasons to avoid encryption, as in (c): encryption software is relatively slow; encryption hardware has a cost at every node; hardware is optimized for large data, so small blocks are dominated by setup overhead; and algorithms may be patented.

Message authentication code (MAC) — also called a keyed hash function. A function of a secret key and a data block that produces a value (the MAC) attached to the message. Without the key, an attacker who alters the message cannot produce the matching MAC; the verifier also knows who sent it, because no one else holds the key. Covered in Chapter 12.

Digital signatures

The hash value is encrypted with the sender’s private key; anyone with the public key can verify it, and forging it requires the private key (Figure 11.4):

M ‖ E(PRa, H(M))(a)authentication + signature
E(K, [M ‖ E(PRa, H(M))])(b)+ confidentiality

Other applications

  • One-way password file: the operating system stores H(password), not the password. A login is checked by hashing the entered password and comparing.
  • Intrusion and virus detection: store H(F) for each file securely (e.g. on write-once media); recompute later to see if F changed. An intruder must change F without changing H(F).
  • Pseudorandom function (PRF) or PRNG: hash output looks random, so it can generate symmetric keys and random bits (12.9).

11.2Two Simple Hash Functions

Two insecure functions that show the general shape (process n-bit blocks one at a time) and why simple checksums fail as cryptographic hashes.

All hash functions view the input as a sequence of n-bit blocks and process them iteratively to produce an n-bit hash.

XOR hash (longitudinal redundancy check) — the bitwise XOR of every block: Ci = bi1 ⊕ bi2 ⊕ … ⊕ bim, where bij is bit i of block j. This is a parity bit per bit position. For random data a data error goes undetected with probability 2−n; for formatted data it does worse (in text, the high bit of each byte is always 0, so a 128-bit XOR hash gives only 2−112).
Rotated XOR (RXOR) — start with hash 0; for each block, rotate the current hash left by one bit, then XOR in the block. The rotation “randomizes” regularities in the input.
Lab · XOR vs RXOR (16-bit)Figure 11.5

Swapping blocks never changes the XOR hash (XOR is order-independent). Easy forgery: append one block equal to the XOR of the current hash and the target hash.

  • RXOR is a good integrity check but useless for security when only the hash is encrypted (Figures 11.3b, 11.4a): for any desired message, append one n-bit block that forces the hash to the required value.
  • Encrypting the whole message plus XOR hash is not enough either. A scheme proposed by the National Bureau of Standards appends h = XN+1 = X1 ⊕ … ⊕ XN (64-bit blocks) and encrypts everything in CBC mode. Since Xi = Yi−1 ⊕ D(K, Yi), the hash equals an XOR of terms that can be taken in any order, so permuting the ciphertext blocks goes undetected.

11.3Requirements and Security

The six requirements of Table 11.1 define “secure” for a hash function, and each application in 11.1 relies on a different subset of them.

Preimage — for h = H(x), x is a preimage of h. H is many-to-one, so a hash value generally has many preimages: with b-bit inputs and n-bit hashes (b > n), about 2b−n each on average; with arbitrary-length inputs, arbitrarily many.
Collision — x ≠ y with H(x) = H(y). Collisions must exist; what matters is that they are infeasible to find.

  • Preimage resistance protects the secret value in method (c): an attacker who sees M and H(S ‖ M) could otherwise invert H and read off S.
  • Second preimage resistance stops forgery with an encrypted hash (Figures 11.3b, 11.4a): otherwise the attacker computes H(M) from an intercepted M and finds another message with the same hash.

Brute-Force Attacks and the Birthday Attack

A brute-force attack depends only on the hash length m. Collisions are found far faster than preimages: about 2m/2 tries rather than 2m.

Two categories of attack exist, as for ciphers: brute force (depends only on bit length) and cryptanalysis (exploits weaknesses of a particular algorithm).

  • Preimage and second preimage attacks: pick random y until H(y) = h. Effort ∝ 2m; on average 2m−1 tries.
  • Collision attack: find any x, y with H(x) = H(y). By the birthday paradox, if values are drawn uniformly from 0 … N−1, the chance of a repeat exceeds 0.5 after about √N draws. For an m-bit hash, √(2m) = 2m/2 tries.

Yuval’s birthday attack on a signed message

  1. A is prepared to sign a legitimate message x by appending its m-bit hash encrypted with A’s private key (Figure 11.4a).
  2. The opponent generates 2m/2 variations x′ of x with the same meaning, and stores them with their hashes.
  3. The opponent prepares a fraudulent message y that A should not sign.
  4. The opponent generates variations y′ of y, hashing each, until some H(y′) matches a stored H(x′).
  5. A signs the valid variation x′. The signature also fits y′ (same hash), so the opponent succeeds without knowing the key.

For a 64-bit hash this costs only about 232. Variations are easy to make: insert “space-space-backspace” pairs between words and switch some to “space-backspace-space”, or reword without changing meaning (Figure 11.7 is a letter written in 238 variations).

Cryptanalysis and the Iterated Hash Structure

Most hash functions in use, SHA included, share one structure, so attacks focus on its compression function.

Cryptanalysis tries to beat brute force. An ideal hash algorithm requires cryptanalytic effort ≥ brute-force effort.

Iterated hash function (Merkle) — split the input into L blocks of b bits, padding the final block and including the total input length in it. A compression function f takes an n-bit chaining variable and a b-bit block and outputs n bits (usually b > n, hence “compression”):
CV0 = IV = initial n-bit value CVi = f(CVi−1, Yi−1) 1 ≤ i ≤ L H(M) = CVL
Redrawn from Figure 11.8, General structure of secure hash code. Step through to follow the chaining variable.
  • Merkle–Damgård result: if the length field is included and f is collision resistant, the iterated hash is collision resistant. Designing a secure hash reduces to designing a collision-resistant compression function on fixed-size inputs.
  • Cryptanalysis therefore targets f: find efficient ways to produce collisions for one execution of f, then deal with the fixed IV. Like block ciphers, f is a series of rounds, so attacks study bit-change patterns from round to round.

11.4Hash Functions Based on Cipher Block Chaining

Building a hash from a block cipher in CBC fashion without a secret key; it inherits the birthday attack and a meet-in-the-middle variant.

Rabin’s proposal: split M into blocks M1, …, MN, and use each block as the key of a symmetric cipher such as DES:

H0 = initial value Hi = E(Mi, Hi−1) G = HN

With DES the hash is only 64 bits, so the birthday attack works. A meet-in-the-middle version of the birthday attack needs only one message and its signature (an encrypted m-bit hash G):

  1. Compute the unencrypted hash G of the intercepted message.
  2. Write any desired message Q1, …, QN−2.
  3. Compute Hi = E(Qi, Hi−1) for 1 ≤ i ≤ N−2.
  4. For 2m/2 random blocks X compute E(X, HN−2); for 2m/2 random blocks Y compute D(Y, G).
  5. By the birthday paradox some X, Y give E(X, HN−2) = D(Y, G).
  6. The message Q1, …, QN−2, X, Y hashes to G, so the old signature fits it.

11.5Secure Hash Algorithm (SHA)

The SHA family is the most widely used set of hash functions. The book describes SHA-512; the other SHA-2 versions are similar.

SHA is a NIST standard (FIPS 180) modeled on MD4. SHA-1 gives a 160-bit hash. SHA-256, SHA-384 and SHA-512 (together SHA-2) use the same structure and the same kinds of modular arithmetic and logical operations; SHA-224, SHA-512/224 and SHA-512/256 were added later (FIPS 180-4).

SHA-512 logic

Input: a message under 2128 bits. Output: a 512-bit digest. Processing is in 1024-bit blocks and follows the iterated structure of Figure 11.8.

  1. Append padding bits so the length ≡ 896 (mod 1024). Padding is always added (1 to 1024 bits): a single 1 bit, then 0 bits.
  2. Append length: a 128-bit unsigned integer, most significant byte first, holding the original length in bits. The result is N × 1024 bits: blocks M1 … MN.
  3. Initialize the hash buffer: eight 64-bit registers a … h, set to the first 64 bits of the fractional parts of the square roots of the first eight primes, stored big-endian.
  4. Process each 1024-bit block in module F: 80 rounds, each using a 64-bit word Wt from the message schedule and a constant Kt (first 64 bits of the fractional parts of the cube roots of the first 80 primes). The output of round 79 is added word-by-word mod 264 to the input Hi−1 to give Hi.
  5. Output: after N blocks, HN is the 512-bit digest.
Big-endian — the most significant byte of a word is stored at the lowest address (leftmost). Little-endian stores the least significant byte first. SHA-512 is big-endian; SHA-3 lanes (11.6) are little-endian.
H0 = IV Hi = SUM64(Hi−1, abcdefghi) abcdefghi = output of round 79 on block i MD = HN SUM64 = word-by-word addition mod 264

SHA-512 Round Function and Message Schedule

Each of the 80 rounds updates the 512-bit buffer abcdefgh. Six words are only shifted down; two (a and e) are new.

T1 = h + Ch(e, f, g) + Σ1(e) + Wt + Kt T2 = Σ0(a) + Maj(a, b, c) h = g g = f f = e e = d + T1 d = c c = b b = a a = T1 + T2 + is addition mod 264, 0 ≤ t ≤ 79
  • Ch(e, f, g) = (e AND f) ⊕ (NOT e AND g): the conditional function “if e then f else g”, bit by bit.
  • Maj(a, b, c) = (a AND b) ⊕ (a AND c) ⊕ (b AND c): true where a majority (two or three) of the bits are true.
  • Σ0(a) = ROTR28(a) ⊕ ROTR34(a) ⊕ ROTR39(a); Σ1(e) = ROTR14(e) ⊕ ROTR18(e) ⊕ ROTR41(e). ROTRn = circular right shift of the 64-bit word by n bits.
  • Word e depends on d, e, f, g, h, Wt, Kt. Word a depends on every input word except d, plus Wt, Kt.

Message schedule

The 80 words Wt come from the current 1024-bit block (Figure 11.12). W0 … W15 are the block’s 16 words. For t = 16 … 79:

Wt = σ1(Wt−2) + Wt−7 + σ0(Wt−15) + Wt−16 σ0(x) = ROTR1(x) ⊕ ROTR8(x) ⊕ SHR7(x) σ1(x) = ROTR19(x) ⊕ ROTR61(x) ⊕ SHR6(x) SHRn = right shift, zeros in on the left

This adds redundancy and interdependence among the compressed words, which makes it harder to find a different block with the same compression output. Every bit of the hash depends on every input bit. Unless SHA-512 has an unpublished weakness, finding two messages with the same digest takes about 2256 operations, and finding a message with a given digest about 2512.

11.6SHA-3

SHA-2 shares structure and operations with the broken MD5 and SHA-0, so NIST ran a competition for a different design. The winner, Keccak, is SHA-3 (FIPS 202). It complements SHA-2 rather than replacing it.

The sponge construction

The sponge has the general structure of an iterated hash: split input into fixed blocks and feed each iteration’s output into the next. It allows variable-length input and output, so the same structure can serve as a hash (fixed output), a PRNG (fixed input), and other functions. It is defined by three parameters:

  • f: the internal function applied once per block, called here the iteration function (Keccak calls it a permutation).
  • r: the bitrate, the input block size; the bits of message processed per iteration.
  • pad: the padding algorithm. pad10* appends 1 then the minimum number of 0s; pad10*1 (multirate) appends 1, 0s, then 1, and is the simplest scheme allowing the same f at different rates. FIPS 202 uses pad10*1. Padding is always added: if the message is already a multiple of r, a full padding block is appended.
State — a b-bit variable s, b = r + c, initialized to all zeros. Capacity c is the part of the state never directly touched by input or output; it measures the achievable security. Raising c and lowering r trades speed for security. Keccak defaults: c = 1024, r = 576, b = 1600.
  • Absorbing phase: pad each r-bit block with zeros to b bits, XOR it into s, then s ← f(s).
  • Squeezing phase: if the wanted output length ℓ ≤ b, return the first ℓ bits of s. Otherwise keep the first r bits as Z0, apply f again, take the next r bits as Z1, and so on until (j−1)·r < ℓ ≤ j·r; return the first ℓ bits.
absorb P₀, P₁, P₂, then squeeze Z₀, Z₁

The SHA-3 Iteration Function f (Keccak-f)

f turns the 1600-bit state into a 5 × 5 matrix of 64-bit lanes and runs 24 rounds of five steps. The steps use only XOR, AND, NOT and rotations, so there are no tables or arithmetic in which a trapdoor could hide.

Lane — one 64-bit word of the state. The state is the array a[x, y, z] with column x = 0…4, row y = 0…4 and bit z = 0…63; as lanes, L[x, y]. Bits map as s[64(5y + x) + z] = a[x, y, z]: the first 64 bits of s are L[0, 0] (lower left), the next L[1, 0], filling row y = 0 first. Note x is the column, unlike the usual row-first math convention.

12.2Message Authentication Functions

Every authentication mechanism has a lower-level function that produces an authenticator and a higher-level protocol that uses it. This section compares the three kinds of authenticator.

Authenticator — a value used to authenticate a message. Three classes of function produce one: a hash function (fixed-length hash value, Chapter 11), message encryption (the ciphertext of the whole message), and a MAC (a fixed-length value computed from the message and a secret key).

Message encryption · symmetric

With key K shared only by A and B, encryption gives confidentiality, and B knows the message came from A (only A could produce ciphertext that decrypts under K) and was not altered (without K an opponent cannot change ciphertext bits to get chosen plaintext changes).

B’s decryption accepts any input X and outputs Y = D(K, X). If any bit pattern is a legitimate plaintext, B cannot tell a real message from random ciphertext. Authentication by encryption requires that only a small subset of bit patterns count as legitimate plaintext, i.e. the plaintext needs structure.

One way to add structure: append an error-detecting code, a frame check sequence (FCS) F(M), before encrypting. The order matters:

An opponent cannot make ciphertext that decrypts to a valid FCS, so this authenticates.

Anyone can compute a valid FCS over any ciphertext, so there is no authentication.

Any structure helps, such as layered protocol headers. If each pair of hosts shared a key and encrypted everything except the IP header, a substituted segment would not decrypt to a meaningful TCP header, and the sequence numbers would stop an opponent from delaying, misordering or deleting segments.

Message authentication code

A and B share key K. A computes MAC = C(K, M) (C = MAC function) and sends M with the MAC; B recomputes and compares (Figure 12.4a). If they match, B knows:

  1. The message was not altered: an attacker without K cannot change the MAC to match changes.
  2. The message is from the alleged sender: no one else can make a proper MAC.
  3. If the message carries a sequence number (HDLC, X.25, TCP), the order is correct: the number cannot be altered.

A MAC is like encryption but need not be reversible. It is a many-to-one function: with an n-bit MAC there are 2n MAC values for N ≫ 2n messages, and 2k keys. Example: 100-bit messages, 10-bit MAC → each MAC value is produced by 2100/210 = 290 messages; a 5-bit key gives 32 mappings. This makes a MAC less vulnerable to being broken than encryption.

Situations where a separate MAC beats symmetric encryption:

  • The same message is broadcast to many destinations; only one has to check authenticity and raise an alarm.
  • A heavily loaded receiver can check selected messages at random instead of decrypting all.
  • A program in plaintext can run without decryption each time, yet be checked on demand.
  • Some applications need authentication but not secrecy, e.g. SNMPv3 separates the two.
  • Separating the functions gives architectural flexibility (authenticate at application level, encrypt at transport level).
  • Protection can outlast reception: decryption ends encryption’s protection, but a MAC can still be checked later inside the target system.
LimitA MAC is not a digital signature: sender and receiver share the same key, so either could have produced it.

12.3Requirements for Message Authentication Codes

Brute-forcing a MAC key works differently from brute-forcing an encryption key, and an attacker may forge tags without the key at all. The three requirements below rule this out.

MAC (also cryptographic checksum) — T = MAC(K, M): M is variable length, K is shared only by sender and receiver, and T is the fixed-length authenticator, called the tag. The tag is attached when M is known to be correct; the receiver recomputes it.

Key search on a MAC. For encryption, ~2k−1 tries of D(Ki, C) find a key whose output looks like plaintext. For a MAC with k > n, trying all 2k keys on a known (M1, T1) leaves about 2k−n keys that match; each further pair cuts the set by 2n, so about k/n rounds are needed. If k ≤ n, the first round likely leaves one key. Discovering a MAC key is therefore no less effort than an encryption key of the same length.

Lab · Rounds of MAC key searchbook: k = 80, n = 32

Forgery without the key. Let M = X1 ‖ … ‖ Xm (64-bit blocks), Δ(M) = X1 ⊕ … ⊕ Xm and MAC(K, M) = E(K, Δ(M)) with DES in ECB mode. Key search costs 256, but an opponent can replace X1 … Xm−1 with any Y1 … Ym−1 and set Ym = Y1 ⊕ … ⊕ Ym−1 ⊕ Δ(M). The new message has the same Δ, so the original tag is still valid.

Lab · Forging the XOR MACAES used as E

Assuming the opponent knows the MAC function but not K, the MAC function must satisfy:

  1. Given M and MAC(K, M), it is infeasible to construct M′ with MAC(K, M′) = MAC(K, M). (defeats the forgery above)
  2. MAC(K, M) is uniformly distributed: for random M, M′, Pr[MAC(K, M) = MAC(K, M′)] = 2−n. (a chosen-plaintext brute force then needs ~2n−1 tries)
  3. If M′ = f(M) for a known transformation f (e.g. flipping specific bits), Pr[MAC(K, M) = MAC(K, M′)] = 2−n. (no weak spots in parts of the message)

12.4Security of MACs

Brute force on a MAC is harder than on a hash because it needs known message–tag pairs; its cost is min(2k, 2n).

A hash collision can be hunted off line. Whether a MAC can be attacked off line depends on the key and tag sizes. The desired property:

Computation resistance — given one or more text–MAC pairs [xi, MAC(K, xi)], it is computationally infeasible to compute any text–MAC pair [x, MAC(K, x)] for a new input x ≠ xi.

Attack the key space

Compute the tag of a known text under all 2k keys; check survivors against more pairs. Effort ≈ 2k. Finding K lets the attacker MAC anything.

Attack the MAC value

Produce a valid tag for a given message, or a message for a given tag. Effort ≈ 2n (like one-way or weak collision resistance), and it cannot be done off line: the attacker needs chosen text–tag pairs or the key.

brute-force effort ≈ min(2k, 2n) reasonable requirement: min(k, n) ≥ N N perhaps ≈ 128

Cryptanalysis tries to beat that; an ideal MAC requires cryptanalytic effort ≥ brute force. MACs vary in structure far more than hashes, so the cryptanalysis is hard to generalize.

12.5MACs Based on Hash Functions: HMAC

A plain hash has no key and cannot be used as a MAC directly. HMAC (RFC 2104, FIPS 198) adds a key around any embedded hash and is mandatory-to-implement for IP security.

Motivation: hash functions generally run faster in software than block ciphers, and their library code is widely available.

Design objectives (RFC 2104)

  • Use available hash functions without modification, especially fast, freely available ones.
  • Allow easy replacement of the embedded hash if faster or more secure ones are needed (e.g. SHA-2 → SHA-3). The hash is treated as a black box.
  • Preserve the hash’s original performance without significant degradation.
  • Use and handle keys in a simple way.
  • Have a well-understood analysis of strength based on reasonable assumptions about the hash. This is HMAC’s main advantage over other hash-based schemes.

The algorithm

Hembedded hash function, n-bit output, b-bit blocks (SHA-256: n = 256, b = 512) Ksecret key; recommended length ≥ n. If longer than b, K is hashed first to give an n-bit key K+K padded with zeros to b bits ipad00110110 (36 hex) repeated b/8 times opad01011100 (5C hex) repeated b/8 times
HMAC(K, M) = H[(K+ ⊕ opad) ‖ H[(K+ ⊕ ipad) ‖ M]]
  1. Pad K with zeros to make the b-bit string K+.
  2. XOR K+ with ipad to get the b-bit block Si.
  3. Append M to Si.
  4. Apply H to the result (the inner hash).
  5. XOR K+ with opad to get the b-bit block So.
  6. Append the inner hash to So.
  7. Apply H and output the result.
Padding sideThe book says zeros go on the left of K. RFC 2104 step (1) appends zeros to the end (right) of K, and real implementations follow the RFC; the lab below does too, so its outputs match the RFC 4231 test vectors (see Sources).

The ipad and opad XORs each flip half the bits of K, a different half each time, so passing Si and So through the compression function pseudorandomly generates two keys from K. For long messages HMAC costs about the same as H; it adds three compression-function calls (for Si, So and the inner hash block).

Redrawn from Figure 12.5, HMAC structure.

Efficient implementation (Figure 12.6): precompute f(IV, K+ ⊕ ipad) and f(IV, K+ ⊕ opad) once per key and use them in place of the IV. Then only one extra compression call is added per message, which pays off when most messages are short.

Lab · HMAC, step by steppreset: RFC 4231 test case 2

Security of HMAC

Its designers proved an exact relationship: for a given effort (time, message–tag pairs), a successful attack on HMAC is equivalent to one of these attacks on the embedded hash:

  1. Computing an output of the compression function with an IV that is random, secret and unknown to the attacker (brute force on that n-bit key ≈ 2n, or a birthday attack).
  2. Finding collisions in the hash even when the IV is random and secret (birthday attack ≈ 2n/2).

For plain MD5 a 264 collision search looks feasible off line. Against HMAC the attacker does not know K and cannot generate pairs off line, so it must observe 264 blocks (272 bits) produced under one key: on a 1-Gbps link, about 150,000 years. On this argument the book considers MD5 acceptable inside HMAC where speed matters.

12.6MACs Based on Block Ciphers: DAA and CMAC

A block cipher in CBC mode with IV = 0 gives a MAC. The original form (DAA) is only secure for fixed-length messages; CMAC fixes that with two derived subkeys.

Data Authentication Algorithm (DAA) · obsolete

FIPS PUB 113 / ANSI X9.17, based on DES. Split the data into 64-bit blocks D1 … DN, padding the last on the right with zeros:

O1 = E(K, D1) Oj = E(K, [Dj ⊕ Oj−1]) 2 ≤ j ≤ N DAC = ON, or its leftmost M bits, 16 ≤ M ≤ 64

This CBC-MAC is secure only if every message has one fixed length of mn bits. Given the tag T of a one-block message X, the attacker knows the tag of the two-block message X ‖ (X ⊕ T): it is again T.

Lab · CBC-MAC length-extension forgeryAES-128 in place of DES

Cipher-based MAC (CMAC) · NIST SP 800-38B

Fixing the limitation took three keys (one cipher key and two b-bit keys); a refinement derives the two b-bit keys from the cipher key. CMAC is for AES (b = 128, k = 128/192/256) and triple DES (b = 64, k = 112/168). For a message of n whole blocks M1 … Mn:

C1 = E(K, M1) Cj = E(K, [Mj ⊕ Cj−1]) 2 ≤ j < n Cn = E(K, [Mn ⊕ Cn−1 ⊕ K1]) T = MSBTlen(Cn) MSBs(X) = leftmost s bits

If the message is not a whole number of blocks, pad the last block on the right with a 1 then 0s, and use K2 instead of K1. Subkeys:

L = E(K, 0b) K1 = L · x multiplication in GF(2b) K2 = L · x2 = (L · x) · x

Multiplying by x is a one-bit left shift, then, if the bit shifted out was 1, an XOR with a constant set by the irreducible polynomial: x128 + x7 + x2 + x + 1 (constant 0x87) for b = 128, x64 + x4 + x3 + x + 1 (0x1B) for b = 64. This is the same doubling used in AES MixColumns (Unit 4).

12.7Authenticated Encryption: CCM and GCM

Many protocols need confidentiality and integrity together. Combining a cipher and a MAC ad hoc has pitfalls; CCM and GCM are NIST-standardized designs that do both.

Authenticated encryption (AE) — an encryption system that simultaneously protects the confidentiality and the authenticity (integrity) of communications.
ApproachComputationReceiver orderUsed by
Hash then encrypt (H→E)h = H(M); E(K, [M ‖ h])decrypt, then verifyWEP (fundamentally weak, replaced)
Authenticate then encrypt (A→E)T = MAC(K1, M); E(K2, [M ‖ T])decrypt, then verifySSL/TLS
Encrypt then authenticate (E→A)C = E(K2, M); T = MAC(K1, C)verify, then decryptIPsec
Encrypt and authenticate (E + A)C = E(K2, M); T = MAC(K1, M)decrypt, then verifySSH

All four have known security concerns, but with proper design any can be secure; that is the goal of CCM and GCM.

Counter with CBC-MAC (CCM) · SP 800-38C

Standardized for IEEE 802.11 Wi-Fi; a variation of encrypt-and-MAC. Ingredients: AES, CTR mode (Unit 5), and the CMAC algorithm, all with one key K. Inputs:

  • Plaintext P: authenticated and encrypted.
  • Associated data A: authenticated but not encrypted, e.g. a protocol header that must travel in the clear.
  • Nonce N: a value unique for every instance during a protocol association; prevents replay and other attacks.
// CCM authentication-encryption (SP 800-38C) 1. Format (N, A, P) into blocks B0, B1, …, Br // B₀ = nonce + length flags 2. Y0 = E(K, B0) 3. for i = 1 to r: Yi = E(K, Bi ⊕ Yi−1) // CBC-MAC 4. T = MSBTlen(Yr) 5. Generate counters Ctr0, Ctr1, …, Ctrm, m = ⌈Plen/128⌉ 6. for j = 0 to m: Sj = E(K, Ctrj) 7. S = S1 ‖ S2 ‖ … ‖ Sm 8. return C = (P ⊕ MSBPlen(S)) ‖ (T ⊕ MSBTlen(S0)) // tag encrypted with Ctr₀

Decryption: reject if Clen ≤ Tlen; regenerate S; recover P and T; recompute the CBC-MAC over (N, A, P); return P only if the tags match, else INVALID. CCM is fairly complex: two full passes over the plaintext, a forced trade-off between nonce and tag lengths, and the key used twice in CTR mode. Analyses still conclude it is highly secure.

Galois/Counter Mode (GCM) · SP 800-38D

Designed to be parallelizable for high throughput, low cost and low latency. The message is encrypted with a CTR variant; the ciphertext is multiplied with key material and length information over GF(2128) to get the tag. GMAC is the MAC-only version. Two functions:

GHASHH(X) — a keyed hash. Split X into 128-bit blocks X1 … Xm; Y0 = 0128; Yi = (Yi−1 ⊕ Xi) · H in GF(2128); return Ym. Equivalently (X1·Hm) ⊕ (X2·Hm−1) ⊕ … ⊕ (Xm·H), so with H2, H3, … precomputed the blocks can be processed in parallel.
GCTRK(ICB, X) — CTR mode from initial counter block ICB: CB1 = ICB, CBi = inc32(CBi−1) (add 1 mod 232 to the rightmost 32 bits), Yi = Xi ⊕ E(K, CBi); the last partial block uses only the needed leftmost bits. Counters are cheap and encryptions can run in parallel.
// GCM authenticated encryption (SP 800-38D), inputs K, IV, P, A 1. H = E(K, 0128) // hash key 2. J0 = IV ‖ 031 ‖ 1 if len(IV) = 96 J0 = GHASHH(IV ‖ 0s+64 ‖ [len(IV)]64) otherwise // pre-counter block 3. C = GCTRK(inc32(J0), P) 4. u, v = zero bits needed to pad C, A to multiples of 128 5. S = GHASHH(A ‖ 0v ‖ C ‖ 0u ‖ [len(A)]64 ‖ [len(C)]64) 6. T = MSBt(GCTRK(J0, S)) 7. return (C, T)

GCM uses only Galois-field multiplication for its hash because it is easy to do in hardware; a CTR-based AE approach is shown to be the most efficient for high-speed packet networks, and GCM meets a high level of security.

12.8Key Wrapping

Key Wrap (KW, NIST SP 800-38F; the AES version is RFC 3394) encrypts a symmetric key under a key both parties already share, with integrity built in.

Key encryption key (KEK) — the already-shared symmetric key used to encrypt (wrap) a new key.
  • Why encrypt a key with a key? Protocols such as IEEE 802.11 and IPsec use a key hierarchy. Lower keys are used and changed often; a higher-level key, used rarely and so more resistant to cryptanalysis, encrypts new lower-level keys for exchange.
  • Why a new mode? Keys can be longer than the block (AES block 128 bits, keys up to 256). Keys are worth more than ordinary data (one key protects much data), so NIST wanted a robust mode where every output bit depends nontrivially on every input bit. In ECB, CBC, CTR and the other modes the last plaintext block affects only the last ciphertext block. KW is slower, but it is used only on small amounts of data.
nnumber of 64-bit key-data blocks (semiblocks) P1 … Pn snumber of stages, s = 6n A(t)64-bit integrity check register after stage t; A(0) = ICV = A6A6A6A6A6A6A6A6 R(t, i)64-bit register i after stage t
// Wrap: inputs P₁…Pₙ and KEK K; output C₀…Cₙ (one block longer) A(0) = A6A6A6A6A6A6A6A6; R(0, i) = Pi for t = 1 to s: W = E(K, [A(t−1) ‖ R(t−1, 1)]) A(t) = t ⊕ MSB64(W) R(t, n) = LSB64(W) for i = 1 to n−1: R(t, i) = R(t−1, i+1) // sliding buffer C0 = A(s); Ci = R(s, i)
// Unwrap: run the stages backwards with the decryption function A(s) = C0; R(s, i) = Ci for t = s down to 1: W = D(K, [(A(t) ⊕ t) ‖ R(t, n)]) A(t−1) = MSB64(W); R(t−1, 1) = LSB64(W) for i = 2 to n: R(t−1, i) = R(t, i−1) if A(0) = A6A6A6A6A6A6A6A6 then Pi = R(0, i) else error

The A output feeds the next stage, while each R output skips forward n stages through the sliding buffer, increasing the avalanche effect. A wrong recovered ICV means error or alteration, so KW gives integrity as well as confidentiality.

12.9Pseudorandom Number Generation Using Hash Functions and MACs

Hash and MAC outputs look random, so like block ciphers (Unit 5) they can drive a PRNG. NIST SP 800-90 and ISO 18031 define a hash-based generator; SP 800-90 also defines one based on HMAC.

PRNG essentials — a seed and a deterministic algorithm producing a stream of pseudorandom bits. Used as a pseudorandom function (PRF) to make a value such as a session key, the seed is known only to its user; used for stream encryption, the seed acts as the secret key shared by sender and receiver.

PRNG based on a hash function

// V = seed, seedlen ≥ k + 64 bits (k = security level), n = output bits, H has outlen-bit output m = ⌈n / outlen⌉; data = V; W = null string for i = 1 to m: wi = H(data); W = W ‖ wi data = (data + 1) mod 2seedlen return leftmost n bits of W

SP 800-90 also updates V periodically. There are no known or suspected weaknesses in this approach with a strong hash such as SHA-2.

PRNG based on a MAC (HMAC)

HMAC gives more confidence in the security than a bare hash, at twice the execution time (two hash executions per output block). The key K and seed V together form the overall seed; SP 800-90 also updates both periodically. Figure 12.15 compares three designs:

NIST SP 800-90

w0 = V for i = 1 to m: wi = MAC(K, wi−1) W = W ‖ wi

Each input is the previous output, so an observer knows HMAC’s input and output; HMAC’s security still protects K.

IEEE 802.11i

for i = 1 to m: wi = MAC(K, V ‖ i) W = W ‖ wi

Seed plus a counter; the output reveals nothing direct about the input. Seems to offer more security than SP 800-90.

TLS / WTLS

A(0) = V for i = 1 to m: A(i) = MAC(K, A(i−1)) wi = MAC(K, A(i) ‖ V) W = W ‖ wi

Two HMAC calls per block: doubles the cost and seems to be security overkill.

11.7 · 12.10Review Questions

Review questions 11.1–11.9 and 12.1–12.9 from the book. Answer first, then open to check.

Chapter 11

11.1 What characteristics are needed in a secure hash function?

Variable input size, fixed output size, efficiency, preimage resistance (one-way), second preimage resistance (weak collision resistance), collision resistance (strong collision resistance), and pseudorandom output (Table 11.1).

11.2 What is the difference between weak and strong collision resistance?

Weak: for a given x it is infeasible to find y ≠ x with H(y) = H(x). Strong: it is infeasible to find any pair x ≠ y with H(x) = H(y). The attacker chooses both messages in the strong case, so the birthday attack applies (2m/2 instead of 2m).

11.3 What is the role of a compression function in a hash function?

It is the fixed-size building block of an iterated hash: it combines the n-bit chaining variable with one b-bit block to give the next chaining variable. If the length is included and the compression function is collision resistant, so is the whole hash.

11.4 What is the difference between little-endian and big-endian format?

Big-endian stores the most significant byte of a word at the lowest address (leftmost); little-endian stores the least significant byte there. SHA-512 uses big-endian; SHA-3 reads lanes little-endian.

11.5 What basic arithmetical and logical functions are used in SHA?

Addition modulo 264 (232 for SHA-256), bitwise AND, XOR and NOT (inside Ch and Maj), circular right shifts ROTR and right shifts SHR.

11.6 Describe the set of criteria used by NIST to evaluate SHA-3 candidates.

The criteria are in the book’s online Appendix V. NIST’s call for candidates ranked three groups: security (the most important: security in applications such as signatures, key derivation, HMAC and DRBGs; collision resistance of about n/2 bits, preimage resistance of about n bits, second-preimage and length-extension resistance; resistance to known attacks; quality of the security arguments), cost (computational efficiency across platforms, memory requirements), and algorithm and implementation characteristics (flexibility, such as a tunable security/performance trade-off and parallelism, and simplicity). See Sources.

11.7 Define the term sponge construction.

An iterated construction that builds a function with variable-length input and arbitrary-length output from a fixed-length function f on b = r + c bits: pad the message to multiples of r, absorb each block by XOR into the state followed by f, then squeeze r bits at a time (applying f between) until the output is long enough.

11.8 Briefly describe the internal structure of the iteration function f.

The 1600-bit state is arranged as a 5 × 5 matrix of 64-bit lanes and passes through 24 rounds. Each round is five steps, θ, ρ, π, χ, ι, each a permutation or substitution of the state. The rounds are identical except for ι’s round constant.

11.9 List and briefly describe the step functions that comprise the iteration function f.

θ: XOR each bit with the parity of a column on one side and a rotated column on the other (diffusion). ρ: rotate each lane by a fixed offset. π: permute lane positions. χ: nonlinear row mix a ⊕ (NOT b AND c). ι: XOR a round constant into L[0, 0] to break symmetry.

Chapter 12

12.1 What types of attacks are addressed by message authentication?

Masquerade, content modification, sequence modification and timing modification (delay or replay). Source repudiation needs digital signatures.

12.2 What two levels of functionality comprise a message authentication or digital signature mechanism?

A lower-level function that produces an authenticator, and a higher-level authentication protocol that uses it to let the receiver verify the message.

12.3 What are some approaches to producing message authentication?

A hash function, message encryption (symmetric or public key), and a message authentication code.

12.4 When a combination of symmetric encryption and an error control code is used for message authentication, in what order must the two functions be performed?

Error control code first, then encryption: E(K, [M ‖ F(M)]) (internal error control). With the code outside, anyone can compute a valid code for any ciphertext.

12.5 What is a message authentication code?

A fixed-length value T = MAC(K, M) computed from the message and a secret key shared by sender and receiver, appended to the message so the receiver can verify origin and integrity.

12.6 What is the difference between a message authentication code and a one-way hash function?

A hash takes no key, so anyone can compute it and the hash value itself must be protected. A MAC depends on a secret key, so only key holders can create or verify it.

12.7 In what ways can a hash value be secured so as to provide message authentication?

Encrypt message plus hash symmetrically; encrypt only the hash symmetrically; hash the message together with a shared secret value; or that plus encryption (Figure 11.3). Encrypting the hash with the sender’s private key also gives a signature.

12.8 Is it necessary to recover the secret key in order to attack a MAC algorithm?

No. Some attacks produce a valid tag directly, such as the XOR-MAC forgery and the CBC-MAC X ‖ (X ⊕ T) forgery. Attacking the tag value costs about 2n, the key about 2k.

12.9 What changes in HMAC are required in order to replace one underlying hash function with another?

None to HMAC itself: remove the existing hash module and drop in the new one (adjusting b and n to the new hash). HMAC treats the hash as a black box.
