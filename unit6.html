Public-Key Cryptography

Symmetric ciphers use one shared key. Public-key (asymmetric) cryptography uses a pair of related keys: one published, one kept private. Chapter 9 sets out the model and its requirements and covers RSA, whose security rests on factoring. Chapter 10 covers Diffie–Hellman and Elgamal (discrete logarithms), elliptic curve cryptography (the elliptic curve logarithm problem) and PRNGs built from asymmetric ciphers.

RSA: C = Me mod n, M = Cd mod n ed ≡ 1 (mod φ(n)) DH: K = YBXA mod q ECC: Q = kP

9.1Principles of Public-Key Cryptosystems

Public-key cryptography addresses two problems symmetric encryption handles badly: key distribution (symmetric keys must already be shared, or handed out by a key distribution center that then has to be trusted) and digital signatures (proving that a particular person sent a message).

Terminology (Table 9.1, from NIST IR 7298)

Asymmetric keys — two related keys, a public key and a private key, used for complementary operations such as encryption and decryption, or signature generation and verification.
Public-key (asymmetric) cryptographic algorithm — an algorithm using such a key pair, chosen so that deriving the private key from the public key is computationally infeasible.
Public key certificate — a digital document, issued and digitally signed with the private key of a Certification Authority, that binds a subscriber’s name to a public key and states that the subscriber alone controls the matching private key.
Public key infrastructure (PKI) — the policies, processes, server platforms, software and workstations used to administer certificates and key pairs, including issuing, maintaining and revoking certificates.

Three misconceptions the chapter corrects

  • Public-key encryption is not inherently more secure than symmetric encryption. Security depends on key length and the work needed to break the cipher.
  • It has not made symmetric encryption obsolete. Its computational overhead keeps it to key management and signatures.
  • Key distribution is not trivial with public keys. A protocol, usually with a central agent, is still needed (Unit 9).

The model

Public-key algorithms are built on mathematical functions rather than substitution and permutation. They use one key for encryption and a different, related key for decryption, with two characteristics:

  • It is computationally infeasible to find the decryption key knowing only the algorithm and the encryption key.
  • (Some algorithms, such as RSA) either key can encrypt, with the other one decrypting.

A public-key encryption scheme has six ingredients: plaintext, an encryption algorithm, a public key and a private key (selected so that if one encrypts, the other decrypts), ciphertext, and a decryption algorithm. The essential steps:

  1. Each user generates a key pair.
  2. Each user places one key (the public key) in a public register or file and keeps the other (the private key) secret. Users collect the public keys of others.
  3. To send Alice a confidential message, Bob encrypts it with Alice’s public key.
  4. Alice decrypts with her private key. No one else can, because only Alice knows it.

Private keys are generated locally and never distributed. A user can change key pair at any time by publishing a new public key. Notation used throughout: PUa, PRa for user A’s public and private key; K for a symmetric secret key. “Private” rather than “secret” is used for the asymmetric key to avoid confusion.

Conventional vs public-key encryption (Table 9.2)

Conventional (symmetric)

To work: the same algorithm and the same key encrypt and decrypt; sender and receiver share both.
For security: the key is kept secret; deciphering without the key is impossible or impractical; the algorithm plus ciphertext samples do not reveal the key.

Public-key (asymmetric)

To work: one algorithm encrypts and a related one decrypts, using a key pair; sender and receiver each hold one key of the pair (not the same one).
For security: one of the two keys is kept secret; deciphering without it is impossible or impractical; the algorithm plus one key plus ciphertext samples do not reveal the other key.

Applications (Table 9.3)

  • Encryption/decryption — encrypt with the recipient’s public key.
  • Digital signature — sign with the sender’s private key, applied to the message or to a small block that is a function of it.
  • Key exchange — two sides cooperate to exchange a session key: a symmetric secret key generated for one transaction (session) and valid for a short time.

Requirements for public-key cryptography

  1. Computationally easy for B to generate a key pair (PUb, PRb).
  2. Easy for sender A, knowing PUb and message M, to compute C = E(PUb, M).
  3. Easy for B to decrypt: M = D(PRb, C) = D[PRb, E(PUb, M)].
  4. Infeasible for an adversary knowing PUb to determine PRb.
  5. Infeasible for an adversary knowing PUb and C to recover M.
  6. (Useful, not always needed) the keys work in either order: M = D[PUb, E(PRb, M)] = D[PRb, E(PUb, M)].

These requirements boil down to needing a trap-door one-way function.

Easy — solvable in polynomial time: for an n-bit input, time proportional to na for a fixed constant a (the class P). Infeasible — effort grows faster than polynomial, e.g. proportional to 2n. Cryptography needs inversion to be infeasible for virtually all inputs, not just the worst or average case.
One-way function — maps a domain into a range so that every value has a unique inverse, computing the function is easy and computing the inverse is infeasible: Y = f(X) easy, X = f−1(Y) infeasible. (Not the same as a one-way hash function, Unit 7.)
Trap-door one-way function — a family of invertible functions fk that is easy one way and infeasible the other way unless extra information (the trap door k) is known: Y = fk(X) easy if k and X known; X = fk−1(Y) easy if k and Y known; infeasible if only Y known.

Public-key cryptanalysis

  • Brute force — same countermeasure as symmetric ciphers: large keys. But the cost of the underlying functions grows faster than linearly with key size, so keys big enough to stop brute force make public-key encryption too slow for general-purpose use.
  • Computing the private key from the public key — not proven infeasible for any public-key algorithm, RSA included.
  • Probable-message attack — specific to public-key systems. If a message is, say, only a 56-bit DES key, an adversary encrypts all 256 possible keys with the public key and matches the ciphertext, so the attack is a 56-bit brute force regardless of the public key’s size. Defense: append random bits to such short messages.

9.2The RSA Algorithm

RSA is the most widely accepted and implemented general-purpose public-key algorithm. Plaintext and ciphertext are integers between 0 and n − 1; a typical n is 1024 bits (309 decimal digits).

Number theory needed (from Unit 2)

Relatively prime — a and b share no positive common factor except 1: gcd(a, b) = 1.
Multiplicative inverse mod m — the d with e·d ≡ 1 (mod m); exists only if gcd(e, m) = 1. Found with the extended Euclidean algorithm.
Euler’s totient φ(n) — the number of positive integers less than n and relatively prime to n. For distinct primes p, q: φ(pq) = (p − 1)(q − 1).
Euler’s theorem — aφ(n) ≡ 1 (mod n) when gcd(a, n) = 1. This is what makes RSA decryption undo encryption.

Description of the algorithm

Plaintext is encrypted in blocks, each with a binary value less than n; in practice the block size is i bits where 2i < n ≤ 2i+1.

C = Me mod n M = Cd mod n = (Me)d mod n = Med mod n

Both sides know n; the sender knows e; only the receiver knows d. So PU = {e, n} and PR = {d, n}. Three requirements must hold:

  1. Values e, d, n exist with Med mod n = M for all M < n.
  2. Me mod n and Cd mod n are relatively easy to compute.
  3. It is infeasible to determine d given e and n.

Requirement 1 holds when e and d are multiplicative inverses modulo φ(n) (proof in online Appendix R):

ed mod φ(n) = 1 ⇔ ed ≡ 1 (mod φ(n)) ⇔ d ≡ e−1 (mod φ(n)) (9.1)

This is only possible if d (and so e) is relatively prime to φ(n).

Computational Aspects of RSA

Two costs matter: encryption/decryption (modular exponentiation with large exponents) and key generation (finding large primes and an e, d pair).

Exponentiation in modular arithmetic

Exponentiating over the integers first and reducing at the end would give gigantic intermediate values. Instead, use [(a mod n) × (b mod n)] mod n = (a × b) mod n and reduce after every multiplication.

Repeated squaring cuts the number of multiplications: x16 takes 15 multiplications directly but only 4 as x2, x4, x8, x16. In general, write b in binary bkbk−1…b0; then

ab mod n = [ ∏bi≠0 (a2i mod n) ] mod n e.g. x11 = x1+2+8 = (x)(x2)(x8)

Efficient operation using the public key

e is usually chosen as 65537 (216 + 1), or 3 or 17. Each has only two 1 bits, minimizing multiplications. If e is fixed first and p, q later turn out to give gcd(φ(n), e) ≠ 1, reject p, q and generate a new pair.

Small-e attack (e = 3). If the same M is sent to three users with e = 3 and moduli n1, n2, n3 (very likely pairwise relatively prime), the attacker uses the Chinese remainder theorem (CRT) on Ci = M3 mod ni to get M3 mod (n1n2n3). Because M < each ni, M3 < n1n2n3, so this equals M3 itself; an ordinary cube root gives M. Countermeasure: add a unique pseudorandom padding string to each M before encrypting.
Chinese remainder theorem (CRT) — for pairwise relatively prime moduli m1, …, mk with product M, every integer A in ZM is uniquely determined by its residues (A mod m1, …, A mod mk), and A can be rebuilt from them (Unit 2).
Lab · Breaking e = 3 with the CRTattack demo

Efficient operation using the private key

d cannot be chosen small: a small d is open to brute force and other cryptanalysis (if e < n and d < n1/4, d is easily found). Decryption is sped up with the CRT instead:

Vp = Cd mod p Vq = Cd mod q Xp = q × (q−1 mod p) Xq = p × (p−1 mod q) M = (VpXp + VqXq) mod n

By Fermat’s theorem (ap−1 ≡ 1 mod p for gcd(a, p) = 1) the exponents shrink: Vp = Cd mod (p−1) mod p, Vq = Cd mod (q−1) mod q, where d mod (p − 1) and d mod (q − 1) are precomputed. The result is about four times faster than computing Cd mod n directly. The RSA lab above shows these values for the loaded key.

Key generation

Each participant must (1) find two primes p and q, and (2) choose e or d and compute the other.

  • Large p, q. n is public, so p and q must come from a large enough set to prevent exhaustive search, yet be found efficiently. No method produces arbitrarily large primes directly.
  • Procedure: pick a random odd number of the right size, test it for primality; if it fails, try the next random number.
  • Probabilistic tests such as Miller–Rabin say only that n is “probably prime”, but repeating with t random bases a makes the probability as close to 1 as desired. Since primes near N are on average ln(N) apart, about ln(N)/2 odd candidates are tried; for a 200-bit prime, ln(2200)/2 ≈ 69.
  • e and d. Pick e, check gcd(φ(n), e) = 1, and compute d = e−1 mod φ(n) with the extended Euclidean algorithm, which does both at once. Two random numbers are relatively prime with probability about 0.6, so few e values need testing.

The factoring problem

Three mathematical approaches:

  1. Factor n into p and q, giving φ(n) = (p − 1)(q − 1) and then d ≡ e−1 (mod φ(n)).
  2. Find φ(n) directly, which is equivalent to factoring n.
  3. Find d directly, which appears to be at least as hard as factoring.

So factoring performance is the benchmark for RSA security. The threat to larger keys is twofold: growing computing power and better factoring algorithms. The quadratic sieve was superseded by the generalized number field sieve (GNFS), which is much faster; the special number field sieve (SNFS) is faster still for numbers of special form, and a general algorithm that fast may appear. A 768-bit modulus has been factored; factoring a 1024-bit modulus is about 1000 times harder, and the book recommends phasing out 1024-bit RSA.

Constraints on p and q to avoid easily factored n:

  • p and q differ in length by only a few digits (for a 1024-bit key, both about 1075–10100).
  • Both p − 1 and q − 1 contain a large prime factor.
  • gcd(p − 1, q − 1) is small.

Timing attacks

Timing attack — determining a private key by measuring how long a computer takes to decrypt messages. It applies to other public-key systems too, comes from an unexpected direction, and is ciphertext-only.

With the algorithm of Figure 9.8 there is one modular multiplication per bit plus an extra one for each 1 bit. The attack recovers the exponent bit by bit from the leftmost bit bk: knowing the first j bits, the attacker can run the first j iterations for a chosen ciphertext. Suppose that for a few known values the modular multiplication is very slow. If total decryption time is always slow when this iteration would be slow with a 1 bit, the bit is 1; if many observed times are fast, it is 0. Real implementations vary less than this extreme case, but enough to make the attack practical.

  • Constant exponentiation time — every exponentiation takes the same time before returning. Simple, but degrades performance.
  • Random delay — add a random delay to confuse timing. If too little noise is added, the attacker compensates with more measurements.
  • Blinding — multiply the ciphertext by a random number before exponentiating, so the attacker does not know which ciphertext bits are being processed. Steps for M = Cd mod n: pick secret random r, 0 ≤ r ≤ n − 1; compute C′ = C(re) mod n; compute M′ = (C′)d mod n; compute M = M′r−1 mod n. It works because red mod n = r mod n. Reported cost: 2–10%.

Fault-based attack

Faults are induced in RSA signature computation by reducing the processor’s power. The resulting invalid signatures (from single-bit errors) are analyzed to recover the private key; a 1024-bit key was extracted in about 100 hours on a commercial microprocessor. It needs physical access and direct control of the processor’s input power, including on-chip power-supply control hardware.

Chosen ciphertext attack and OAEP

Chosen ciphertext attack (CCA) — the adversary chooses ciphertexts and is given the plaintexts decrypted with the target’s private key. Rather than learning nothing new, the adversary picks blocks that, once processed with the private key, give information needed for cryptanalysis.

Basic RSA is vulnerable because of its multiplicative property:

E(PU, M1) × E(PU, M2) = E(PU, [M1 × M2]) (9.2)
  1. Compute X = (C × 2e) mod n.
  2. Submit X as a chosen ciphertext and receive Y = Xd mod n.
  3. Since X = (Me mod n)(2e mod n) = (2M)e mod n, Y = 2M mod n, and M follows.

10.1Diffie–Hellman Key Exchange

Diffie–Hellman lets two users securely agree on a secret value, typically used as a symmetric key for later encryption. The algorithm only exchanges secret values; it does not encrypt messages or sign. Its security rests on the difficulty of computing discrete logarithms.

Primitive root — a is a primitive root of prime p if its powers a mod p, a2 mod p, …, ap−1 mod p are distinct and are exactly the integers 1 … p − 1 in some order.
Discrete logarithm — for an integer b and primitive root a of prime p there is a unique exponent i, 0 ≤ i ≤ p − 2, with b = ai mod p. i is the discrete logarithm of b for base a, mod p: dloga,p(b). Computing ai mod p is easy; finding i from b is, for large primes, infeasible.

The algorithm

Global public: prime q, α a primitive root of q (α < q) User A: private XA < q public YA = αXA mod q User B: private XB < q public YB = αXB mod q A computes K = (YB)XA mod q B computes K = (YA)XB mod q

Both get the same K, by the rules of modular arithmetic:

K = (YB)XA mod q = (αXB)XA mod q = αXBXA mod q = (αXA)XB mod q = (YA)XB mod q

An adversary sees only q, α, YA, YB. To get the key it must take a discrete logarithm, e.g. XB = dlogα,q(YB), then compute K as B does.

Example · book
q = 353, α = 3, XA = 97, XB = 233 YA = 397 mod 353 = 40 YB = 3233 mod 353 = 248 K = 24897 mod 353 = 40233 mod 353 = 160

Numbers this small fall to brute force: compute powers of 3 mod 353 until 40 or 248 appears (exponent 97 gives 40). With large numbers this is impractical.

Key exchange protocols

  • One-time keys (Figure 10.1): A generates a one-time XA, sends YA; B generates XB, replies with YB; both compute K. q and α are known in advance, or A picks them and sends them in the first message.
  • Directory of long-lasting keys: each user i stores a long-lasting public Yi (with global q, α) in a central directory. User j fetches Yi, computes the shared key and sends an encrypted message. With a trusted directory this gives confidentiality (only i and j can compute the key) and a degree of authentication (only j could have made the key), but no protection against replay attacks.

10.2Elgamal Cryptographic System

A public-key encryption scheme based on discrete logarithms, closely related to Diffie–Hellman. It is used in some form in the Digital Signature Standard (Unit 8) and S/MIME (Unit 12).

Global public: prime q, α a primitive root of q Key generation (Alice): private XA, 1 < XA < q − 1 YA = αXA mod q public key {q, α, YA} Encryption (Bob), message 0 ≤ M ≤ q − 1: random k, 1 ≤ k ≤ q − 1 one-time key K = (YA)k mod q C1 = αk mod q C2 = K·M mod q ciphertext (C1, C2) Decryption (Alice): K = (C1)XA mod q M = (C2K−1) mod q

Why it works: K = (YA)k = (αXA)k = αkXA = (C1)XA mod q, and C2K−1 = KMK−1 = M mod q. In words: Bob makes a one-time key K from Alice’s public values and his random k; C1 = αk is the “clue” that lets Alice rebuild K with her private key; C2 is M masked by K. Messages longer than q are sent as blocks, each less than q.

Example · book (GF(19))
q = 19, α = 10 (primitive roots of 19: 2, 3, 10, 13, 14, 15) XA = 5: YA = 105 mod 19 = 3 public {19, 10, 3} M = 17, k = 6: K = 36 mod 19 = 7 C1 = 106 mod 19 = 11 C2 = 7 × 17 mod 19 = 5 Decrypt (11, 5): K = 115 mod 19 = 7 K−1 = 11 M = 5 × 11 mod 19 = 17
Use a new k for every block. If k is reused, C2,1/C2,2 = KM1/KM2 = M1/M2 mod q, so knowing one block M1 gives M2 = (C2,1)−1C2,2M1 mod q.

Security: recovering the private key needs XA = dlogα,q(YA); recovering K needs k = dlogα,q(C1). These are considered infeasible if q is at least 300 decimal digits and q − 1 has at least one large prime factor.

10.3Elliptic Curve Arithmetic

Elliptic curve cryptography (ECC) appears to give security equal to RSA with a far smaller key, reducing processing overhead. Its arithmetic is addition of points on a curve, which forms an abelian group.

Abelian groups

Abelian group {G, ·} — a set G with a binary operation · that associates each ordered pair (a, b) with an element a · b in G, satisfying: (A1) closure: a · b ∈ G; (A2) associative: a · (b · c) = (a · b) · c; (A3) identity e: a · e = e · a = a; (A4) inverse a′: a · a′ = a′ · a = e; (A5) commutative: a · b = b · a.

Diffie–Hellman works in the multiplicative group of nonzero integers mod q: “exponentiation” is repeated multiplication, and the attacker must find k from a and ak (discrete logarithm). ECC uses an operation called addition of points; “multiplication” is repeated addition, k × a = a + a + … + a (k times), and the attacker must find k from a and k × a.

Elliptic curves over real numbers

Elliptic curves are not ellipses; the name comes from the cubic equations, similar to those used for an ellipse’s circumference. The general (Weierstrass) form is y2 + axy + by = x3 + cx2 + dx + e; it is enough to use

y2 = x3 + ax + b (10.1)
Cubic equation — an equation of degree 3 (highest exponent 3). Point at infinity / zero point O — an extra element included in every elliptic curve; it acts as the additive identity.

E(a, b) is the set of all points (x, y) satisfying Eq. 10.1, plus O. Each curve is symmetric about y = 0. E(a, b) forms a group provided

4a3 + 27b2 ≠ 0 (10.2)

Geometric rule: if three points on the curve lie on a straight line, their sum is O. From this:

  1. O is the additive identity: O = −O and P + O = P.
  2. −P has the same x and negated y: if P = (x, y), −P = (x, −y). P + (−P) = O.
  3. For P, Q with different x, draw the line through them; it meets the curve at a third point R. Then P + Q = −R, the mirror image of R in the x axis. (If the line is tangent at P or Q, take R = P or R = Q.)
  4. P and −P lie on a vertical line, which is viewed as meeting the curve at O: P + (−P) = O.
  5. To double Q, draw the tangent at Q; it meets the curve at S. Then Q + Q = 2Q = −S.

Algebraic rule: for distinct P = (xP, yP), Q = (xQ, yQ) that are not negatives, with slope Δ = (yQ − yP)/(xQ − xP):

xR = Δ2 − xP − xQ yR = −yP + Δ(xP − xR) (10.3) Doubling (yP ≠ 0): Δ = (3xP2 + a) / (2yP), xR = Δ2 − 2xP, yR = Δ(xP − xR) − yP (10.4)

Elliptic curves over Zp (prime curves)

For cryptography, variables and coefficients are restricted to a finite field, giving a finite abelian group. Two families are used: prime curves over Zp (best for software, no bit-fiddling) and binary curves over GF(2m) (best for hardware, very few logic gates). There is no obvious geometric picture over finite fields; the algebraic rules carry over.

y2 mod p = (x3 + ax + b) mod p (10.5) group condition: (4a3 + 27b2) mod p ≠ 0 mod p (10.6)

Ep(a, b) is the set of integer pairs (x, y), 0 ≤ x, y ≤ p − 1, satisfying Eq. 10.5, plus O. Example: (9, 7) is on E23(1, 1) because 72 mod 23 = 3 and (93 + 9 + 1) mod 23 = 739 mod 23 = 3. Rules for all P, Q in Ep(a, b):

  1. P + O = P.
  2. −(xP, yP) = (xP, −yP mod p); e.g. on E23(1, 1), −(13, 7) = (13, 16).
  3. For P ≠ −Q, R = P + Q with
    xR = (λ2 − xP − xQ) mod p yR = (λ(xP − xR) − yP) mod p λ = (yQ − yP)/(xQ − xP) mod p if P ≠ Q λ = (3xP2 + a)/(2yP) mod p if P = Q
    Division means multiplying by the multiplicative inverse mod p.
  4. Multiplication is repeated addition: 4P = P + P + P + P.

The number of points N in Ep(a, b) is bounded by p + 1 − 2√p ≤ N ≤ p + 1 + 2√p, roughly p.

Elliptic curves over GF(2m) (binary curves)

GF(2m) has 2m elements with polynomial arithmetic (Unit 4). The form used is different from Zp:

y2 + xy = x3 + ax2 + b (10.7)

with x, y, a, b in GF(2m) and arithmetic in GF(2m). E2m(a, b) (all solutions plus O) is a finite abelian group provided b ≠ 0. Rules:

  1. P + O = P.
  2. −(xP, yP) = (xP, xP + yP).
  3. P ≠ ±Q: λ = (yQ + yP)/(xQ + xP); xR = λ2 + λ + xP + xQ + a; yR = λ(xP + xR) + xR + yP.
  4. 2P: λ = xP + yP/xP; xR = λ2 + λ + a; yR = xP2 + (λ + 1)xR.
Example · book, GF(24)

Irreducible polynomial f(x) = x4 + x + 1; generator g with g4 = g + 1 (g = 0010). On y2 + xy = x3 + g4x2 + 1 (a = g4, b = 1), the point (g5, g3) satisfies the equation: g6 + g8 = g15 + g14 + 1, i.e. 1100 ⊕ 0101 = 0001 ⊕ 1001 ⊕ 0001 = 1001. (Addition in GF(2m) is bitwise XOR.)

10.4Elliptic Curve Cryptography

ECC point addition is the counterpart of modular multiplication in RSA, and repeated addition (kP) the counterpart of modular exponentiation. The hard problem is undoing kP.

Elliptic curve discrete logarithm problem — for Q = kP with Q, P ∈ Ep(a, b) and k < p, computing Q from k and P is relatively easy, but finding k from Q and P is hard.
Example · book, E23(9, 17)

Find k with kP = Q for P = (16, 5), Q = (4, 5). Brute force lists multiples: P = (16, 5), 2P = (20, 20), 3P = (14, 14), 4P = (19, 20), 5P = (13, 10), 6P = (7, 3), 7P = (8, 7), 8P = (12, 17), 9P = (4, 5). So k = 9. Real k values are far too large for this.

Order n of a point G — the smallest positive integer n such that nG = O.
Global public: Eq(a, b) with q a prime p or 2m; base point G = (x1, y1) of large order n A: private nA < n public PA = nA × G (a point) B: private nB < n public PB = nB × G A: K = nA × PB B: K = nB × PA since nA × (nB × G) = nB × (nA × G)

Breaking it requires k from G and kG. The shared secret is a pair of numbers; to use it as a session key, take the x coordinate or a simple function of it.

Elliptic curve encryption/decryption

First encode the message m as a curve point Pm (not simply as a coordinate, since not every x or y is on the curve; straightforward encodings exist). Each user picks private nA and public PA = nA × G.

Encrypt for B (random k): Cm = { kG, Pm + kPB } Decrypt (B): (Pm + kPB) − nB(kG) = Pm + k(nBG) − nB(kG) = Pm

A masks Pm by adding kPB; only A knows k, so nobody can remove the mask from the public PB alone. kG is the “clue” that removes it for whoever knows nB. An attacker would need k from G and kG.

Security of ECC

Security depends on the elliptic curve logarithm problem: finding k given kP and P. The fastest known technique is the Pollard rho method. For equal key lengths, ECC and RSA take comparable computational effort, so ECC’s much shorter keys for the same security are a computational advantage.

10.5Pseudorandom Number Generation Based on an Asymmetric Cipher

An asymmetric cipher’s output looks random, so it can drive a PRNG. Because asymmetric algorithms are much slower than symmetric ones, they are used for a pseudorandom function (PRF) producing a short pseudorandom bit sequence, not open-ended bit streams.

PRNG based on RSA: Micali–Schnorr

Recommended in ANSI X9.82 and ISO 18031. Its structure is like OFB mode used as a PRNG (Unit 5), with RSA in place of a block cipher. Part of each output is fed back and the rest is output, so output bits never become the next input, which supports forward unpredictability.

Redrawn from Figure 10.8.
Setup: RSA primes p, q; n = pq; e with gcd(e, φ(n)) = 1; N = ⌊log2n⌋ + 1 (bit length of n); r + k = N Seed: random x0 of r bits Generate: for i = 1 … m: yi = xi−1e mod n xi = r most significant bits of yi zi = k least significant bits of yi Output: z1 ‖ z2 ‖ … ‖ zm
  • n = pq — RSA-strength modulus.
  • 1 < e < φ(n), gcd(e, φ(n)) = 1 — the map s → se mod n is one-to-one.
  • re ≥ 2N — the exponentiation needs a full modular reduction.
  • r ≥ 2 × strength — protects against cryptographic attacks. (Strength, NIST SP 800-90: the security strength in bits, one of 112, 128, 192, 256; breaking takes 2strength operations.)
  • k, r multiples of 8 — implementation convenience. k ≥ 8 and r + k = N — all bits are used.

Trade-off: a large k gives more output bits per (expensive) RSA operation, but a large r gives more strength. Example: e = 3, N = 1024 gives 3r > 1024, so r ≥ 683 and k = 341 bits per exponentiation, each costing one modular squaring and one multiplication: (xi × (xi2 mod n)) mod n.

Lab · Micali–Schnorr with a 512-bit modulustoy size, e = 3

PRNG based on ECC: dual elliptic curve PRNG (DEC PRNG)

With P, Q known points on a curve, x(·) the x coordinate of a point and lsbi(s) the i least significant bits of s, a random seed s0 in {0, …, #E(GF(p)) − 1} (#E = number of curve points) is turned into 240k bits:

for i = 1 to k do si ← x(si−1 P) ri ← lsb240(x(si Q)) end for return r1, …, rk

Its security and efficiency compared with alternatives are disputed; the only motivation for using it would be a system that already implements ECC and no other symmetric, asymmetric or hash algorithm from which a PRNG could be built.

Current status (outside the book)NIST removed Dual_EC_DRBG from its recommendation: SP 800-90A Revision 1 (2015) no longer includes it, and NIST advised users to switch to the remaining approved DRBGs (Hash_DRBG, HMAC_DRBG, CTR_DRBG). See Sources.

The key-term lists from both chapters, plus the intermediate terms they depend on, one line each.

Public-key cryptography
Cryptography with a related key pair, one public and one private; also called asymmetric cryptography.
Public-key cryptosystem
A system using a public-key algorithm for encryption, digital signatures and/or key exchange.
Public-key encryption
Encrypt with the recipient’s public key, decrypt with the recipient’s private key.
Public key
The key of the pair that is published (PU).
Private key
The key of the pair kept secret by its owner (PR); never distributed.
Secret key
The single shared key of symmetric encryption (K).
Public key certificate
Document signed by a Certification Authority binding a name to a public key.
Digital signature
Transformation with the sender’s private key that anyone can verify with the public key; authenticates source and data.
Key exchange
Two sides cooperate to establish a shared session key.
Session key
Symmetric key generated for one transaction and valid for a short time.
One-way function
Easy to compute, infeasible to invert.
Trap-door one-way function
One-way unless extra information (the trap door) is known, which makes inversion easy.
Probable-message attack
Encrypt every likely message with the public key and match the ciphertext; countered by appending random bits.
RSA
C = Me mod n, M = Cd mod n, n = pq, ed ≡ 1 (mod φ(n)); security rests on factoring n.
Euler’s totient function φ(n)
Count of positive integers below n relatively prime to n; φ(pq) = (p − 1)(q − 1).
Timing attack
Recovering a private key from decryption times; countered by constant time, random delay or blinding.
Blinding
Decrypt C·re and multiply by r−1, hiding which ciphertext is processed.
Chosen ciphertext attack (CCA)
Adversary picks ciphertexts and obtains their decryptions under the target’s private key.
Optimal asymmetric encryption padding (OAEP)
Seed-and-mask encoding of the message (with hash and MGF) before RSA encryption, against CCA.
Primitive root
a whose powers mod prime p produce every integer 1 … p − 1.
Discrete logarithm
The exponent i with b = ai mod p; infeasible to compute for large p.
Diffie–Hellman key exchange
Exchange Y = αX mod q; both sides compute K = αXAXB mod q.
Man-in-the-middle attack
Adversary intercepts and replaces public values, sharing one key with each party.
Elgamal
Discrete-log encryption: ciphertext (αk mod q, K·M mod q) with one-time key K = YAk mod q.
Abelian group
Set with an operation satisfying closure, associativity, identity, inverses and commutativity.
Finite field
A field with a finite number of elements, e.g. Zp or GF(2m).
Cubic equation
Equation of degree 3, such as y2 = x3 + ax + b.
Elliptic curve
Points satisfying such a cubic equation plus the point O; over a finite field, a finite abelian group.
Zero point (point at infinity) O
The identity element of elliptic curve addition.
Elliptic curve arithmetic
Point addition (three collinear points sum to O) and scalar multiplication kP as repeated addition.
Prime curve
Elliptic curve over Zp: y2 mod p = (x3 + ax + b) mod p; suited to software.
Binary curve
Elliptic curve over GF(2m): y2 + xy = x3 + ax2 + b; suited to hardware.
Order of a point
Smallest n > 0 with nG = O.
Elliptic curve cryptography (ECC)
Public-key schemes whose security rests on finding k from kP and P.
Micali–Schnorr
RSA-based PRNG: yi = xi−1e mod n, feed back r high bits, output k low bits.

9.3 · 10.6Review Questions

Review questions 9.1–9.7 and 10.1–10.4 from the book. Answer first, then open to check.

Chapter 9

9.1 What is a public key certificate?

A digital document, issued and signed with a Certification Authority’s private key, that binds a subscriber’s name to a public key and states that the subscriber alone controls the corresponding private key.

9.2 What are the roles of the public and private key?

The public key is published; anyone uses it to encrypt messages for its owner or to verify the owner’s signatures. The private key is known only to its owner, who uses it to decrypt messages encrypted with the public key and to create signatures. What one key does, only the other can undo.

9.3 What are three broad categories of applications of public-key cryptosystems?

Encryption/decryption (with the recipient’s public key), digital signatures (with the sender’s private key), and key exchange (agreeing on a session key).

9.4 What requirements must a public-key cryptosystem fulfill to be a secure algorithm?

Easy for B to generate a key pair; easy for a sender to encrypt with PUb; easy for B to decrypt with PRb; infeasible to determine PRb from PUb; infeasible to recover M from PUb and C; and (optionally) the two keys can be applied in either order. Together these call for a trap-door one-way function.

9.5 How can a probable-message attack be used for public-key cryptanalysis?

If the plaintext comes from a small set (e.g. it is only a 56-bit DES key), the attacker encrypts every candidate with the public key and compares with the intercepted ciphertext. The attack costs a search of the message space regardless of the public key’s size. Appending random bits to short messages defeats it.

9.6 List the different approaches to attack the RSA algorithm.

Brute force (try all private keys); mathematical attacks, equivalent to factoring n; timing attacks on decryption time; hardware fault-based attacks on signature generation; and chosen ciphertext attacks exploiting RSA’s properties.

9.7 Describe the countermeasures to be used against the timing attack.

Constant exponentiation time (all exponentiations take the same time; costs performance); random delay (adds noise, but too little can be overcome with more measurements); blinding (multiply the ciphertext by re for a secret random r before exponentiating and remove r afterwards, so the attacker does not know which bits are processed; about 2–10% overhead).

Chapter 10

10.1 Briefly explain Diffie–Hellman key exchange.

Users agree on a prime q and primitive root α. A picks secret XA and sends YA = αXA mod q; B picks XB and sends YB = αXB mod q. Each computes K = (other’s Y)own X mod q = αXAXB mod q. An eavesdropper must solve a discrete logarithm to find K. Without authentication it is open to man-in-the-middle attacks.

10.2 What is an elliptic curve?

The set of points (x, y) satisfying a cubic equation, in cryptography of the form y2 = x3 + ax + b (over the reals or Zp) or y2 + xy = x3 + ax2 + b (over GF(2m)), together with a point at infinity O. With point addition, it forms an abelian group.

10.3 What is the zero point of an elliptic curve?

The point at infinity O, included in every elliptic curve. It is the additive identity: P + O = P, and P + (−P) = O.

10.4 What is the sum of three points on an elliptic curve that lie on a straight line?

O, the zero point. This is the geometric rule from which P + Q = −R follows.
